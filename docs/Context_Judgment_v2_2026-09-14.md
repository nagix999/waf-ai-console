# 요청 의미 판단 보완 v2 — 2026-09-14

## 상태와 범위

[150건 비교에서 정한 후속 우선순위](evaluations/Analyst_Assessment_GPT54Mini_150_2026-09-14.md)의 **1번: 미탐과 과도한 확정 보완**을 구현했다. 공통 시스템 지침은 `waf-system-v2.11`, 새 접수 프롬프트는 `waf-judgment-v2.11/policy-N`이다.

코드와 오프라인 검증 범위다. 실행 중 서비스는 v2.10을 유지하며 **이번 변경을 재배포하거나 실제 LLM으로 평가하지 않았다.** 정확도 향상을 확인한 것으로 표시하지 않는다. 이전 평가의 운영 확대 보류 권고도 유지한다.

## 변경한 판단 기준

새 지침은 `입력 문맥 → 공격 의미 → 정상 의미 → 판정을 가르는 조건` 순서로 정리했다. 서버가 이 순서로 별도 판정을 실행하는 것은 아니며 두 역할이 공유하는 판단 지침이다.

| 발견한 문제 | 지침의 보완 |
| --- | --- |
| SQL 시그니처 불일치를 이유로 SVG 공격을 정상 처리 | 시그니처 적합성과 요청 전체의 다른 공격 구문을 따로 평가 |
| JSON 따옴표·일반 헤더·표시용 플래그를 정상 근거로 사용 | 전달 형식과 그 안의 실행·조회·경로 접근 조작을 구분 |
| 실행·렌더링·외부 연결 성공이 확인되지 않아 공격을 부정 | 공격 시도와 성공을 분리하고 성공 여부만으로 보류하지 않음 |
| 키워드·파일명 안의 점만으로 정상 요청을 공격으로 해석 | 값·구조·문법이 함께 뒷받침하는 정상 의미를 설명 |
| 일반적인 API 형식만으로 권한·기능 미상의 요청을 확정 | 실제 판정을 가르는 권한·소유 관계·허용 기능·처리 범위를 명시 |
| 회사명·테스트 표식을 정상 근거로 사용 | 회사명·유입명·테스트 표식은 정상 근거가 아님을 명시 |

원문 근거 연결, 정탐/오탐/참고 근거 구분, 보류 쟁점, 한국어 설명과 추가 확인 계약은 유지한다. 외부 조회식에는 성공을 추정하지 않는 제한을 유지하되, 일률적인 조회 후속 확인 예시는 줄였다. 실제 필요한 확인은 기존 `analyst_checks` 기준으로 작성한다.

모델이 구문과 업무 의미를 제대로 구분하는지는 별도 평가가 필요하다. 특정 파일명·문항 ID·테스트 표식으로 답안을 강제하는 코드, 공격 정규식에 의한 자동 판정, 새 LLM 단계는 추가하지 않았다.

## 길이와 보존

저장된 사용자 편집 지침은 변경하지 않는다. 아래는 **기본 편집 지침을 붙인 코드 기본값**과 배포 v2.10 이미지의 같은 기본값을 비교한 값이다. 실제 정책 2의 토큰 수나 호출 비용을 측정한 표가 아니다.

| 항목 | v2.10 | v2.11 |
| --- | ---: | ---: |
| 고정 지침 문자 수 | 3,592 | 3,574 |
| 고정 지침 UTF-8 바이트 | 7,428 | 7,353 |
| Primary 기본 지침 문자 수 | 3,949 | 3,931 |
| Primary 기본 지침 UTF-8 바이트 | 8,248 | 8,173 |
| Verifier 기본 지침 문자 수 | 3,979 | 3,961 |
| Verifier 기본 지침 UTF-8 바이트 | 8,336 | 8,261 |

길이는 사실상 유지하면서 판단 순서를 명확히 한 수정이다. 모델별 토크나이저의 절감이나 응답 속도 향상을 의미하지 않는다.

- Production/Test, Primary/Verifier의 공통 기준은 같다. Verifier는 Primary 결과를 받지 않는다.
- v2.11에도 원문 후보 선택·요청 입력 검사·분석가용 근거 계약을 함께 적용한다. 버전 허용 목록에서 하나가 빠져 이전 출력 계약으로 돌아가는 회귀를 검사한다.
- 과거 v2.6~v2.10으로 고정된 실행은 당시 지침과 입출력 계약을 유지한다. 이미 접수된 분석을 새 지침으로 덮어쓰지 않는다.
- API 결과 스키마, DB, 패키지 의존성, 모델·Verifier 정책, 관리자 편집 지침, 모델 입력 구조는 변경하지 않았다. 기존 150건의 입력·답안·평가 결과는 보존한다.
- API 정의서의 코드 버전 표시는 패키지 문서와 원본 문서에 함께 반영했다. 실행 중인 정의서는 재배포 전까지 기존 버전이다.

## 별도 검수 자료

[요청 의미 검수 자료 v1](../samples/waf-context-review-v1/README.md)에 총 18건을 추가했다.

- 공격/정상 6쌍: HTML, SQL, 셸, 경로, 외부 조회식, 템플릿.
- 조건 확인 6건: 문서 권한, 서버 측 URL 조회, 사용자 SQL, 임베드 콘텐츠, 상대 경로, 관리 작업.
- 요청은 문서용 주소와 중립적인 공통 메타데이터를 사용한다. 답안 이유·분류·확인 조건은 `reference/answers_18.json`에만 있다. 업로드의 `expected_verdict`는 기존 접수 경로에서 분리한다.

**AI가 작성한 개발용 문항이며, 전문가가 확정한 답안이나 독립 검증셋이 아니다.** 특히 조건 확인 문항은 실제 업무 기준에 따라 참고 답안이 달라질 수 있어 사람이 검토해야 한다. 문서용 주소와 서버가 부여하는 테스트 유입 정보는 남아 있으므로 모든 평가 편향이 제거된 것으로 보지 않는다. 새 18건의 점수는 기존 150건과 별도 집계한다.

## 검증

운영 DB·설정·볼륨을 연결하지 않은 읽기 전용 임시 컨테이너와 `--network none`에서 검사했다. 배포 이미지의 Python 3.12·운영 패키지를 사용하고 로컬 pytest 지원 파일만 추가로 읽었다. 프런트엔드는 변경하지 않았다.

- 핵심 지침·원문 후보·입력 검사·근거 구분·공통 지침 접수·과거 스냅샷 회귀: 177항목 통과.
- 새 자료의 재현성·HTTP 구조·원문 연결·답안 분리·버전 계약: 21항목 통과.
- 전체 백엔드 회귀: **1,834항목 통과**, 596.13초. Starlette/AnyIO의 기존 사용 중단 예고 경고 1건이며 실패는 없다. 위 두 묶음도 전체 회귀에 포함되므로 통과 수를 합산하지 않는다.
- `python3 scripts/build_context_review_samples.py`: 18건 생성 정의와 저장 파일 일치. 파일 쓰기·외부 요청·모델 호출 없음.
- 기존 파싱 난이도·Hard·Medium 각 50건의 SHA-256이 이전 평가와 일치하고, 운영 API 문서 원본과 패키지 사본도 바이트 단위로 일치한다.

정적 지침 검사와 가짜 모델 출력을 이용한 계약 검사는 **실제 모델의 의미 해석이나 정답률 검증이 아니다.** Gemma4, 실제 운영 로그, 유료 재평가를 수행하지 않았다.

## 다음 작업

1. 버전이 빠진 부분 로그에서도 확인 가능한 본문 누락과 수집 상태 미확인을 구분하도록 입력 검사를 보완한다. `partial` 전체를 보류로 바꾸지 않는 범위를 먼저 확정한다.
2. 최종 보류의 판단 쟁점·확인 자료 연결, 자료 부족이 아닌 근거 해석 검토 안내와 중복 설명을 보완한다.
3. 새 18건 참고 답안을 사람이 검수하고 고정한 뒤, 재배포·유료 실행 승인하에 같은 150건을 다시 비교한다. 18건은 별도 평가하고 미탐·과탐·잘못된 확정/보류·설명 유용성을 함께 확인한다.

위 1~2번은 이번 코드 변경에 포함하지 않았다. 미탐 한 건이 줄어드는 대신 정상 요청의 보류나 과탐이 늘어나는지도 보아야 하므로 전체 답안 일치율만으로 개선을 판단하지 않는다.
