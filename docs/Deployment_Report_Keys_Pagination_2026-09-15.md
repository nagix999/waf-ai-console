# PDF·운영 키 삭제 확인·페이지 이동 배포

2026-09-15, 현재 작업 환경의 로컬 Docker 네 서비스를 재배포했다. 별도 운영서버를 배포한 기록은 아니다. 앱 버전은 **0.2.0**을 유지하고 새 태그는 만들지 않는다.

## 적용 범위

- 웹 보고서와 같은 컴포넌트·글꼴·색상으로 PDF 직접 다운로드. A4 줄바꿈·페이지 나눔은 화면과 다를 수 있다.
- CRITICAL 배지의 진한 빨강 배경·흰 글자.
- Production API 키 삭제 시 연결 분석 보존/삭제 선택·정확한 키 이름 확인. 감사 이력과 검증 데이터셋 사본 보존.
- 기존 8개 페이지 이동 영역: 가운데 정렬된 처음·이전·번호·다음·끝, 현재/전체 페이지·표시 범위. 검색·서버 정렬·선택 범위 유지.

상세 동작·보호 조건·출력 한도는 [기능 안내](Report_PDF_and_Key_Deletion_2026-09-15.md)를 따른다.

## 데이터·설정 보존

대기/처리 중 분석과 모델 검증이 모두 0건임을 확인했다. 먼저 SQLite backup API로 만든 사본에 마이그레이션을 연습하고, 네 서비스를 중지한 상태에서 별도의 최종 백업을 확보한 뒤 실제 DB를 적용했다.

- DB: `0017_validation_data` → **`0018_dataset_source_deleted`**. 데이터셋 문항의 삭제된 원본 표시만 추가하며 기존 값은 모두 false다. 마이그레이션은 분석을 삭제하지 않는다.
- 기존 분석 **1,214건**, 암호화 값 **20,884개** 보존·복호화 확인.
- 25개 테이블 중 Alembic 버전 행을 제외한 모든 기존 행·열의 해시 일치, 무결성·외래 키 검사 통과. 새 표시 컬럼은 별도로 검사한다.
- `moduagent`, 현재 모델·역할·공통/편집 지침·동시 처리·서비스 키·암호화 키, 기존 명령·네트워크·볼륨·포트 보존.
- UI `http://127.0.0.1:18080`, API `http://127.0.0.1:18000`.

새 분석 접수·모델 검증·LLM 호출·설정 복원·키 발급·실제 분석 삭제는 수행하지 않았다. 이번 배포는 기존 모델 지정의 검증 성공 여부를 바꾸지 않는다.

## 확인 결과

- API healthy, API·worker·model-tester·frontend 실행 및 재시작 0회 확인.
- API와 두 워커의 **128개 파일**을 현재 소스와 대조했다. 웹은 현재 소스로 다시 Docker 빌드하여 배포 이미지 ID 일치와 캐시 적중을 확인했다.
- HTTP **35개** 통과: 인증·Origin 거부, 분석/테스트 평가, 데이터셋, 키 삭제 미리보기, 밝은/어두운 PDF·부록·잘못된 옵션 거부, Excel, 운영 API 정의서 PDF, OpenAPI 계약.
- 배포 브라우저 **7개** 통과: 로그인, 1440/390/320px 페이지 이동·가운데 정렬, 운영 키 삭제 미리보기/취소·기본 보존·이름 확인 전 버튼 비활성, PDF 직접 다운로드, CRITICAL 대비. 브라우저 오류·삭제 요청·LLM 호출 0건.
- 배포 API 이미지의 PDF/키 삭제 보호/내보내기 회귀 **52개** 통과. 실제 Chromium을 사용하되 임시 DB·가짜 입력·네트워크 차단 환경이며 앱 소스는 마운트하지 않았다.
- 프런트엔드 **40개 테스트 파일** 재통과. 앞선 전체 회귀·모의 브라우저 결과는 기능 안내에 보존한다.

초기 HTTP 점검은 로컬 Node 빌드 산출물을 참조해 파일명을 찾지 못했다. Docker 빌드 산출물 기준으로 수정 후 재검증했다. 브라우저 점검의 로그인 버튼 선택자도 실제 마크업에 맞춰 수정했다. 서비스 코드를 변경한 오류 수정은 아니다.

실제 Gemma/OpenAI 품질·장시간 부하·운영서버 자원 사용량은 미검증이다. 기존 Vite 번들 크기 경고와 Starlette 사용 중단 예고는 남아 있다.

## 재기동·복구·게시

이번 배포는 기존에 승인된 Chromium 의존성을 포함한다. API/worker 공통 이미지와 프런트엔드를 모두 저장소 루트 context로 빌드한다. Compose·자동화 스크립트에 반영되어 있다.

실제 로컬 Compose·최종 DB 백업·직전 이미지 정보는 비공개 `.local-deploy/README.md` 맨 위에 기록한다. 디렉터리 700, 비밀 구성·백업 600으로 보존하고 Git에서 제외한다. 기본 Compose만 실행해 포트·모드·키를 초기화하거나 `down -v`를 실행하지 않는다.

이전 이미지·백업은 남겼다. 배포 이후 데이터가 추가될 수 있으므로 복구 시 현재 DB도 먼저 백업하고 호환성을 확인한다. 원본 삭제 표시를 실제 사용한 뒤에는 0018 downgrade가 차단된다. DB 복원·downgrade·삭제는 이번 배포에서 수행하지 않았다.

GitHub 게시 대상은 기존 `nagix999/waf-ai-console`의 main이다. 원래 작업 폴더의 비어 있는 읽기 전용 `.git`은 수정하지 않고 기존 main을 이어가는 게시용 복제본을 사용한다. 승인된 코드·문서·테스트·글꼴만 게시하며 비밀값·DB·백업·의존성 설치물·생성된 보고서 번들을 제외한다.
