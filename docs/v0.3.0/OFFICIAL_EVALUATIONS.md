# 테스트 실행 구성과 공식 평가

2026-09-17. v0.3.0 개발 중인 계약이다. 운영 승격·전체 화면 전환·릴리스 완료를 뜻하지 않는다.

## 화면

- 테스트 상단 **실행 구성**에서 1차 판정(Primary), 추가 검증(Verifier), 근거 정리, 지침 버전, 입력 스키마 버전을 선택한다. 초기값은 Test 역할과 공통 활성 지침·스키마다.
- 현재 설정으로 전체 검증을 통과한 모델과 저장된 버전만 선택할 수 있다. 비활성 지침·스키마도 가능하며 운영 활성 설정은 바뀌지 않는다.
- 세 입력 방식에 같은 선택을 전달한다. 탭 전환은 작성 중인 입력을 유지하며 접수 중 구성 변경을 막는다. 구성을 다시 불러오면 기본값으로 돌아간다. 조회 실패 시 자동으로 다른 구성을 사용하지 않는다.
- 단건 입력의 추가 입력에 스키마 확장 필드용 JSON을 제공한다. 기존 필드 덮어쓰기는 막으며 서버에서 예약 필드·선택 스키마를 다시 검증한다.
- 데이터셋은 이름 검색으로 선택한다. 검색어는 POST 본문에만 보내고 브라우저 주소나 접속 로그 URL에 넣지 않는다.
- **공식 평가**는 승인된 문항만 실행한다. 미검토·검토 완료 문항 수와 제외 안내를 표시한다. 보류도 승인 답안으로 사용할 수 있다.
- **일반 분석**은 기존처럼 전체 문항을 실행하고 참고 답안과 비교한다. 공식 평가로 표시하지 않는다. 모의 실행은 공식 평가가 불가능하다.
- 공식 평가 상세에서는 승인 답안 고정을 명시하고 수동 답안 일괄 입력·수동 평가 저장 버튼을 숨긴다. 현재 결과와 자동 저장한 평가 기록을 선택할 수 있다.

## 접수 API

`POST /api/v1/validation-datasets/{id}/runs`

```json
{
  "expected_revision": 8,
  "name": "후보 구성 검증",
  "idempotency_key": "unique-request-key",
  "evaluation_mode": "ground_truth",
  "candidate_configuration": {
    "primary_profile_id": "profile-id",
    "verifier_profile_id": null,
    "evidence_editor_enabled": false,
    "evidence_editor_profile_id": null,
    "prompt_policy_version_id": "policy-version-id",
    "input_schema_version_id": "schema-version-id"
  }
}
```

`evaluation_mode` 생략 시 기존 API와 같은 `reference`다. 기존 재접수 키의 의미도 유지한다. 공식 평가를 요청하면:

1. 요청 revision이 현재 데이터셋과 같은지 확인한다.
2. 해당 버전의 approved 문항 ID·답안을 고정한다. 0건이면 거절한다.
3. 후보 구성과 각 문항 입력을 선택한 스키마로 검증한다. 오류가 있으면 이번 접수 전체를 rollback한다.
4. 내부 전용 문항은 세 역할 모두 내부 vLLM만 허용한다. 기존 승인·원문 암호화·감사 정책을 유지한다.
5. Primary → 조건부 독립 Verifier → 서버 정책으로 실행한다. 답안·승인 정보는 모델 입력에 넣지 않는다. 필드 설명도 계속 이력 전용이다.

기존 단건·파일·API 테스트를 공식 평가로 바꾸는 경로는 없다. 승인 후에도 이전 테스트는 일반 비교로 남는다.

`POST /api/v1/validation-datasets/search`: 관리자 전용 읽기 검색. `{ "query": "검색어", "limit": 20, "offset": 0 }`, limit 최대 50. `%`와 `_`는 와일드카드가 아닌 문자로 검색한다.

## 평가 기록과 재실행

- 공식 평가 답안은 `TestRunItem.label_id`에 연결한 접수 당시 답안이다. `reference_basis=latest` 요청이나 이후 분석 상세에서 입력한 참고 답안으로 바뀌지 않는다.
- 최신 실행이 전부 종료되면 worker가 사용한 분석 ID, 답안 ID, 후보 구성 지문, 지표 버전, 집계 결과를 `TestEvaluation`에 저장한다. 실패가 있어도 실패 건수·평가 제외 사유를 그대로 남긴다. 완료됐다는 이유만으로 운영 적용 자격을 부여하지 않는다.
- 평가 저장과 재실행 접수는 SQLite 쓰기 잠금으로 직렬화한다. 동시에 완료되거나 같은 작업을 복구해도 같은 평가 기록을 중복 생성하지 않는다.
- 평가 저장 실패로 분석 결과를 실패 처리하지 않는다. worker는 15초 간격으로 대기 실행을 최대 5개씩 순회해 중단된 기록 저장도 복구한다. 한 기록의 오류가 다음 기록 처리를 막지 않는다. 예외 로그에는 유형만 남긴다.
- 실패 항목 재실행은 기존 모델·지침을 유지한다. 문항별 최신 시도만 현재 지표에 반영하고, 완료 후 새 평가 revision을 자동 저장한다.
- 이전 평가 조회는 저장된 분석 ID와 답안 ID를 사용한다. 재실행 시각에만 의존하지 않는다. 전체 집계는 저장된 스냅샷을 사용하고 난이도·유형 필터는 같은 고정 ID의 부분 집계다.
- 일반 참고 비교의 수동 평가 기록 저장과 최신 답안 조회는 그대로 유지한다. 공식 평가에 수동 기록 저장을 요청하면 `official_ground_truth_fixed`로 거절한다.
- 서버 구분 필드는 입력 스키마·이벤트의 사용자 확장 필드로 등록할 수 없다.

## 비교 기준

공식 평가가 하나라도 포함된 비교는 양쪽 모두 공식 평가여야 한다. 데이터셋 버전 ID, 승인 문항 버전 목록, 지표 정의 버전이 같아야 한다. 현재 비교 범위는 전체 실행이며 상세 화면의 난이도·유형 필터를 적용하지 않는다.

기준이 다르면 `comparable=false`, `comparison_block_reason=ground_truth_scope_mismatch`와 빈 문항·미산출 지표를 반환한다. 화면에서도 버전·문항 목록 지문·지표 버전을 확인해 비교 수치를 숨긴다. 같은 event_id로 입력이 다른 문항은 문항 버전 ID로 각각 대응한다.

지표 정의 `waf-three-way-v1`은 기존 3×3 행렬과 이진 Accuracy/Precision/Recall/F1, 판정 보류 관련 지표를 그대로 쓴다. 분모가 없는 값은 null이며 0점으로 만들지 않는다. 실패·미평가·출처 구분도 보존한다. 고정 합격선이나 자동 승격은 추가하지 않았다.

## DB 변경과 이전

`0021_official_evaluation`:

- TestRun: 공식/일반 구분, 승인 문항 버전 ID 목록, 지표 버전, 평가 기록 대기 여부 및 조회 인덱스.
- TestRunItem: 데이터셋 문항 버전의 nullable 외래키.
- TestEvaluation: 공식/일반 구분, 지표 버전, 구성 지문, 고정 분석 ID, 전체 집계 스냅샷.

기존 실행·평가는 reference로 유지한다. 없는 구성이나 공식 평가 이력을 추정하지 않는다. 신규 설치의 현재 metadata와 기존 DB에서의 증분 이전을 모두 처리한다. SQLite downgrade는 문항 연결 외래키를 제거하기 위해 해당 연결 테이블만 재구성한다. 공식 평가 실행 또는 기록이 있으면 downgrade를 거절한다. 이 경우 업그레이드 전 DB와 대응 암호화 키 백업 복구가 필요하다.

새 운영 패키지는 추가하지 않았다. 실제 운영 DB migration, 모델 호출, Docker 재배포, Git 게시·태그 생성은 수행하지 않았다.

## 다음 단계

**평가된 구성의 운영 승격**: 실행 실패 없는 공식 평가 확인, 현재 운영 상태와 차이 표시, API 비호환 스키마 변경의 명시적 승인, 관리자 최종 승인, 구성 전체의 원자적 반영·충돌 차단·이력 저장. 기존 운영 기준 스냅샷과 직접 운영 변경 경로의 제한도 이 단계에서 구현한다.

그다음 공통 탐색·KR/EN·3개 테마·전체 세부 화면과 실제 worker 관측 기반 Runtime을 연결한다. 현재 기능은 v0.3.0 전체 완료가 아니다.

## 검증 결과

- 백엔드 후보 구성·공식 평가·Ground Truth·기존 데이터셋·비교·재실행·동시 처리·입력 스키마·마이그레이션 회귀 **179개 통과**. 공식 평가의 마지막 복구 조회 조정과 재접수/지표 버전 충돌 검증 후 관련 **8개 재검증 통과**. 두 숫자를 중복 합산하지 않는다.
- 공식 평가 테스트는 파일 기반 SQLite WAL에서 수행했다. 동시 저장 중복 방지, 답안 수정 후 공식 점수 유지, 승인 문항만 접수, 실패 재실행→새 기록, 과거 기록 고정, 동일 event_id의 별도 문항 대응, 다른 버전 비교 차단을 확인했다.
- 신규 설치·기존 테이블 형태·반복 upgrade·공식 평가 전 downgrade·공식 평가 후 downgrade 거절을 가상 DB로 확인했다. 처음 발견한 SQLite 외래키 DROP COLUMN 오류는 연결 테이블 재구성으로 수정했다.
