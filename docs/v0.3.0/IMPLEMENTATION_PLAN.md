# v0.3.0 구현 계획 — 2026-09-17

> 과거 계획입니다. 2026-09-21부터 최종 기준은 Canonical V5 REVIEWED이며, 현재 변경 내용은 [V5 구현 보고서](CANONICAL_V5_IMPLEMENTATION.md)를 따릅니다. 아래의 Production 직접 변경 유지와 이전 메뉴 구조는 현재 동작이 아닙니다.

## 기준과 합의

사용자가 제공한 `WAF_AI_Console_Astra_Handoff_FINAL.zip`의 문서 6개와 화면 참고 이미지 6개를 검토했다. 제품·동작은 ASTRA_HANDOFF, 데이터 계약은 BACKEND_CONTRACT, 시각 수치는 UI_IMPLEMENTATION_SPEC을 따른다. 이미지 속 임의 데이터·Q&A 예시·알림·GPU·비용 수치를 구현하지 않는다.

사용자 확인 사항:

- 운영 승격은 Approved Ground Truth의 공식 평가가 실행 실패 없이 완료된 구성만 허용한다. Accuracy/F1의 고정 합격선이나 자동 승격은 두지 않고 관리자가 검토·승인한다.
- 기존 운영 구성·분석·평가·암호화 데이터를 보존한다. 현재 구성을 이전 운영 기준 스냅샷으로 남긴다. 과거 평가에 공식 승인 이력을 만들어 넣지 않는다.
- 입력 API 호환성에 영향을 주는 스키마 변경도 변경 내역과 위험을 보여준 후 명시적으로 승인받으면 허용한다. 기존 핵심 필드 보호는 유지한다.
- UI 작업을 운영 승격 구현보다 먼저 진행한다. **승격 기능이 완성되기 전까지 기존 운영 모델 배정·공통 지침 활성화·입력 스키마 적용을 유지한다.** 이는 전환 기간의 합의이며, 최종 단일 승격 경로를 완료한 것으로 간주하지 않는다.
- 세부 화면은 데스크톱 브라우저 중심으로 정리한다. 별도 모바일 개선은 이번 범위에서 제외하고 기존 반응형 동작은 보존한다.

추가 구현 원칙:

- 기존 관리자 인증·외부 전송 승인·내부 전용 데이터 제한·원문 암호화·조회 감사를 유지한다.
- 정탐/오탐/보류와 Draft/Reviewed/Approved는 서로 다른 상태다. 참고 판정이나 합성 기대값은 승인된 Ground Truth로 자동 전환하지 않는다.
- 기존 단건·파일 테스트와 참고 판정 비교는 유지하되 공식 Ground Truth 품질과 분리해서 표시한다.
- 한 관리자가 검토와 승인을 수행할 수 있다. 별도 계정 체계나 2인 승인은 추가하지 않고 행위자와 각 단계 이력을 남긴다.
- 후보의 지침·스키마 선택은 운영 활성 상태를 바꾸지 않는다. 운영에 적용할 때는 UI의 현재 입력이 아닌 테스트 당시 구성을 사용한다.
- 프로필 ID만이 아니라 설정 지문, 전체 지침 스냅샷·내용 지문, 스키마 버전·지문, Evidence Editor 상태를 대조한다. 동시 처리 설정은 승격 범위에서 제외한다.
- 운영 직접 적용 버튼을 숨기는 것만으로 끝내지 않고 서버의 운영 변경 경로도 검토한다. 폐기·외부 승인 취소 등의 보안 차단은 우회하지 않는다.
- 실행 중인 서비스 변경, 운영 DB 마이그레이션, 실제 LLM 호출, GitHub 게시·태그 생성은 구현 검증과 별도다.

## 구현 순서와 검증 기준

2026-09-17 순서 조정: 3단계의 공식 평가까지 구현한 뒤 4·5단계의 UI를 먼저 진행한다. 운영 승격과 Runtime 관측 API는 이후에 연결하며, UI에서 미구현 상태를 정상 값으로 표시하지 않는다.

1. **Ground Truth 기반**: 검토 상태 DB/API, 새 불변 revision, 출처 보존, 기존 DB·평가 호환성. 가상 데이터로 전이·동시 변경·암호화·권한·마이그레이션 확인.
2. **Candidate 구성**: 단건/파일/데이터셋의 명시적 후보 구성, 지침·스키마 비활성 버전 선택, 요청 재전송과 worker 재실행 시 동일 스냅샷. Production 무변경 확인.
3. **공식 평가·운영 승격**: Approved membership 고정, 동일 revision·scope·지표 정의 비교, 승격 preflight/transaction/history, 기존 운영 기준선. 실패 시 전체 rollback·동시 승격 충돌·기존 결과 불변 확인.
4. **공통 화면·탐색**: 작은 i18n 계층, 3개 테마, 단일 sidebar, 기존 hash alias·뒤로 가기·URL 검색어 비노출, 공통 버튼/메뉴/dialog. 운영 의존성은 추가하지 않음.
5. **세부 화면 연결**: Inference/Evaluation/Models & Agents/API & Integration의 기존 기능 재배치, 후보 구성·승격·GT 검토 UI, 다운로드·원문 이동·검색/표 구성.
6. **Runtime**: 실제 heartbeat·queue·지연시간·진단·운영 품질·변경 이력, 읽기 전용 배포 정보. 미측정 데이터는 unknown/미제공으로 표시.
7. **릴리스 검증**: 백엔드 회귀·마이그레이션·프런트엔드 테스트/빌드, 데스크톱 1280~1920px·KR 3테마/EN Light, 접근성·언어/테마 전환·폼 보존. 기존 모바일 회귀 검사는 유지하되 새 모바일 개선은 하지 않는다. 완료 후 버전 0.3.0 정리.

## 데이터 변경 영향

첫 마이그레이션은 데이터셋 문항에 검토 상태를 추가한다. 기존 문항은 Draft가 되지만 내용·답안·암호문·기존 테스트 membership과 저장 평가는 그대로다. 상태 전이는 원본 행을 갱신하지 않고 새 문항/데이터셋 버전을 만든다.

구현한 `0019_ground_truth_review`에는 가져온 답안의 출처·작성자·원본 답안 ID도 nullable 필드로 추가했다. 기존 기록에 없는 출처 정보는 소급 추측하지 않는다. `0020_test_candidate_config`는 TestRun에 nullable 구성 스냅샷·지문을 추가하며 과거 실행을 새 후보·공식 평가로 간주하지 않는다.

`0021_official_evaluation`은 공식 평가 구분, 승인 문항 버전 연결, 지표 정의 버전, 평가 대기 상태 및 고정 평가 기록을 추가한다. 과거 실행·평가에는 reference 기본값만 부여하며 공식 평가로 소급 전환하지 않는다. 공식 평가 기록이 있으면 downgrade를 거부한다. 후속 마이그레이션에는 운영 구성·승격·변경 이력과 worker heartbeat가 필요하다. 실제 운영 DB에 적용하지 않는다.
