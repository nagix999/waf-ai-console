# UI 전환 기록 — 2026-09-17

> 과거 UI 작업 기록입니다. 6개 Workspace, SK 기본 테마, 운영 승격·Runtime API는 [Canonical V5 구현](CANONICAL_V5_IMPLEMENTATION.md)에서 대체·완성했습니다. 이 파일의 이전 목업과 메뉴를 구현 기준으로 사용하지 않습니다.

사용자 요청에 따라 운영 승격 구현보다 UI를 먼저 진행한다. 승격이 완성될 때까지 기존 Production 모델 배정·공통 지침 활성화·입력 스키마 적용을 유지한다. 이번 작업은 프런트엔드만 변경하며 DB 이전·운영 의존성 추가·실제 모델 호출·서비스 재배포는 포함하지 않는다.

## 연결한 화면

- 런타임: 상태, 운영 품질, 진단, 배포 정보, 변경 이력.
- 추론: 개별 분석 이력. 전체·운영·테스트 탭은 모두 개별 분석 목록이다.
- 평가: 테스트 실행, 실행 단위 테스트 결과, Ground Truth.
- 모델·Agent: LLM 프로필, Agent 구성, 공통 지침, 동시 처리. 기존 설정의 중첩 탭을 메인 탐색에서 제거한다.
- API·연동: Production API, API 키, 입력 스키마, vLLM 연결 대상.

기존 hash URL은 그대로 지원한다. 새 독립 화면은 `#settings/instructions`, `#settings/concurrency`, `#runtime/quality`, `#runtime/diagnostics`, `#runtime/deployment`, `#runtime/changes`를 사용한다. 기존 테스트 목록 링크는 실행 목록을, 테스트 개별 목록 링크는 개별 분석을 연다.

헤더 검색은 이벤트 ID·출발지 IP·회사명·탐지명으로 기존 분석 검색을 수행한다. 분석 ID는 UUID 형식을 확인한 뒤 상세를 연다. 검색어·폼 값·API 응답은 브라우저 주소, history.state, localStorage/sessionStorage에 추가 저장하지 않는다. 서버 검색 요청은 기존 API 계약을 그대로 사용한다. 기존 메모리 내 탐색 상태와 뒤로 가기를 유지한다.

## 표현과 접근성

- Light/SK/Dark 테마. 기본은 Light이며 OS 자동 테마는 추가하지 않는다. SK의 강조색과 성공/경고/오류 의미 색상을 분리한다.
- `waf-console-theme`, `waf-console-locale`에 허용된 설정값만 저장한다. 저장소 접근이 막혀도 화면은 작동한다.
- KR/EN은 **공통 메뉴·페이지 제목·런타임 상태·공통 닫기 조작**부터 적용한다. 언어 선택창에 적용 범위를 알린다. 기존 세부 페이지, 지표 설명과 오류 문구 전체의 영문 전환은 아직 미완료다. 사용자 입력·원문·모델 출력·보고서 본문은 자동 번역하지 않는다.
- 제목·짧은 설명은 본문 상단, 계정·언어·테마·검색은 헤더로 분리한다. 계정 이니셜은 현재 관리자 이름에서 가져온다.
- 공통 대화상자는 이름 있는 X 버튼과 기존 native dialog의 Escape·포커스 제어를 유지한다. 작은 화면은 dialog 기반 메뉴를 사용한다.
- 일괄 선택 동작은 선택한 항목이 있을 때만 표시한다. 저장 완료 안내는 선택이 해제되어도 보존한다.

## Runtime 정보의 한계

새 상태 화면은 기존 API에서 실제로 제공하는 운영 요청 수·일별 접수량·현재 저장된 모델/지침/스키마/동시 분석 상한만 표시한다. API 키별 필터와 선택 기간을 유지한다. API 응답 확인은 모델 검증이나 전체 서비스 정상 상태를 뜻하지 않는다.

worker heartbeat, 전체 큐 상태, 지연시간 p50/p95/p99는 아직 수집하지 않는다. 대기 수는 **선택 기간에 접수된 운영 요청** 기준이며 전체 큐라고 표시하지 않는다. 서버 이미지 버전·배포 시각·통합 구성 변경 이력은 미제공으로 표시한다. 화면 버전은 현재 frontend package 버전이며, 백엔드 배포 버전으로 표시하지 않는다.

운영 품질 화면 상단의 공식 평가 영역은 승격/운영 구성 연결 API가 없으므로 연결 전임을 알린다. 기존 참고 답안 비교·추이 그래프는 별도 하단 영역에서 유지하며 공식 평가나 전체 운영 정확도라고 표시하지 않는다. 기존 개별 분석 평가·테스트 평가 동작도 유지한다.

새 Runtime 읽기는 진행 중 요청이 있으면 4초, 평상시 20초 간격으로 갱신한다. 설정·키 목록은 20초 간격이다. 백그라운드 탭에서는 중지하고 오류 시 간격을 늘린다. 전체 기존 페이지의 polling까지 전환한 것은 아니다.

## UI 2차: 분석 상세

- `판정 결과 / Agent 실행 이력 / 입력 / 결과 JSON / 보고서`를 최상위 탭으로 분리했다. 기존 `/raw`, `/report` 주소와 뒤로 가기를 유지하며 `/agent`, `/json`을 추가했다.
- 위쪽에는 당시 실행 요약과 간단한 최종 판정을 유지한다. 모델·지침·스키마·시간의 저장값만 표시하고 누락값을 현재 설정이나 0으로 채우지 않는다. 근거 정리 모델의 이름처럼 결과 본문에 없는 정보는 사용자가 실행 이력을 조회했을 때 해당 기록에서만 보완한다.
- 실행별 **총 재시도 횟수는 기존 상세 API에 없으므로 추정하지 않는다**. 단계에서 출력 형식 재시도와 근거 인용 교정 횟수를 구분하며, 근거 교정의 앞뒤 호출에 포함된 출력 재시도를 합산한다. HTTP 전송 재시도나 worker 복구·수동 재실행까지 포함한 통합 재시도 지표는 아니다.
- 판정 결과는 요약 → 세부 분석 → 근거 → 참고 답안 비교 → 추가 확인 사항 순서다. 정탐/오탐 근거 구분과 보류 설명, 저장 판정은 바꾸지 않았다. 참고 답안 입력·데이터셋 추가는 별도 메뉴로 묶었다. 실패 상태에서 같은 설명을 두 번 표시하지 않는다.
- Agent 이력은 기존 단계 목록/상세 2열, JSON 트리·색상·검색·원문을 유지한다. 탭을 왕복하거나 테마·언어를 바꿔도 선택한 단계를 유지한다. ID·지문은 `실행 식별자`, 이벤트 ID·스키마 상세는 `이벤트·버전 정보`에서 확인한다.
- 입력에는 HTTP 원문 / 입력 필드 / 인코딩·난독화를 둔다. 근거의 `입력에서 보기`는 발췌문을 변환 없이 검색한다. HTTP는 원문 전체에서 같은 문구를 찾는 기능으로, 파서의 필드 경계를 다시 검증하거나 의미상 비슷한 위치를 추측하지 않는다. 메타데이터는 지정된 기본/추가 필드만 찾는다. 문구나 필드가 없으면 찾지 못했다고 알린다.
- 입력은 사용자가 탭이나 근거 이동을 선택했을 때만 기존 감사 대상 API로 조회한다. Agent 기록도 해당 탭을 열 때만 조회하며 벗어나면 진행 중 조회·주기 갱신을 중지한다. 방향키로 탭에 포커스만 옮길 때는 조회하지 않는다. 늦은 이전 분석 응답은 현재 화면에 반영하지 않는다.
- PDF/Excel은 다운로드 메뉴로 묶고 기존 서버 출력, 부록·조회한 디코딩 옵션, 감사와 발췌 민감정보 안내를 유지한다. 보고서/결과 JSON을 열거나 다운로드할 때 입력·Agent 조회를 새로 수행하지 않는다. 결과 JSON은 저장 결과 그대로이며 보고서 미리보기/Markdown 전환도 유지한다.
- 새 상세 탭·실행 요약의 KR/EN을 추가했다. 기존 Agent/원문 도구와 결과 설명 전체의 영문화는 후속 범위이며 모델·사용자 원문은 번역하지 않는다.

검증: 프런트엔드 45개 테스트 파일, 빌드, `scripts/inference-detail-smoke.mjs`의 가상 API 브라우저 검증을 통과했다. 브라우저에서 5개 탭·뒤로 가기, 명시적 원문/Agent 조회, 원문/필드/누락 발췌 이동, URL·저장소 비노출, 단계 선택 보존, PDF/Excel 옵션, 답안 저장 후 비교 갱신, 데이터셋/실패 재실행 확인창, KR 3테마·EN 제목·390px, 늦은 응답 무시와 오류 안내를 확인했다. 다운로드 바이너리는 가상 응답이며 실제 PDF 생성 서버를 다시 검증한 것은 아니다.

이 작업에는 DB/백엔드 변경, 새 의존성, 실제 모델 호출, Docker 재배포, Git 게시가 없다. 기존 Production 변경 기능과 미완성 승격 정책의 경계도 그대로다.

## UI 3차: 데스크톱 세부 화면

- 테스트 상세: `문항별 결과 / 평가 지표`로 나누고 저장된 Primary·Verifier·지침을 상단에 배치했다. 당시 전체 구성은 실행 정보에서 확인한다. 기록이 없으면 현재 설정으로 추정하지 않는다. 3×3 행렬의 칸을 선택하면 해당 문항 목록으로 이동하며 평가 기준은 유지한다.
- 테스트 비교: `판정 품질 / 시간·사용량 / 문항별 변화`로 분리했다. 지표 차이는 %p, 개수 차이는 건수로 표시하며 무조건 개선/악화로 색을 붙이지 않는다. 공식 평가의 답안 버전·범위·지표 정의가 맞지 않으면 기존 비교 차단을 유지한다. 누락값을 0으로 채우지 않는다.
- Ground Truth: 데이터셋 이름 검색과 승인 문항 수를 제공한다. 편집창은 `입력 / 답안·검토 / 버전 이력`으로 나누며 탭을 옮겨도 작성 내용을 유지한다. 미저장 변경이 있으면 검토·승인 및 버전 이동을 막고, 이전 버전은 읽기 전용이다. 입력 오류는 해당 탭과 필드로 이동한다. 내용 저장만으로 승인되지 않는다.
- LLM 프로필: 빠른 테스트·전체 검증만 표에 남기고 검증 결과·연결정보·편집을 더보기로 묶었다. 전체 검증창은 두 범위 중 하나를 선택한 뒤 실행한다. 기본은 연결·기능 확인이며, 150건 실행은 명시적으로 선택해야 한다. 외부 전송/비용 안내, 설정 변경 시 재확인과 중복 실행 방지는 유지한다.
- Agent: 적용 확인창에 저장된 배정과 제안 배정의 차이를 보여준다. Primary 변경에 따라 함께 바뀌는 Verifier와 근거 정리 사용 여부도 포함한다. 승격 기능 연결 전까지 기존 운영 배정은 계속 사용할 수 있다.
- 지침·스키마: 작성·적용과 비교/기술 정보 동작을 나누고 버전 목록의 높이와 읽기 영역을 조정했다. 작성 중인 버전은 닫았다 열어도 보존한다. 기존 필드 보호·샘플 검증·적용 확인은 바꾸지 않았다.
- API 키: 카드 목록을 표로 바꾸고 10개씩 페이지 이동을 적용했다. 이름 변경은 바로, 식별 정보와 삭제는 더보기에서 연다. 삭제 시 이름 재입력·분석 보존/삭제 선택·감사와 데이터셋 사본 보존 정책은 유지한다. 내부 연결 대상도 편집/관리 동작을 분리하고 사용 중인 대상의 삭제를 계속 차단한다.
- 공통 더보기는 마우스와 키보드로 열고 닫을 수 있다. Escape 후 원래 버튼으로 포커스를 돌려주며 비활성 항목에 자동 포커스하지 않는다. 부가 동작을 닫아도 별도 편집창은 유지한다. 주요 버튼과 표 간격·상태 색상을 3테마에서 맞췄다.
- 개별 분석 목록과 모델 프로필 조회도 백그라운드 탭에서 중지하고 오류 시 간격을 늘리는 조회 방식으로 변경했다. 모든 기존 조회 루프를 바꾼 것은 아니다.

## UI 4차: 목업 반영

`mockup/`의 12개 이미지와 ZIP의 `ASTRA_HANDOFF.md`, `UI_IMPLEMENTATION_SPEC.md`를 대조했다. 메뉴·행동·색상 토큰은 Markdown을 우선하며 이미지는 배치와 밀도의 기준으로 사용한다. 모바일을 새로 설계하지 않고 데스크톱 브라우저에 맞춘다.

- 공통: 242px 사이드바, 64px 헤더, 메뉴별 아이콘, KR/EN 표시와 3테마를 정리했다. 목업의 잘못된 메뉴명·중복 설정 탭·가짜 알림은 추가하지 않았다. 모든 그룹은 처음에 펼쳐 보이고 각각 접을 수 있다.
- 런타임: 상태 4개 → 설정/요청량 58:42 → 지연시간/실패율 58:42 → 최근 요청 순서다. 키·기간 선택을 페이지 제목 오른쪽에 배치했다. 최근 10건은 기존 분석 검색 API에 동일 키·기간·Production 조건을 전달한다. 조건 변경 중에는 이전 목록을 숨기고, 조회 실패 문구에 서버 오류 원문을 노출하지 않는다. 상세 및 동일 범위의 분석 이력으로 이동한다.
- 실행 실패율은 `실패 ÷ (완료 + 실패)`다. 대기·진행 중은 분모에서 제외하고 보류를 실행 실패로 세지 않는다. 값이 없거나 종료된 요청이 없으면 0% 대신 `—`를 표시한다.
- 요청량은 API에 있는 일별 총량만 그린다. 목업의 시간별 성공/재시도/실패 누적 막대, 재시도율, 전체 큐나 worker 정상 상태를 추정하지 않는다. p50/p95/p99는 `미측정`이고 가짜 선 그래프가 없다. 실제 설정 적용 시각·승격 구성 ID는 API가 제공하지 않아 추가하지 않았다.
- 분석 상세: 실행 요약/판정 요약 65:35, 판정별 배경, 310px 단계 타임라인과 상세 패널이다. 회사·IP 연결은 이벤트 정보로 옮겼다. 실행 선택·실행 시간은 한 줄로, 시작·종료 시각은 실행 식별자 창으로 모았다. 실제 기록된 단계만 표시하며 재시도 단계를 임의로 만들어내지 않는다. 단계의 모델·공급자·토큰은 메타데이터에서 읽고, 토큰이 마지막 호출의 기록이라는 점을 명시한다. 전체 호출 합계나 비용으로 오인하게 표시하지 않는다.
- Ground Truth: 데이터셋 카드, 검토 상태 탭, 문항 버전/저장 시각과 더보기 메뉴를 정리했다. 상세는 460px 오른쪽 패널이며 입력/답안·검토/버전 이력과 승인 보호 규칙을 유지한다. 목록 API에 없는 복호화된 HTTP·URI·IP를 목업의 표 칸에 채우려고 자동 조회하지 않는다. 원문은 사용자가 상세를 열었을 때만 기존 감사 대상 API로 읽는다.
- 평가 실행: 후보 구성 카드 아래 Ground Truth 선택/선택된 데이터셋 정보 2열을 배치했다. 승인 수·문항 수·버전은 조회값만 표시한다. 공식 평가/참고 답안 비교 구분과 외부 전송·승인 제한은 그대로다.
- 테스트 비교: 기준을 고른 뒤에는 기준 목록을 접고 두 실행과 6개 품질 지표 카드를 먼저 보여준다. `비교 기준 변경`으로 다시 선택한다. 조건이 다르면 점수 차이 비교를 계속 차단한다. p50/p95 등 기록된 수행 지표는 시간·사용량 탭에 남기고 비용이나 자동 합격 추천은 만들지 않는다.
- LLM 프로필: 공급자/모델, 설정된 컨텍스트 한도, 배정, 최근 검증과 실행 버튼을 간결하게 정리했다. 컨텍스트 숫자가 중간에서 줄바꿈되지 않도록 했다. 프로필 값이며 서버에서 감지한 한도라고 표시하지 않는다.

기존 사용자 합의대로 승격 기능 완성 전까지 Production 모델 배정·공통 지침 활성화·스키마 적용을 유지한다. 목업의 최종 승격 화면을 기능 없는 승인 버튼으로 흉내 내지 않는다. 운영 의존성·DB·분석 정책은 바꾸지 않았다.
