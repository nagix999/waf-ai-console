# 보고서 PDF와 운영 키 삭제

> 이 문서는 최초 구현 기록이다. PDF 출력은 이후 **Chromium·Playwright를 제거한 ReportLab 방식**으로 교체했다. 현재 설치·동작 기준은 [ReportLab PDF 안내](ReportLab_PDF_2026-09-15.md)를 따른다. 아래 브라우저 설치 명령은 과거 기록이며 현재 배포에 사용하지 않는다. 키 삭제·권한·감사·페이지네이션 계약은 유지한다.

2026-09-15 구현 후 로컬 Docker 재배포 완료. DB `0018_dataset_source_deleted`를 적용하고 기존 분석·설정·이력을 보존했다. **실제 분석 삭제·모델 호출은 하지 않았다.** 배포 범위와 점검 결과는 [배포 기록](Deployment_Report_Keys_Pagination_2026-09-15.md)을 따른다. 별도 운영서버는 미배포다.

## 보고서

분석 상세의 PDF 버튼은 인쇄창 없이 파일을 내려받는다. 서버 Chromium이 웹과 같은 `ReportDocument` 컴포넌트·Markdown 생성기·CSS·한글 글꼴로 출력한다. 화면의 밝은/어두운 테마와 평가·실행 부록 선택을 전달한다. A4 여백과 페이지 나눔 때문에 화면의 가로 폭·줄바꿈까지 픽셀 단위로 같지는 않다. 판정이나 설명을 새로 생성하는 LLM은 사용하지 않는다.

- 기본 PDF: 웹 보고서 기본 본문과 근거 발췌. HTTP 전체 원문·추가 입력 필드·Agent 중간 출력 제외.
- 부록: 화면의 ‘평가·실행 부록 포함’ 선택을 PDF에도 적용.
- 디코딩: 상세에서 디코딩을 조회한 경우에만 PDF 요청에 명시하고 서버에서 다시 계산한다. 별도 원문 접근 감사 이력을 남긴다. 분석 전체 원문은 추가하지 않는다.
- Excel: 기존 분석 상세 중심의 항목별 문서 유지. 웹 CSS와 PDF 전용 선택은 적용하지 않는다.
- 다운로드 시점에 저장된 최신 결과·참고 답안을 읽는다. 열린 화면이 오래됐으면 내용이 달라질 수 있다.
- 실제 완료 결과만 PDF/Excel을 제공한다. 모의·진행 중·실패 결과는 제외한다.

관리자 세션 전용 `GET /api/v1/analyses/{id}/report.pdf`는 다음 선택값을 받는다. 나머지 쿼리는 거부한다.

| 선택값 | 기본값 | 의미 |
| --- | --- | --- |
| `include_appendix` | `false` | 평가·실행 부록 포함 |
| `include_decoding` | `false` | 관리자 원문 접근 후 디코딩 내용 포함 |
| `theme` | `light` | `light` / `dark` |

본문 512,000바이트, 표시 항목 1,000개, PDF 80페이지, 파일 10MiB 한도다. 출력 입력 JSON에도 2MiB 한도가 있다. 초과하면 413을 반환하며 잘린 파일로 성공 처리하지 않는다. API 프로세스마다 PDF는 한 번에 1개만 생성하고, 다른 요청은 503 `report_export_busy`로 재시도를 안내한다. 45초를 넘기면 브라우저를 포함한 자식 프로세스 그룹을 종료하고 503 `report_export_timeout`을 반환한다. 이는 분석 동시 처리 설정과 별개다.

브라우저에는 고정 HTML/번들과 보고서 데이터만 제공한다. URL 요청·서비스 워커·다운로드를 차단하고 사용자 문자열은 React 텍스트로만 렌더링한다. DB/암호화/공급자 인증 환경변수·관리자 쿠키는 자식 프로세스에 전달하지 않는다. 브라우저 예외 내용도 로그나 API 응답에 출력하지 않는다. 웹과 같은 색상 출력은 [Playwright 공식 PDF 동작](https://playwright.dev/python/docs/api/class-page#page-pdf)의 배경 출력·print CSS 옵션을 사용한다.

CRITICAL 배지는 상세의 일반 회색 텍스트 규칙에서 제외하고 진한 빨강 배경·흰 글자로 표시한다.

## 운영 API 키 삭제

설정의 Production 키 삭제창에서 연결 분석 수를 확인하고 **분석 보존**(기본) 또는 **분석도 함께 삭제**를 선택한다. 어느 쪽이든 현재 키 이름을 정확히 입력해야 한다. 키와 키별 대시보드가 목록에서 사라지고 인증은 차단된다. 키의 내부 삭제 기록과 감사 이력은 보존한다.

분석 삭제 범위는 `service_api_key_id`가 해당 키인 Production 분석뿐이다. 같은 `source_system`을 사용해도 다른 키의 결과는 삭제하지 않는다. 선택 범위 안의 재실행·결과·암호화 원문·Agent 이력·참고 답안·리뷰를 함께 삭제한다. 대기/처리 중 분석, 다른 키 재실행 또는 테스트 이력의 참조가 있으면 분석 삭제 전체를 거부한다. 키만 삭제하여 분석을 보존하는 것은 가능하다.

검증 데이터셋 사본의 문항·답안·버전·내부 모델 전용 제한은 보존한다. 원본 연결만 해제하고 상세에 ‘삭제된 분석’으로 표시한다. 사본의 변경 사실도 감사 이력에 남긴다. 삭제는 하나의 DB 트랜잭션으로 처리하므로 실패하면 키·원본·사본 연결·삭제 감사 기록 모두 롤백한다.

삭제 직전에 잠금 상태에서 키 이름과 대상 목록·상태를 다시 확인한다. 미리보기 이후 새 분석이 생기거나 상태가 달라졌으면 409로 거부하고 다시 확인하도록 한다. 키 삭제 직전에 인증한 접수 요청도 적재 시 키 상태를 재확인한다. 이미 분석 보존으로 삭제한 키에 나중에 삭제 옵션을 덧붙여 데이터를 지울 수 없다. Test 키는 기존과 같이 분석 보존 삭제만 제공한다.

이 기능은 애플리케이션 DB에서의 삭제다. 기존 백업·보관된 PDF·검증 데이터셋 사본이나 SQLite 파일의 물리적 흔적을 지우는 보안 삭제 기능은 아니다. 백업 폐기와 보관 정책은 별도로 관리해야 한다.

## 빌드·DB 적용

새 운영 의존성은 `playwright==1.62.0`과 이에 맞는 Chromium/시스템 라이브러리다. 이미지 빌드 시 내려받으며 보고서 생성 시 인터넷은 필요 없다. API·worker가 공유하는 백엔드 이미지의 크기와 첫 빌드 시간이 증가한다. Node 빌드 단계에서 공유 보고서 번들을 만들며 런타임 Node 서버는 추가하지 않는다.

두 Dockerfile 모두 **저장소 루트**를 빌드 context로 사용한다. Compose와 자동화 스크립트를 함께 수정했다. Docker를 쓰지 않는 개발 환경은 다음 준비가 필요하다.

```bash
cd frontend
npm ci
npm run build:report
cd ../backend
pip install -e '.[dev]'
python -m playwright install --with-deps chromium
alembic upgrade head
```

UI 보고서 코드를 바꾸면 `npm run build:report`도 다시 실행한다. Docker 빌드는 자동으로 수행한다. WOFF2는 기존 Nanum 글꼴의 모든 글자를 유지한 압축본이며 OFL 예약 이름을 Waf Report로 변경했다. 원본·OFL 라이선스를 보존하며 웹 배포에 `assets/OFL-WafReport.txt`를 포함한다. 재생성 스크립트는 `scripts/build-report-fonts.py`이고, 재생성할 때만 `fonttools[woff]`가 필요하다.

Alembic `0018_dataset_source_deleted`는 데이터셋 문항의 `original_analysis_deleted` 표시만 추가한다. 기존 행은 `false`이고 마이그레이션 자체는 분석을 삭제하지 않는다. 배포 전 일관성 있는 DB 백업을 확보한 뒤 기존 절차로 API/worker를 중지하고 `alembic upgrade head`를 적용한다. 원본 삭제 표시를 사용한 뒤에는 0018 downgrade를 거부하며 복구에는 배포 전 백업이 필요하다. 포트·모델·지침·동시 처리 설정은 변경하지 않았다.

## 검증 범위

추가 요청한 페이지네이션은 기존 8곳의 이동 영역을 공통 컴포넌트로 바꿨다. 처음/이전/번호/다음/끝과 현재·전체 페이지, 표시 범위를 가운데 정렬한다. 번호는 최대 5개와 생략 기호로 표시한다. 서버의 offset/limit 조회를 유지하며 화면에 받은 행만 임의로 다시 나누지 않는다. 검색·정렬·평가 범위는 유지하며 기존 페이지 크기 변경 기능은 첫 페이지로 이동한다. 결과가 없으면 0/0페이지와 비활성 이동 버튼을 표시한다. 보고서·고정 평가 행렬처럼 페이지 조회가 없는 표에는 불필요한 조작을 추가하지 않았다.

테스트는 가짜 입력·임시 DB·외부 요청을 차단한 브라우저에서만 수행한다. 키 이름/삭제 범위 검증, 활성 분석 차단, 다른 키 보호, 데이터셋 사본 보존, 전체 롤백, 마이그레이션, PDF 권한/한도/타임아웃/환경변수 격리, 실제 Chromium 한글 PDF, 모바일·테마·삭제 모달·다운로드를 점검한다. 실제 운영 데이터 삭제나 운영 서버의 자원 사용량·동시 부하 검증은 하지 않는다.

검증 기록:

- 프런트엔드 40개 테스트 파일 통과. 기존 500kB 이상 JS 청크 경고는 남아 있다.
- mock 브라우저 12개 시나리오 통과: 키·PDF 4개, 페이지네이션 PC/390px/320px 3개, 기존 답안·보고서·테스트 상세 5개. 실제 API·LLM 호출 없음.
- API·프런트엔드 Docker 이미지 빌드 성공. 소스 마운트 없는 최종 API 이미지에서 PDF·키 삭제 관련 52개 테스트 통과.
- 밝은/어두운 8페이지 PDF의 정탐/오탐/참고 구분, 한글과 2,400자 공백 없는 발췌가 마지막까지 보존됨을 텍스트 추출·화면으로 확인.
- 배포 자동화 166개 테스트 중 160개 통과·6개 환경별 검사 생략. 별도 기본/Gateway Compose 계약 검증 통과(실제 .env 조회·서비스 변경 없음).
- 백엔드 전체 회귀 2,081개 통과. 별도 2건은 컨테이너의 `/scripts` 미연결로 실패했다. 해당 경로를 읽기 전용으로 연결하고 두 테스트 파일 전체를 재실행해 75개 모두 통과했다(앞서 통과한 검사와 중복 포함). 제품 코드 변경 없이 실행 환경 누락을 해소했다.
