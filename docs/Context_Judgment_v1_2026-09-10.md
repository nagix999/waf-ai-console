# 요청 문맥 판단 보강 v1

2026-09-10. 원문 후보 선택 평가에서 확인한 정상 데이터 과탐을 줄이기 위한 공통 지침 변경이다. 코드·오프라인 검증과 실제 모델 품질 평가는 구분한다.

## 확인한 문제

직전 gpt-5.4-mini 100건에서는 원문 출처 검증 오류가 없었지만 정상 답안 6건을 공격으로 판정했다. 저장된 두 역할의 해석을 관리자 감사 조회로 확인했다. GraphQL 별칭의 SQL 키워드, 정규식 안의 템플릿 표기, 무해한 이중 인코딩 검색어, 표시용 경로 세그먼트, 이스케이프된 코드 예시, JSON 문자열 속 HTTP 요청이 탐지 패턴과 일치한다는 이유로 공격 의도에 연결됐다. 이 사례들에서는 판단에 필요한 주변 원문이 이미 제공되어 있었다.

이는 원문 존재 검증이 의미적 정확성을 보장하지 않는 사례다. 후보 선택 변경·지침·단일 실행의 모델 변동 중 어느 하나만을 과탐 증가의 원인으로 입증한 것은 아니다.

## 이번 최소 변경

- 공통 시스템 지침을 `waf-system-v2.8` / `waf-judgment-v2.8`로 구분한다. 언어 문법·입력 위치·주변 값을 함께 해석하고 패턴 일치와 공격 시도를 구분한다.
- 인용문·코드 예시·검사 패턴·별칭과 실행 구문, 문자열 내부 개행과 실제 HTTP 경계를 구분한다. 디코딩 후에도 원래 값을 감싼 구조와 용도를 유지한다.
- 구조와 값이 함께 뒷받침하는 정상 문맥은 정상 근거로 사용한다. 가상의 서버 실행·재디코딩 취약점을 덧붙이지 않는다. 반대로 JSON·경로명·표시용 플래그 하나만으로 정상 처리하지 않고 실제 공격 구문과 맥락을 확인한다.
- 기존 원문 후보/출력 계약, 파서, 디코더, 예산 계산, 재시도, Verifier 실행·결합 정책은 유지한다. 새 도구·외부 조회·자동 판정 덮어쓰기를 추가하지 않는다.
- `v2.7`과 `v2.8`은 같은 후보 선택 계약을 사용한다. 새 코드에서도 `v2.6` 이전 스냅샷은 기존 인용 계약으로, `v2.7` 스냅샷은 기존 후보 선택 지침으로 실행한다. 이미 접수된 지침·결과를 재작성하지 않는다.
- Production/Test는 같은 새 공통 지침을 사용한다. 저장된 편집 지침 policy-2와 모델 지정은 유지하고, 입력 필드 설명은 계속 추론 이력에만 기록한다.

기본 Primary 지침은 3,191→3,692자(501자 추가)다. 문항별 예외·긴 few-shot 예시 없이 판단 기준만 추가했으며, 문자 수는 실제 모델 토큰 수가 아니다. 기존 4,096 토큰 시스템/스키마 예약을 바꾸지 않았고 Gemma4 tokenizer·32K 실행은 별도 검증해야 한다. DB 마이그레이션·운영 의존성 변경은 없다.

## 검증 범위

오프라인 테스트는 공통 지침 경계, 정상/공격 형태의 주변 원문 보존, 원문 후보 연결, 이전 두 버전의 실행 계약 유지, 두 역할 입력 동일성, 참고 답안 파일 불변성을 검사한다. 모의 출력과 텍스트 검사는 모델의 판단 정확도를 측정하지 않는다.

백엔드 전체 1,691항목 통과(567.19초), 관련 119항목 통과, 이후 Medium을 포함한 150건 원문 후보 검사 1항목 재확인을 완료했다. Starlette/AnyIO의 기존 폐기 예정 경고 1건이 있다. 백업과 행·암호문 비교 후 로컬 백엔드 세 서비스만 재배포했으며 기존 739건·키·모델·편집 지침·웹 UI는 보존했다.

사용자가 승인한 실제 평가는 같은 gpt-5.4-mini로 파싱 난이도 50건 + Hard 50건 + 추가 Medium 50건, 총 150건을 완료했다. 참고 답안은 바꾸지 않고 모델 입력에서 분리했다. 앞의 100건은 직전 v2.7 실행과 같은 문항 쌍으로 비교하고 Medium은 별도 결과로 제시한다. Medium에는 비교 가능한 직전 실행이 없어 개선율을 만들지 않는다. 동일 문항 재사용이므로 독립 평가셋 성능으로 표시하지 않는다.

참고 답안 일치는 파싱 46/50, Hard 36/50, Medium 37/50으로 총 119/150건이다. 같은 100건의 정상 과탐은 6→1건으로 줄었지만 필요한 보류를 확정한 오류는 9→12건으로 늘고 공격 문항의 보류가 1건 발생했다. 새 전체 150건에서는 보류 답안 30건 중 22건을 확정했다. 원문 검증 오류·추가 교정 호출·실행 실패는 없었다. **의미 판단의 부분적 개선이며 운영 확대를 권고하지 않는다.** 세 판정 혼동행렬, 조건부 지표, Verifier 변화, 배포 보존 결과와 한계는 [실제 평가 보고서](evaluations/Context_Judgment_GPT54Mini_150_2026-09-10.md)를 기준으로 한다.

공식 [GPT-5.4-mini 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.4-mini)와 [구조화 출력 안내](https://developers.openai.com/api/docs/guides/structured-outputs)를 확인하고 기존 모델·API·구조화 출력 계약을 유지했다. 구조화 출력의 형식 준수와 보안 해석의 정확성은 별도 검증 대상이다.

OpenAI Docs의 [GPT-5.4 계열 프롬프트 안내](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.4)에서 작은 지침으로 시작하고 측정된 오류를 고치는 내용만 추가하라는 원칙을 참고했다. 이번에는 긴 예시나 출력 스키마를 더하지 않고 관측한 문맥 해석 오류에 대한 공통 판단 기준만 추가했다.

HTTP 메시지 완전성·누락/상충 필드 검사는 다음 별도 범위이며 이번 문맥 지침만으로 해결했다고 표시하지 않는다. 실제 Gemma4와 사내 운영 로그, 미사용 독립 문항은 이번 평가에 포함하지 않는다.
