# 분석가 확인 안내 v2.4 검증 기록

기준일: 2026-09-07. 사용자 승인 범위는 화면·보고서 배치, 확인 안내의 목적 구분, 근거 반복 억제 및 합성 로그 4건의 실제 모델 연결 검증이다. 사내 로그 전송이나 150건 재평가는 수행하지 않았다.

## 변경 범위

- 판정 요약 → 세부 분석 결과 → 판정 근거 → 기타 정보 → 추가 확인 사항 순서. 보고서의 선택형 부록을 포함해도 추가 확인 사항이 마지막이다.
- 보류에는 판정 구분에 필요한 확인, 정탐·오탐에는 실제 유용한 선택적 후속 확인만 요청한다. 확정 판정의 빈 확인 목록은 숨기고, 신뢰도 수치만으로 확인 필요 여부를 결정하지 않는다.
- 같은 출처·발췌·해석의 완전 중복을 최종 결합에서 제거한다. 화면에서는 같은 원문을 묶고 다른 설명은 보존한다. 의미 유사도만으로 다른 해석을 삭제하지 않는다.
- 원문 출처 검증의 고정 시스템 진단은 업무 체크가 아니라 해석 주의사항으로 분리한다. 기존 결과에는 저장값을 수정하지 않는 표시 호환 처리를 적용한다.
- 판정 결합 정책, 독립 검증 입력, 기존 결과·Label, DB 스키마와 운영 의존성은 유지한다. 프롬프트는 `waf-judgment-v2.4`, 결과 계약은 `waf-analysis-v2`, 전처리는 `waf-text-decoder-v2`다.

## 실제 모델 4건

기존 승인된 OpenAI Production 프로필 `gpt-5.4-mini`를 변경 없이 사용했다. `/api/v1/test-analyses`로 순차 접수했으며 서버 분류는 `test` / `test_lab`이다. 별도 합성 기대값은 분석 요청에 포함하지 않았고, 기존 Label 150건을 유지했다. 새 Label도 등록하지 않았다.

| --- | --- | --- | --- | --- |
| 정상 검색 | 오탐 | 오탐 | NONE | 14.221초 |
| URL 인코딩 SQLi | 정탐 | 정탐 | LOW | 17.172초 |

| 환경값이 미해석인 조회식 | 보류 | 오탐 | NONE | 13.932초 |

모두 완료됐고 실제 8개 LLM 단계의 구조화 출력 교정은 0회였다. 모든 단계 시간과 토큰 사용량이 기록됐다. 프레임워크 사용량 합계는 입력 24,620 / 출력 5,075 / 전체 29,695 토큰이며 청구서나 네트워크 재시도 횟수의 검증값은 아니다. 입력 잘림은 없었다. JNDI·환경변수·외부 연결·코드는 조회하거나 실행하지 않았다.

## 결과 해석과 남은 한계

1. 4건은 연결·구조화 출력·화면 스모크 검증이다. 기대값 3건 일치를 운영 정확도 75%로 해석하지 않는다. 특히 보류 기대값은 검증된 정답이 아니라 사전 합성 가정이다.
2. 8개 역할 출력의 발췌 16개 중 5개가 지정한 원문과 일치하지 않아 제외됐다. 출처 검증은 동작했지만 잘못된 인용 생성 자체가 해결된 것은 아니다. 최종 출력에서 완전 동일한 근거 triple은 0개다.
3. 의미상 반복은 남았다. 정상·SQLi는 전체 요청과 하위 필드에서 같은 관찰을 반복했고, JNDI는 같은 원문의 두 설명이 상당 부분 겹쳤다. 프롬프트의 반복 억제가 의미상 중복 제거를 보장하지 않는다.
4. 미해석 조회식 표본은 실제 환경값·실행 미확인을 밝히면서도 테스트용 문자열로 보인다는 설명을 정상성 근거로 사용했다. 합성 메타데이터·변수명의 테스트 암시가 판단에 영향을 주었을 가능성과, 정상 처리 근거 없이 오탐으로 확정하는 경계를 추가로 검토해야 한다. 모델이 두 번 같은 결론을 냈다고 환경 확인이 대체되지는 않는다.
5. 실제 모델 4건에는 최종 보류가 없었다. 보류 안내의 표시·목적은 로컬 합성 회귀로 검증했으며 실모델의 좋은 보류 안내 출력은 이번 표본에서 확인하지 못했다.
6. 실모델 확인 후의 시스템 안내 분리·모바일 보강에는 추가 유료 호출을 하지 않는다. 저장된 4건은 재판정하거나 덮어쓰지 않는다.

## 자동 검증과 데이터 보존

- 백엔드 최종 전체 테스트: **810 passed**, 기존 Starlette/AnyIO deprecation 경고 1개.
- 프런트 최종 전체 테스트: **90 passed**, Vite build 및 합성 Chromium 회귀 통과. 보류·정탐·오탐·실패, 체크 유무, 동일한 97% 점수 조건과 기존 기술 진단의 주의사항 분리를 비교했다.
- 실제 JNDI 결과의 긴 요약에서 모바일 가로 넘침을 발견했다. 긴 무구분 합성 요약으로 재현한 뒤 줄바꿈·최소 너비 CSS를 수정했고, 390px 화면이 유지되는 것을 모의 브라우저에서 검증했다.
- 최종 Docker 배포 후 같은 실제 4건을 읽기 전용 Chromium으로 재검증했다. 1~3번의 저장된 기술 진단 체크는 표시 업무 0개·주의사항 1회로 구분됐고, 4번의 빈 확인은 유지됐다. 네 건 모두 모바일 390px에서 가로 넘침·브라우저 오류가 없었다. 보고서·Markdown·부록 전환도 통과했다. 로그인 외 POST, 추가 LLM 호출, 원문/Agent 조회, 무관 결과 조회와 외부 요청은 없었다.
- 원문·Agent 이력의 명시적 열기 시 지연 조회, 완료/실패 후 polling 중지, Markdown/서식 보기·선택형 부록, HTML 비실행을 회귀 검증했다.
- 실제 4건 접수 후 DB 읽기 검증: 기존 모든 행 보존, 분석·Agent 실행 각 4건 및 단계 32개만 추가. 분석 157건, Label 150건. 프로필·리뷰·모델 테스트 이력과 스키마 `0005_analysis_labels`는 그대로다. 관리자 조회에 따른 접근 감사는 추가된다.
- 최종 표시 보강 재배포에서도 157건의 모든 기존 행 보존과 환경 일치, 네 서비스 기동·API readiness·기존 관리자 로그인, 재시작 0회를 확인했다. UI는 `http://localhost:18080`, API는 `http://localhost:18000`이다. 활성 배포·롤백·비공개 백업 경로는 커밋하지 않는 `.local-deploy/README.md`에 남겼다.

## 다음 가장 작은 검증

추가 모델 호출에 합의한 뒤, 테스트를 암시하는 이름을 줄인 별도 합성 경계 표본으로 정상 처리 근거가 있는 경우와 없는 경우를 비교한다. 동시에 한 관찰의 근거를 여러 경로·문장으로 반복하지 않도록 출력 기준을 보강하고, 원문 인용 오류를 별도로 측정한다. 기존 4건 결과를 기대값에 맞춰 수정하거나 전체 150건을 곧바로 재실행하지 않는다.
