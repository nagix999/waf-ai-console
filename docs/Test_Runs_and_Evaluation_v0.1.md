# 테스트 실행 관리와 공통 평가 지표

## 문항 목록 기준 Excel·필드 선택 — 2026-10-22

웹의 **Excel 다운로드**는 현재 **문항별 결과**의 필터·정렬·답안 기준에 맞는 전체 문항을 받는다. `limit`/`offset`만 제외하며 현재 페이지나 체크한 문항만 내보내는 기능이 아니다. 난이도·유형·처리 상태·답안 비교·Confusion Matrix 셀·단일/복수 그룹·문항 목록에 적용된 AND/OR 조건을 함께 사용한다. 통계 편집 초안이나 문항으로 이동하지 않은 통계의 별도 조건은 문항 목록의 조건을 바꾸지 않는다. 기존 평가 지표의 분모는 다운로드와 별개로 유지한다.

모달에서 실제 대상 건수와 영문/한글 필드명을 확인하고 체크박스로 필드를 추가·제외한다. 기본은 사용 가능한 모든 필드 선택이며 전체 선택·모두 해제·필드 검색을 제공한다. 최소 한 필드를 선택해야 하며 0건이면 웹 다운로드를 비활성화한다. 모달의 조건/선택은 메모리에서만 유지하고 URL·브라우저 저장소에 넣지 않는다. 필터·평가 기준을 바꾸면 모달을 닫고 다시 확인하며, 페이지 이동만으로 내보내기 범위를 바꾸지 않는다.

파일은 정확히 **분석결과 / 컬럼안내** 두 시트다. 분석결과의 헤더는 영문이며 컬럼안내의 헤더는 `column_name`(영어 컬럼명), `column_name_ko`(한국어 컬럼명), `description`(설명), `example`(데이터 형식 예시)다. 선택한 컬럼만 안내하고 예시는 실제 원문·Cookie·첫 문항 데이터를 복제하지 않는 형식 예시다. 추가 입력의 설명은 가능하면 테스트 접수 당시 스키마 정의를 사용하며 현재 운영 스키마로 바꿔 쓰지 않는다. 비영문/특수문자 필드명은 영문 별칭으로 내보내고 한글명에 원래 필드명을 표시한다.

근거 영문 컬럼은 `evidence_true_positive` / `evidence_false_positive` / `evidence_context`다. 각각 주요 정탐 근거 / 주요 오탐 근거 / 주요 참고 내용이며 기존처럼 최대 5개·`\n---\n` 구분·표시 순서를 유지한다. 이전 한글 근거 헤더와 시트명에 의존하는 Excel 처리 코드는 수정이 필요하다. `verdict`는 최종 AI 판정, `expected_verdict`는 접수 당시 기대 판정, `reference_verdict`는 선택한 평가 기준 답안, `initial_verdict`는 외부 1차 판정이며 서로 대체하지 않는다.

| 관리자 API | 본문·계약 |
|---|---|
| `POST /api/v1/test-runs/{id}/export/preview` | `{filters}`. `filters`는 `/cases/search`와 같은 조건에서 `limit`/`offset`을 제외한 객체. `{count, columns, scope, reference_basis}` 반환. 각 column은 `{name, label_ko, description, example, group}` |
| `POST /api/v1/test-runs/{id}/export.xlsx` | `{filters, columns: [영문 컬럼명], expected_count, preview_scope}`. preview의 count/scope와 같은 대상인지 확인한 뒤 XLSX 반환 |
| 기존 `GET /api/v1/test-runs/{id}/export.xlsx` | URL에 조건을 넣는 기존 연동을 깨지 않도록 답안 기준만 받는 전체 문항 경로 유지. 출력 시트·영문 헤더는 새 형식을 사용. 웹은 위 POST를 사용 |

다운로드도 같은 SQLite 읽기 snapshot에서 대상·컬럼·내용을 확인한다. 모달 이후 새 문항/재실행/조건 적용 결과/필드 구성 등으로 대상 문항·실행 ID나 컬럼 구성이 달라지면 `409 test_export_selection_changed`이며 부분 파일을 만들지 않는다. 모달에서 **대상 다시 확인** 후 다운로드한다. 같은 문항이 처리 완료되거나 설명·답안 값만 갱신되어도 필터 대상이 바뀌지 않았다면 다운로드 시점의 일관된 값을 내보낸다. 진행 중 worker의 heartbeat 때문에 다운로드를 막지 않는다. scope는 변경 감지값이지 권한 토큰이 아니다. 필터는 POST 본문으로만 보내며 미지원 query/필드·페이지 옵션·중복/미지원 출력 컬럼은 422다. 관리자·정확한 Origin/CSRF·감사·암호화 정책을 유지하고 서비스 키는 사용할 수 없다.

사전 조회는 HTTP 원문이나 전체 결과 JSON을 적재·복호화하지 않고 문항 metadata·추가 필드 이름/타입·고정 스키마 정의만 읽는다. 제외한 payload는 실제 파일 생성에서도 읽거나 복호화하지 않으며, 전체 결과 JSON과 추가 입력도 해당 출력 필드가 필요할 때만 적재한다. 다운로드에는 기존 `export_test_run_xlsx` 감사를 남긴다. 한도(5,000행/128MiB 셀 값/512개 물리 컬럼/32MiB 파일)·수식 비실행·긴 값의 이어짐 컬럼·공식 답안·저장 평가·재실행 기준은 유지한다. 이어짐 컬럼도 안내 시트에 설명하며 이름 충돌은 422 `test_export_column_collision`로 부분 파일 없이 거부한다.

DB migration이나 새 운영 의존성을 추가하지 않는다. 이전 피드백 작업의 `0027_review_feedback` 변경을 보존하며 운영 DB·지침·모델·Production 승격 정책을 바꾸지 않는다. Docker 재배포·Git 업로드는 별도다.

**검증(2026-10-22)**: 기존 관련 backend 212개와 신규 23개, 중복 제외 **235개 통과**. 최종 Excel/행렬 59개를 다시 검증했으며 필터/정렬과 전체 페이지 일치·아홉 행렬 셀·AND/OR·추가 입력·영문 헤더/두 시트/선택 컬럼 안내·원문 제외/안전한 실패·새 대상 감지·처리 중 값 갱신·고정 평가/재실행·원문 이스케이프와 길이 분할·권한을 확인했다. 프런트엔드 **569개와 최종 Vite build 통과**(기존 500kB bundle 경고 유지). 브라우저는 통계 29장과 새 모달 10장, 총 **39개 스크린샷**을 생성하고 주요 데스크톱 Light·모바일 Dark 화면을 검토했다. 새 모달은 KR/EN·SK/Light/Dark·건수/선택·검색·페이지 이동과 필터 변경 구분·오류 후 제외 필드 유지·Escape/포커스 복귀를 검증했다. 모두 가상 API/합성 데이터이며 실제 서비스·LLM/외부 요청은 0회다. 화면은 `test-results/test-export/`, `test-results/test-statistics/`의 Git 제외 로컬 자료다. backend 전체 suite·운영 DB 규모/부하·실제 다운로드 배포 경로는 미검증이며 재배포·Git 게시는 하지 않았다.

## 사이드 메뉴·통계 요약·전체 Excel — 2026-10-12

사용자 요청으로 작업 공간의 서브 메뉴를 본문 탭에서 사이드바로 옮긴다. 기존 홈/평가/설정/운영/연동과 하위 기능·주소·권한은 유지한다. 메인 메뉴는 펼치고 접을 수 있고 현재 페이지의 서브 메뉴를 표시한다. 모바일에서는 탐색 창 안에서 하위 항목을 선택한다. 페이지 내부의 업무 탭은 그대로이며 테스트 상세는 **문항별 결과 / 평가 상세 / 통계 요약**을 제공한다. `#evaluate/tests/{id}/statistics`, `/metrics`는 새로고침·뒤로/앞으로 이동에서도 선택을 유지한다. 검색값·필드 값은 URL이나 브라우저 저장소에 기록하지 않는다.

### 집계 기준

- 집계 필드: `signature`(기본), `company_name`, `waf_vendor`, `waf_action`, `event_name`, `src_ip`, `dest_ip`, `difficulty`, `test_category`.
- 기본은 1개 필드이며 **기준 추가**로 2개·3개까지 선택한다. 같은 필드를 중복 선택할 수 없다. 예: `회사 + 시그니처 + WAF 조치`는 세 값이 모두 같은 문항끼리 집계하고 각 기준을 별도 컬럼으로 표시한다. 기준 변경·추가·제거 시 항목 검색과 페이지를 초기화한다.
- 현재 페이지가 아닌 테스트 전체의 선택한 난이도·유형 범위를 서버 SQL로 집계한다. 그룹 검색·정렬·페이지 이동을 제공하고, 상태·답안 비교·행렬·그룹의 문항 목록 필터는 집계 분모에 적용하지 않는다.
- 통계의 문항은 접수된 고유 문항(`ingest_status=accepted`)이다. 중복·접수 거부는 별도로 표시한다. 항목을 선택해 이동한 문항 목록도 같은 고유 문항만 표시하며, 필터를 초기화하면 기존 전체 접수 내역으로 돌아간다.
- 판정 비율 = 해당 판정 건수 / 판정이 기록된 완료 문항. 정탐·오탐·보류 세 비율을 모두 제공한다. 실패·중지·미완료는 판정 분모에 포함하지 않고, 판정값이 없는 완료 문항도 분리한다.
- **전체 정확도 = 답안 일치 / 비교 가능한 문항(보류 포함)**. 참고 보류와 AI 보류의 일치도 포함한다. 평가 상세의 이진 Accuracy(확정 정탐·오탐만 비교)와 분모가 다르므로 전체 정확도로 명시한다. 빈 분모는 0%가 아니라 `null`/`—`다.
- 기존 평가 제외 규칙(실패·미완료·모의 실행·실행 출처 미확인·답안 포함 입력), 공식 답안 고정, 최신/접수 당시/저장 평가 선택과 재실행 연결을 재사용한다. 기본은 최신 참고 판정이며 공식 테스트는 고정된 공식 답안을 사용한다. 저장한 평가는 당시 실행·답안을 유지한다.
- 미탐·과탐은 확정 판정의 오류 건수이며 답안 대비 모델 보류·보류 답안의 잘못된 확정은 별도 집계한다. 데이터 분포를 정확도나 운영 전체의 품질로 해석하지 않는다. 입력·원문을 복호화하거나 LLM을 호출하지 않는다.

### 새 관리자 API

| 경로 | 용도 | 파라미터 |
|---|---|---|
| `GET /api/v1/test-runs/{id}/statistics` | 필드별·조합별 통계 | `group_by`(쉼표로 구분한 1~3개 필드), `q`, `sort_by=cases/value/accuracy/inconclusive`, `sort_order`, `limit`(1~100), `offset`, 기존 답안·난이도·유형 선택 |
| `GET /api/v1/test-runs/{id}/export.xlsx` | 테스트 전체 Excel | `reference_basis=latest/initial` 또는 `evaluation_id`. 페이지·검색·문항 필터 파라미터는 거부 |
| 기존 `GET /api/v1/test-runs/{id}` | 통계 항목의 문항 조회 | 기존 단일 필터 `group_field`, `group_value` 또는 `group_missing=true`; 조합은 `group_filters` JSON. 기존 결과/평가 응답 유지 |

통계 응답은 `test_run_id`, `group_by`, `items`, `total_groups`, `limit`, `offset`, `summary`, `rejected`, `duplicates`, `reference_basis`, `evaluation_id`, `accuracy_includes_inconclusive`를 제공한다. `summary` 및 각 그룹은 `cases`, 처리 상태별 건수, 판정별 건수, `distribution_total`, `verdict_rates`, `labeled`, `comparable`, `matches`, `accuracy`, `label_coverage`, 오류 방향별 건수, `unclassified_completed`를 제공한다. 그룹의 `value=null`은 미입력이며 실제 문자열 "미입력"과 구분한다. 같은 테스트의 필요한 답안만 조회하도록 기존 최신 답안 관계의 대상 범위를 좁혔다.

조합 집계는 `group_by=company_name,signature,waf_action`처럼 요청한다. 빈 기준·중복 필드·4개 이상·허용하지 않은 필드·반복된 `group_by` 파라미터는 422로 거부한다. 응답에 선택 순서의 `group_fields` 배열과 각 행의 `values` 객체를 추가한다. 예: `values={"company_name":"Example Corp","signature":"SQL","waf_action":"D"}`. 이전 단일 집계와의 호환을 위해 `value`는 첫 번째 필드 값으로 유지한다. SQL은 각 컬럼을 개별 `GROUP BY`하며 문자열을 이어 붙이지 않는다. 따라서 구분자가 포함된 값이나 미입력과 실제 문자열이 섞이지 않는다.

항목 검색 `q`는 선택한 필드 중 하나라도 일치하면 표시한다. `sort_by=value`는 선택 순서대로 모든 기준을 정렬하고, 수치 정렬은 모든 기준 값으로 동률을 해소해 페이지 순서를 안정화한다. 검색·페이지 이동·집계 기준 수와 관계없이 상단 요약의 분모는 유지한다. 별도의 **집계 전 필터**를 적용한 경우에는 그 조건에 맞는 문항이 상단 요약과 그룹 집계의 분모다.

조합 항목의 문항 조회는 `group_filters=[{"field":"company_name","value":"Example Corp"},{"field":"signature","value":"SQL"},{"field":"waf_action","value":"D"}]`를 URL 인코딩해 요청한다. 1~3개 고유 기준을 AND로 적용하며 `value=null`은 NULL/빈 문자열을 함께 선택한다. 각 객체에는 `field`, `value`만 허용하고 값은 null 또는 1~4,096자 문자열, 전체 JSON은 32,768자까지다. 잘못된 JSON·필드·중복·타입·개수는 422이며 기존 단일 필터와 같이 보내면 충돌로 거부한다. 문항 목록의 **문항 필터 초기화**는 조합 선택도 해제하되 집계 기준 설정·답안 기준은 유지한다. WAF 차단/허용은 관측값이며 조합별 분포 자체로 관제 규칙을 확정하지 않는다.

### 집계 전 필터 — 2026-10-14

통계 요약의 **집계 전 필터**에서 과탐 방향·미탐 방향·판정 불일치를 빠르게 선택하거나 **조건 편집**으로 조건을 조합한다. 편집 초안은 적용 전까지 조회에 사용하지 않는다. 필드·연산·값을 모두 검증한 뒤 **필터 적용** 시 페이지를 처음으로 돌리며, 유효하지 않은 조건을 생략해서 전체 범위를 조회하지 않는다. **전체**는 집계 전 조건을 해제한다. 집계 기준은 기존처럼 1~3개이며 기준 변경·추가·제거는 적용한 조건을 유지한다.

- 과탐 방향: 참고 오탐(정상) → AI 정탐(공격), 기존 평가 outcome `false_positive`.
- 미탐 방향: 참고 정탐(공격) → AI 오탐(정상), outcome `false_negative`.
- 판정 불일치: 위 두 방향과 `abstained`(참고 확정 → AI 보류), `expected_abstention_mismatch`(참고 보류 → AI 확정). 참고 보류/AI 보류의 일치는 불일치가 아니다.
- 빠른 선택은 기존 평가에서 비교 가능한 문항만 대상으로 하며 실패·모의 실행·출처 미확인·답안 포함 입력 등을 오판으로 분류하지 않는다. 개별 참고/AI 판정 필터는 원래 저장된 값을 조회하고 평가 제외 규칙은 지표 계산에 그대로 적용한다.
- 최신 참고 판정/접수 당시 기대 판정/저장 평가 선택, 최신 재실행, 공식 테스트의 고정된 기대 판정을 기존 `test_read_context`로 공유한다. 공식 테스트에서는 화면의 필드명도 **기대 판정**으로 표시하고 이후 수동 참고 판정으로 공식 답안을 대체하지 않는다.

**필드 20개**: `reference_verdict`, `verdict`, `evaluation_outcome`, `company_name`, `signature`, `waf_action`, `waf_vendor`, `event_name`, `event_id`, `src_ip`, `dest_ip`, `src_port`, `dest_port`, `difficulty`, `test_category`, `case_name`, `status`, `severity`, `threat_category`, `confidence_score`. `verdict`는 Primary 단독 출력이 아니라 정책 결합 후 저장된 최종 AI 판정이다. payload·결과 JSON·암호화 원문·임의 추가 필드 경로·SQL·정규식은 허용하지 않는다.

- 텍스트: 같음/다름, 포함/포함하지 않음, 시작/끝남, 값 없음/있음. 포함·시작·끝남은 대소문자를 구분하지 않는 기존 SQL 비교를 사용하고 `%`, `_`, `\\`는 와일드카드가 아니라 문자 그대로 검색한다.
- 선택값(판정·비교 결과·WAF 조치·상태·심각도): 같음/다름, 값 없음/있음. 지정된 값만 허용한다.
- 숫자(포트·신뢰도): 같음/다름·초과/이상·미만/이하·값 없음/있음. 포트는 정수 0~65,535, 신뢰도는 유한 숫자 0~1이며 Boolean·숫자 문자열·범위 초과를 서버에서 거부한다.
- 값 없음은 텍스트/선택값의 NULL 또는 빈 문자열, 숫자의 NULL이다. 음의 비교(다름/포함하지 않음)에는 SQL NULL이 자동 포함되지 않으므로 필요하면 값 없음 조건을 OR로 추가한다.
- 묶음 내부 및 묶음 간에 각각 AND/OR를 선택한다. 예: `(회사=A OR 회사=B) AND (참고 판정=오탐 AND AI 판정=정탐)`. 임의 우선순위를 추측하지 않고 명시적인 묶음으로 계산한다.
- 화면은 최대 5개 조건 묶음·총 20개 조건을 제공한다. 서버도 루트/하위 묶음 두 단계, 루트 포함 최대 6개 논리 노드·20개 조건, 조건 JSON 최대 UTF-8 32 KiB, 텍스트 값 최대 4,096자를 제한한다. 깊은 중첩·빈 묶음·알 수 없는 필드/연산/속성·잘못된 값은 422 `invalid_test_case_filter`로 거부하며 입력 값을 오류에 출력하지 않는다.

조건은 **그룹 집계 전 WHERE**에 적용한다. 선택한 난이도/유형과 테스트 소속은 항상 AND로 고정하며 OR 조건으로 범위를 벗어나지 못한다. `summary`와 그룹 건수·판정 비율·정확도는 같은 필터 문항을 사용한다. `scope_cases`는 난이도/유형 범위의 필터 전 고유 문항 수, `case_filter_applied`는 조건 적용 여부다. 접수 거부/중복은 필터 전 범위이며 화면에 안내한다. 오판만 선택한 정확도 0%는 **선택 문항 정확도**이고 전체 모델의 정확도로 표시하지 않는다. 빈 분모는 여전히 `null`/`—`다.

## 단건 테스트의 1차 판정 — 2026-09-30

사용자 합의로 R5의 Production 단건 전용 제한을 **단건 테스트에 한해** 확장한다. 원본 canonical 문서는 과거 기준으로 보존한다.

| 접수 경로 | 1차 판정 입력 |
|---|---|
| Production/Test 서비스 키 `POST /api/v1/analyses` | 최상위 접수 메타데이터로 허용 |
| 관리자 `POST /api/v1/test-runs` | `event` 바깥의 접수 메타데이터로 허용. 기존 추가 JSON 사용을 위해 `event`의 최상위도 분리 처리하되 두 위치에 중복 지정하면 거부 |
| 관리자 `POST /api/v1/test-analyses` | 단건 요청의 최상위에서 허용 |
| 파일·평가 데이터셋·사용자 입력 스키마·`extra_fields` 내부 | 기존 제한 유지 |

- `initial_verdict`: `true_positive` / `false_positive` 중 하나. 현재 1차 판정 계약은 이 두 값만 허용하며 `inconclusive`는 지원하지 않는다.
- `initial_probability`: 유한한 **숫자 0~1**. 문자열·Boolean·범위 초과는 거부하며 90%는 `0.9`로 입력한다. 선택된 1차 판정 클래스의 신뢰도다.
- 두 값은 함께 입력하거나 모두 생략/null이어야 한다. `initial_model_version`은 판정·신뢰도가 있을 때만 선택 입력(1~255자)한다.
- 웹 단건 분석의 **추가 입력 → 1차 판정**을 사용한다. 추가 JSON에 넣어도 이벤트에서 분리하지만 전용 입력란과 같은 필드를 중복 입력할 수 없다.
- 기존 `Analysis` 컬럼에 저장한다. 원문·이벤트 지문·추가 필드·Primary/Verifier 입력·프롬프트·입력 스키마에는 포함하지 않는다. 단건 분석 상세의 1차/심층 비교를 재사용한다.
- `expected_verdict`와 독립적이다. 입력하지 않은 기대 판정을 1차 판정으로 채우지 않고, 데이터셋 복사에도 1차 판정을 답안으로 사용하지 않는다.
- 서비스 단건의 같은 이벤트를 재전송할 때 1차 판정의 추가·제거·변경은 `409 initial_assessment_conflict`다. 명시적 세션과 자동 생성 테스트 모두 동일하며 기존 값은 보존한다. 관리자 단건의 동일 접수 키로 내용을 바꾸면 기존 `409 test_run_idempotency_conflict`를 유지한다.
- 실패 재실행은 기존 1차 판정 스냅샷을 복사한다. 이번 변경이 이미 접수 거부된 문항을 자동으로 실행하거나 과거 데이터를 수정하지 않는다.
- 잘못된 필드는 단건 HTTP 검증에서 안전한 필드명으로 안내하고, 문항별 거부에는 `initial_assessment_pair_required`, `initial_probability_invalid` 등 고정 코드를 제공한다. 원문·필드 값을 오류에 출력하지 않는다.

DB migration·운영 의존성·Agent 지침 변경은 없다. Production 반영 절차와 API 키의 Test/Production 권한 분리는 그대로 유지한다.

## 평가 범위

- 분석 결과의 전체/프로덕션 및 테스트의 개별 문항 검색 조건에 맞는 **전체 결과**를 서버에서 집계한다. 테스트 실행 상세는 선택한 실행·난이도·유형 전체를 집계한다. 현재 화면의 한 페이지만 채점하지 않는다.
- Production에서도 참고 답안 연결 후 동일한 지표와 Confusion Matrix를 제공한다. 별도 참고 답안 파일의 미리보기·확정 및 append-only Label 이력을 재사용한다.
- Production 지표는 답안이 존재하는 선택된 표본의 성능이다. 답안이 없는 운영 트래픽의 정답을 추정하지 않으며, 검토 대상의 선택 편향 때문에 전체 트래픽 성능으로 일반화할 수 없다.
- 합성 기대값, 독립 참고 답안(`reference`, `ai_visible=false`), AI 결과를 본 참고 답안, 열람 여부 미확인은 분리해 표시한다. 혼합 집계는 독립 정확도 인증이 아니다.
- 실행 중 지표는 완료된 유효 문항에 대한 잠정 집계다. 실패·미완료·미라벨·stub·출처 불명·이미 답안이 포함된 입력은 품질 분모에서 제외하고 제외 건수를 표시한다.

## Confusion Matrix와 분모

각 평가 지표 옆 `?`는 마우스 올리기·키보드 포커스 및 클릭으로 설명을 제공한다. 정의와 높거나 낮을 때의 의미를 함께 설명하며, 보류율·커버리지처럼 단독으로 높고 낮음을 좋고 나쁨으로 판단할 수 없는 지표는 주의점도 표시한다.

양성은 참고 답안의 `true_positive`(정탐), 음성은 `false_positive`(오탐)다. 이 앱의 판정값 `false_positive`는 혼동행렬의 FP 셀과 다른 개념이다.

| 참고 답안 ↓ / AI 최종 판정 → | 정탐 | 오탐 | 보류 |
| --- | ---: | ---: | ---: |
| 정탐 | TP | FN: 미탐 방향 | AP |
| 오탐 | FP: 과탐 방향 | TN | AN |

`D = TP + FN + FP + TN`, `B = D + AP + AN`이다. `D`는 이진 참고 답안이 있고 정탐/오탐으로 확정한 유효 문항 수, `B`는 여기서 AI 보류까지 포함한 유효 문항 수다. 실패·미완료를 보류로 바꾸지 않는다.

| 지표 | 계산 | 해석 |
| --- | --- | --- |
| Accuracy | `(TP + TN) / D` | 확정 판정 중 정답 비율 |
| Precision | `TP / (TP + FP)` | 정탐으로 판정한 문항 중 참고 정탐 비율 |
| Recall | `TP / (TP + FN)` | 확정 판정한 참고 정탐 중 맞힌 비율 |
| F1 | `2TP / (2TP + FP + FN)` | 정탐 Precision·Recall의 조화평균 |
| Specificity | `TN / (TN + FP)` | 확정 판정한 참고 오탐 중 맞힌 비율 |
| 과탐률(FPR) | `FP / (FP + TN)` | 확정 판정한 참고 오탐을 정탐으로 판정한 비율 |
| 미탐률(FNR) | `FN / (FN + TP)` | 확정 판정한 참고 정탐을 오탐으로 판정한 비율 |
| Balanced Accuracy | `(Recall + Specificity) / 2` | 두 참고 클래스에 같은 비중을 둔 재현율 평균 |
| Macro F1 | `(정탐 F1 + 오탐 F1) / 2` | 두 클래스의 F1을 같은 비중으로 평균 |
| MCC | `(TP×TN − FP×FN) / sqrt((TP+FP)(TP+FN)(TN+FP)(TN+FN))` | 네 혼동행렬 셀을 함께 반영한 상관계수(-1~1) |
| 판정 커버리지 | `D / B` | 유효 이진 참고 문항 중 확정한 비율 |
| 보류율 | `(AP + AN) / B` | 유효 이진 참고 문항 중 보류한 비율 |
| 보류 포함 정답률 | `(TP + TN) / B` | 보류로 정답을 제시하지 못한 문항까지 분모에 포함 |
| 답안 연결률 | `labeled / total` | 현재 검색 범위에서 참고 답안이 있는 비율; 실행 실패에도 답안은 있을 수 있음 |

오탐 F1은 `2TN / (2TN + FP + FN)`이다. 각 비율의 분모가 0이면 API는 `null`, 화면은 `계산 불가`를 반환한다. Balanced Accuracy와 Macro F1은 **확정 판정한 참고 정탐·오탐이 둘 다 있어야** 계산한다. MCC도 분모 0을 임의로 0이나 1로 바꾸지 않는다.

Accuracy부터 MCC까지는 **확정 판정 기준**이다. 보류를 제외해 수치가 좋아 보이는 것을 막기 위해 커버리지·보류 건수와 보류 포함 정답률을 함께 확인한다. 이 Recall을 전체 공격 문항의 탐지율로 표현해서는 안 된다. 참고 답안 자체가 `inconclusive`인 합성 문항은 '기대 보류 비교'로 따로 집계하며 위 이진 행렬과 지표에서 제외한다. `waf-dummy-v1`은 참고 정탐 60건·오탐 60건·기대 보류 30건이다.

계산식의 기준은 [scikit-learn의 평가 지표 정의](https://scikit-learn.org/stable/modules/model_evaluation.html), [F1 및 Macro 평균 정의](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.f1_score.html)다. 보류·미지원 클래스·출처 처리 기준은 이 프로젝트가 정한 정책이며 scikit-learn 패키지를 운영 의존성으로 추가하지 않는다.

### 이번에 제공하지 않는 지표

ROC-AUC·PR-AUC·Brier score·확률 보정 오차는 현재 결과의 `confidence_score`를 정탐 확률로 간주해 계산하지 않는다. 이 값은 선택한 판정에 대한 모델의 자기평가이며 정탐의 보정된 확률이 아니다. 향후 양성 클래스 점수 정의와 독립 검증 자료를 확보한 뒤 도입해야 한다. 심각도 채점·자동 모델 합격선·자동 Production 승격도 이번 범위에 포함하지 않는다.

## 이름이 있는 테스트 실행

파일 업로드, 직접 입력, 설정에서 선택하는 합성 150건 판정 평가에 사용자가 테스트명을 입력한다. 이름은 표시·검색용이며 동일한 이름을 재사용해도 실행 ID는 서로 다르다. 이름·문항명에는 원문이나 비밀정보를 넣지 않는다.

### 결과 조회 동선

- **분석 결과 → 테스트 → 테스트명**에서 실행별 평가 지표·Confusion Matrix와 문항별 분석 결과를 함께 본다. 테스트 탭은 개별 분석 나열 대신 실행 목록을 기본으로 표시한다.
- **전체 / 프로덕션**은 기존 단건 분석 목록·필드별 검색·참고 답안 지표를 유지한다. Production 접수를 테스트 실행처럼 묶지 않는다.
- 문항을 누르면 기존 분석 상세로 이동하고, 돌아오면 원래 실행의 난이도·유형·셀·처리 상태·답안 비교·페이지를 복원한다. 테스트 목록으로 돌아오면 이름 검색의 초안·적용값·페이지를 보존한다. 다른 실행을 새로 선택하면 문항 필터는 초기화한다.
- **테스트 문항 전체 보기**는 실행 묶음이 없는 이전 자료를 포함한 전체 테스트 분석 검색이다. 이름 없는 자료만의 목록은 아니다. 기존 데이터의 묶음·이름을 추정하지 않는다.
- 이름 검색과 개별 테스트 문항 검색은 운영 분석 검색 상태와 분리한다. 이름 목록에는 분석용 source·판정 필터를 적용한 것처럼 표시하지 않는다.
- 테스트 분석 입력 화면의 결과·실행 목록 및 설정의 이름 있는 150건 결과는 같은 분석 결과 실행 상세로 연결한다. 실행 ID가 없는 이전 모델 검증 링크는 해당 source로 제한된 개별 테스트 문항 목록을 유지한다.
- 화면 조회는 GET만 사용하며 재분석·답안 수정·모델 호출을 하지 않는다. 수정 범위는 프런트엔드로, DB 마이그레이션이나 새 운영 의존성은 없다.

### 접수와 보존

- 새 실행은 고유 내부 source와 실행 ID를 발급한다. 동일 이벤트 ID라도 이전 실행을 덮어쓰지 않는다.
- 같은 접수의 재전송은 같은 `idempotency_key`를 사용한다. 같은 키로 이름·내용을 바꾸면 충돌이며 새 분석을 만들지 않는다. 새 실행은 새 키를 사용한다.
- 파일명·SHA-256은 출처 식별에 사용한다. 원본 파일 전체를 추가 평문 저장하지 않는다.
- 각 문항은 원래 행 번호, 분석 연결, 접수 결과, 선택적 난이도·테스트 유형·문항명 및 초기 참고 답안 연결을 보존한다. 파일 내부의 동일 분석 중복은 평가 표본을 늘리지 않는다.
- 과거 일반 테스트는 '이전 테스트 / 실행 묶음 없음'으로 남긴다. 접수 시각만으로 과거 파일 단위를 추정하지 않는다.

### 실행 조건과 답안

일반 테스트는 접수 당시 **Test 용도로 지정한 프로필**과 프롬프트를 고정한다. Production 지정은 변경하지 않는다. 실제 모델 실행에는 전체 검증을 통과해 지정한 Test가 필요하며 미지정이면 `409 test_model_profile_required`다. 해당 프로필이 변경·비활성화되거나 통신 허용이 해제되면 다른 모델로 조용히 전환하지 않는다. 지정 교체·해제는 이미 접수된 테스트의 고정 모델을 바꾸지 않는다. 기존 버전에서 Production을 고정한 테스트도 원래 스냅샷을 보존한다. 기존 150건 검증은 선택한 후보 프로필과 전용 model-test worker를 유지한다. Production 수집기의 모델 선택·중복 접수 계약은 변경하지 않는다. 용도 분리는 추가로 `0011_model_test_role`이 필요하며 [LLM 설정 정의서](LLM_Profile_Assignments_v0.1.md)를 따른다.

고정된 테스트 실행 평가는 접수 시점 답안을 사용한다. 일반 분석 결과 화면은 기존처럼 최신 답안을 사용하므로, 사후 정정한 경우 기준이 다를 수 있으며 화면에서 구분한다. 사후 답안 정정으로 이전 테스트의 점수를 몰래 바꾸지 않는다. 새 기준으로 독립 재실행하려면 변경한 답안과 함께 새 테스트를 접수한다. 재실행은 추가 모델 호출·비용이 발생할 수 있다.

모델·프롬프트 고정은 코드·파서 버전까지 완전히 재현 가능하다는 보장이 아니다. 요청한 조건과 실제 실행한 모델·실행 모드·완료 여부를 구별하며 stub는 실제 품질 점수로 세지 않는다.

### 평가용 메타데이터

이름 있는 테스트 파일은 이벤트 행의 최상위 `expected_verdict`, `difficulty`, `test_category`, `case_name`을 이벤트 검증 전에 분리한다. 직접 입력은 이벤트와 별도 요청 필드로 받는다. 이 필드들은 이벤트 지문·암호화 원문·Primary/Verifier 입력에 포함하지 않는다. 임의 payload 본문의 정답 문장까지 제거하는 기능은 아니다.

기존 150건 샘플의 분류는 참고 답안에서 정확한 event ID로 연결한다. 후보 검증용 패키지 원본 데이터셋은 보존하고 별도 메타데이터 파일을 사용한다. 분류가 없는 사용자 파일은 '미분류'이며 AI가 추측한 공격 유형을 시험 분류 정답처럼 사용하지 않는다.

## DB 변경과 배포

### 관리자 API

모든 `/api/v1/test-runs` API는 관리자 세션 전용이다. 서비스 API Key의 Production source별 조회 권한은 확장하지 않는다.

| 경로 | 요청 및 응답 |
| --- | --- |
| `POST /api/v1/test-runs` | JSON의 `name`, `idempotency_key`, `event` 필수. 이벤트와 별도로 `expected_verdict`, `difficulty`, `test_category`, `case_name` 선택. 공통 활성 프롬프트를 고정하고 실행 상세 반환 |
| `POST /api/v1/test-runs/uploads` | multipart의 `name`, `idempotency_key`, `file` 필수. JSON/CSV 최대 파일 제한과 최대 5,000행 검사. 공통 활성 프롬프트를 고정하고 실행 상세 반환 |
| `GET /api/v1/test-runs` | `q` 이름 검색, `limit`(1~100, 기본 20), `offset`. `items`, `total`, `limit`, `offset` 반환 |
| `GET /api/v1/test-runs/{id}` | `limit`(1~200, 기본 50), `offset`, 난이도·유형 및 문항 필터. 실행 정보와 `items`, `total_items`, `facets`, `evaluation_summary` 반환 |
| `GET /api/v1/test-runs/{candidate_id}/comparison` | `baseline_id` 필수, `limit`(1~200, 기본 25), `offset`, `changes_only`. 두 실행 전체의 공통 문항·고정 답안 비교; 페이지 필터는 요약 분모와 분리 |

`name`은 공백만 아닌 표시 가능한 1~120자다. `idempotency_key`는 8~120자의 영문·숫자·`_.:-`만 허용한다. 난이도는 최대 80자, 유형 120자, 문항명 240자다. 이름은 비밀정보 저장란이 아니다. 이벤트 본문 오류는 원문을 응답에 포함하지 않으며 접수 거부 문항으로 기록한다.

상세의 `difficulty`, `test_category`는 지표·행 목록을 함께 좁힌다. `difficulty_missing=true`, `test_category_missing=true`는 미분류 선택이다. `status`, `evaluation_outcome`, `reference_verdict`, `verdict`는 **문항 목록만** 좁힌다. 혼동행렬 셀 선택 후에도 원래 평가 범위의 점수·분모를 유지한다. 분석 결과 공통 목록에는 `test_run_id`, `test_difficulty`, `test_category` 필터가 추가된다.

실행 상세는 `source_system`, `execution_mode`, 안전한 `profile_metadata`, `prompt_version`, 접수/상태별 건수, `started_at`, `completed_at`, `total_elapsed_ms`도 제공한다. 실행 조건의 암호화 지침·API Key는 응답하지 않는다. 거부된 행에는 분석 ID가 없으며, 파일 내부 중복 항목은 독립 평가 표본으로 세지 않는다.

기존 관리자 `/test-analyses`, `/test-uploads`는 `name`, `idempotency_key` query를 필수로 받고 새 실행에 연결한다. 이전 응답 구조에 `test_run_id`를 추가하며, 재전송 시 원래 접수 건수를 반환한다. Production `/analyses`, `/uploads`의 요청·멱등키 계약에는 변경이 없다. 모델 설정의 150건 검증은 기존 `/model-profiles/{id}/tests`에 이름과 접수 키를 보내고 `test_run_id`로 공통 상세를 조회한다.

### 마이그레이션

Alembic `0010_test_runs`는 `test_runs`, `test_run_items` 및 필요한 연결 메타데이터·인덱스를 추가한다. 새 운영 패키지·큐는 추가하지 않는다. 기존 분석·암호화 원문·결과·Label 이력을 삭제하거나 다시 분석하지 않는다.

운영 적용 전 SQLite 일관성 백업과 암호화 키 백업을 확인하고 API 및 쓰기 worker를 중지한 뒤 마이그레이션한다. 새 스키마 적용이 완료된 후 같은 버전의 API·analysis worker·model-test worker를 시작하고 프런트엔드도 재빌드한다. 실행 이력이 있는 스키마의 강제 downgrade는 하지 않는다. 이 개발 작업 자체는 운영 DB 마이그레이션·Docker 재배포·실제 LLM 검증을 수행하지 않는다.

## 검증 범위

GPU 없이 합성 SQLite 데이터와 모의 Agent 출력으로 계산식·빈 분모·출처 구분·필터·페이지 범위·권한·실행 분리·재접수 중복 방지·답안 격리·프로필 고정·마이그레이션 이력 보존을 검증한다. 실제 모델 정확도, 유료 호출 비용, 장시간 다중 프로세스 실행과 운영 부하는 별도 환경에서 확인해야 한다.
