# 원문 후보 선택 v1 — 2026-09-10

## 목적과 적용 범위

인용 교정 v2의 동일 100문항 재평가에서 참고 답안 일치가 80→63건, 보류가 23→36건으로 악화됐다. 디코딩 값이나 파서 힌트를 원문 필드처럼 출력하는 오류가 주요 원인이었다. 이번 변경은 원문 인용을 서버가 구성하고 모델은 후보 번호와 해석을 선택하도록 바꾼다. 파서의 메시지 완전성 판정, Verifier 실행·결합 정책, 모델 지정, 답안은 변경하지 않는다.

## 계약

- 새 공통 시스템 지침: `waf-system-v2.7`, 프롬프트: `waf-judgment-v2.7/policy-N`. Production/Test에 동일하게 적용한다. 관리자 편집 지침의 저장 내용·활성 버전은 보존한다.
- 새 지침으로 고정된 실행만 `evidence-selection-v1`을 사용한다. 과거 암호화 스냅샷의 시스템 버전은 유지하고 기존 인용 계약으로 처리한다. 기존 완료 결과를 재작성하지 않는다.
- 내부 모델 출력의 evidence는 `source_id`, `interpretation_ko` 두 필드다. 외부 결과는 기존 `waf-analysis-v2`의 `field`, `excerpt`, `interpretation_ko`로 서버가 변환한다. 새 DB 마이그레이션이나 운영 패키지는 없다.
- 후보 번호·원문·위치·디코딩 힌트 연결과 모델 원래 출력은 암호화된 Agent 입출력에만 저장한다. 평문에는 버전, 건수, 고정 사유 코드만 남긴다. 입력 필드 정의는 기존 버전 스냅샷의 이력 용도만 유지하며 LLM에 설명을 추가하지 않는다.

## 원문 후보

실제 모델에 제출된 연속 원문 구간에서만 후보를 만든다. 요청 라인·본문, 검증된 디코딩 원문, 제출 구간의 양 끝, 제한된 줄·청크, 제출된 이벤트 scalar를 사용한다. 특정 문항 ID·정답·공격 패턴을 순위 기준으로 사용하지 않는다.

최대 48개, 후보당 300자, 직렬화 예산 최대 8,192자 또는 전체 입력 문자 예산의 1/5 중 작은 값이다. 전체 입력 예산에서 미리 예약한다. 줄 순회 100회, 한 구간 청크 100회, 메타데이터 깊이 8·scalar 100개로 제한한다. 모든 원문을 후보로 담는 것은 아니며, 누락은 `omitted`로 표시한다. 필요한 근거가 후보에 없으면 보류하도록 지시한다. 후보의 부재를 공격 부재로 해석하지 않는다.

선택 뒤에는 번호 존재 여부, 중복 번호, 정확한 원문 문자열, 원래 위치, 해당 HTTP 필드 구간, 실제 제출 구간을 다시 검증한다. CR/LF 변환, 다른 필드 검색으로 보정, 생략된 위치의 동일 문자열 대체를 하지 않는다. 확정 판정에는 payload 또는 실제 추가 필드 근거가 필요하며 시그니처·IP·WAF action만으로 확정하지 않는다. 추가 필드의 실제 의미나 근거 해석의 타당성까지 기계적으로 보증하지는 않는다.

## 디코딩과 해석

후보의 `decoded_hint_indexes`는 암호화 입력에 포함된 디코딩 힌트의 원문 위치에 연결한다. 디코딩 결과를 별도 원문 인용으로 출력하지 않는다. 모델은 연결된 디코딩 전 원문 번호를 고르고 `interpretation_ko`에서 원문 관찰과 정적 변환 결과를 구분한다. 긴 디코딩 원문은 여러 300자 후보로 나뉠 수 있다. 기존 original/decoded/steps/warnings는 그대로 제공한다.

정적 디코딩은 서버의 실제 해석·Log4j 실행·침해 성공의 증명이 아니다. 새로운 네트워크 조회나 코드 실행 도구를 추가하지 않는다.

## 실패와 교정

형식 오류에는 기존의 원인별 구조화 출력 교정을 1회 유지한다. 존재하지 않거나 원문 위치가 맞지 않는 후보를 선택하면 같은 역할·모델에서 번호 교정을 최대 1회 요청한다. 번호 교정 중 형식 오류 재시도는 중첩하지 않는다.

교정은 오류가 난 인덱스의 번호만 바꾼다. 판정·요약·해석·나머지 유효한 근거는 재작성하지 않는다. 미해결 선택, 수정 대상 밖의 변경, 재판단 필요 응답이면 유효한 원문은 보존하고 보류한다. 교정 LLM 실패는 기존 Primary 실패/Verifier 보류 규칙을 따른다. 근거 검증을 완화하거나 Verifier를 끄지 않는다.

## 검증 구분

로컬 Docker 재배포 후 같은 gpt-5.4-mini·100건을 실제 평가했다. 일치 63→81건, 보류 36→15건이며 원문 선택 오류·교정 호출·형식 교정은 0건이었다. 다만 정상 답안의 과탐이 1→6건으로 증가해 운영 정확도 전반의 개선으로 보지 않는다. [실제 평가 보고서](evaluations/Evidence_Selection_GPT54Mini_100_2026-09-10.md)에 혼동행렬, 지표 분모, 실패 사례와 데이터 보존 검증을 기록했다. 새 후보 선택 관련 29항목, 최종 관련 회귀 127항목을 통과했다.

합성 입력 단위·통합 회귀와 동일 gpt-5.4-mini·파싱 난이도 50건 + 기존 hard 50건 재평가를 구분한다. 실제 결과는 별도 평가 보고서에 기록한다. 같은 문항을 개발에도 사용하므로 독립적인 미사용 평가셋은 아니다. Gemma4 및 실제 운영 로그의 품질·토큰 한도는 별도 검증이 필요하다.

구조화 출력의 객체 추가 필드 금지·필수 필드 처리는 기존 공용 변환기를 재사용한다. 기준: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). 스키마 준수가 판정의 정확성을 보장하지는 않는다.
