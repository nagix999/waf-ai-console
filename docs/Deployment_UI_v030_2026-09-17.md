SQLite backup API로 사본을 만들어 이전 리허설을 통과한 뒤, 진행 중 분석·모델 검증이 없는 상태에서 서비스를 정지하고 최종 백업을 생성했다. 실제 이전 후 25개 테이블의 기존 열·행을 해시로 대조했다. 분석 **1,214건**, 암호화 값 **20,884개**의 보존·복호화와 DB 무결성·외래 키 검사를 통과했다.

이전 직후 읽기 전용 Docker 볼륨에서 SQLite WAL 보조 파일을 열 수 없어 검증이 한 차례 중단됐다. 스키마는 이미 정상 적용돼 있어 재적용하지 않았다. 볼륨에서 보조 파일 생성만 허용하고 DB 연결은 `mode=ro`로 유지해 검증을 완료했다. 데이터 덮어쓰기·다운그레이드·백업 복원은 하지 않았다.

기동 후에는 접속 감사가 추가될 수 있으므로 기존 감사 행의 포함 여부까지 대조하고 추가만 허용한다. 분석·평가·설정 등 다른 기존 테이블은 일치해야 한다.

배포 전 발견한 기존 `/api/v1/test-uploads` 오류도 최소 수정했다. 내부 함수를 직접 호출할 때 새 `Form` 기본값 객체가 후보 구성으로 전달돼 업로드가 422로 거절됐다. 이 이전 호환 경로에는 후보 선택이 없으므로 `candidate_configuration=None`을 명시했다. 새 기능이나 판정 정책 변경은 아니다.

테스트 자료도 현재 계약에 맞췄다. 구버전 실행에는 후보 지문이 없음을 재현하고, 새 실행에서는 손상된 지침을 후보 구성 검증이 먼저 차단하는 것을 별도로 확인한다. Alembic 테스트가 비활성화한 logger는 해당 로그 검증에서만 복구한다. 샘플 생성 스크립트 누락은 검증 컨테이너의 읽기 전용 경로 연결로 해결했다.

## 백업과 남은 범위

최종 이전 전 백업은 `.local-deploy/ui-v030-20260917-6QtmTd/backup.db`다. `rehearsal-backup.db`·`rehearsal.db`는 사전 연습 자료이므로 혼동하지 않는다. 비밀 구성·DB는 비공개 디렉터리에 보존하며 Git에 포함하지 않는다.

구 이미지와 `previous-compose.json`을 보존했지만 자동 복구 명령으로 실행하지 않는다. 새 문항 검토·후보 테스트·공식 평가가 기록된 뒤에는 단순 다운그레이드가 안전하지 않다. 복구가 필요하면 현재 DB까지 먼저 보존하고 이후 기록과 호환성을 검토한다. `down -v`나 DB 덮어쓰기를 하지 않는다.

실제 LLM 품질·운영 GPU·부하 검증은 수행하지 않았다. 운영 승격·이전 운영 기준 스냅샷·실제 Runtime 관측 API·세부 문구 전체 영문화는 미완료 상태다. 승격 기능 완성 전까지 기존 운영 설정 변경 기능은 유지한다.
