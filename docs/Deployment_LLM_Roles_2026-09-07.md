관리자 프로필 조회에서 기존 Production 1건은 `can_assign=true`, Draft 1건은 `can_assign=false`/`profile_not_verified`임을 확인했다. Test는 두 프로필 모두 false다. 프로필 지정·해제·수정 API는 호출하지 않았다. 로그인 이후에도 백업과 모든 기존 행·열을 다시 대조해 일치, DB 무결성·외래키 정상, 분석/검증 실행 건수 불변과 대기 작업 0건을 확인했다.

이번 기동 후 점검은 HTTP·인증·스키마·정적 파일 일치 검증이다. 배포된 화면의 브라우저 클릭 검증이나 실제 모델 호출 검증을 수행한 것으로 해석하지 않는다. 개발 단계의 합성 브라우저 검증은 별도 기능 문서에 기록되어 있다.

Test는 아직 미지정이다. 일반 테스트를 실제 모델로 실행하려면 관리자가 현재 설정의 전체 검증을 통과한 프로필을 Test로 명시적으로 지정해야 한다. 지정 전에는 Production으로 대신 실행하지 않는다. 후보 모델의 빠른·전체·150건 검증은 별도 요청이며, 모델 호출·비용·외부 전송 승인이 필요한 작업이다.

## 복구와 재시작 주의사항

- 기존 Compose 파일만 단독 실행해 이번 로컬 배포의 이미지·포트·실행 설정을 바꾸지 않는다. 배포 설정과 이미지 식별자를 먼저 확인하고 같은 버전의 API·두 worker·UI를 유지한다.
- 백업 복구는 복구 권한, 복구 이후 모델 선택 정책, 배포 후 추가된 분석·답안·감사·설정 등의 신규 데이터를 검토한 뒤에만 수행한다. 복구 직전의 현재 DB도 별도로 보존하고 모든 쓰기 프로세스를 중지해야 한다.
- 이 백업의 존재가 무조건적인 덮어쓰기나 데이터 삭제의 승인을 뜻하지 않는다. DB뿐 아니라 암호화 키의 안전한 보관·복원 가능성도 확인해야 한다.
- 자동 또는 강제 downgrade를 실행하지 않는다. Test 지정이 남으면 `0011` downgrade가 차단되고, 이름 있는 실행 이력이 있으면 `0010` downgrade가 차단된다. SQLite에서 허용된 downgrade도 참조 이력을 보존하기 위해 일부 추가 컬럼을 남긴다.
- 이후 대기 작업이 있는 상태에서 worker를 재시작하면 모델 호출이 재개될 수 있다. 구버전 worker 혼용이나 임의의 `stub` 전환으로 이를 우회하지 않는다.
