# 검증 데이터 관리 배포 — 2026-09-15

## 적용 결과

현재 작업 환경의 로컬 Docker API·분석 worker·모델 검증 worker·웹 UI를 재배포했다. 별도 운영서버를 배포한 기록은 아니다. 앱 버전은 **0.2.0**을 유지한다.

- UI: `http://127.0.0.1:18080`, API: `http://127.0.0.1:18000`.
- 데이터 관리, 버전별 문항·데이터셋 분석, 개별/일괄 참고 답안·메모, 답안 재평가 이력, Test API 키를 반영했다.
- 보고서 본문 폭을 넓히고 정탐 근거·오탐 근거·참고 내용을 구분했다.
- 기존 `moduagent`, Production/Test의 `gpt-5.4-mini`, Primary·Verifier·근거 정리 배정과 공통 지침 v2.12·사용자 편집 지침을 유지했다.
- **배포 직전 근거 정리는 운영·테스트 모두 켜져 있었다.** 이전 배포 기록의 꺼짐 기본값으로 되돌리지 않았다. 동시 처리·환경값·포트·볼륨·네트워크·명령도 유지했다.

사용법과 제한은 [검증 데이터 관리](Validation_Datasets_2026-09-15.md), 외부 연동은 [API 정의서](Production_API_v0.1.md)를 따른다. 운영에서 복사한 문항은 내부 vLLM 전용이며 현재 Test 프로필이 OpenAI라면 그 문항의 실행은 차단된다. 모델을 자동 교체하지 않는다.

### 배포 후 별도 활동

HTTP·브라우저 점검 이후 별도로 데이터셋 1개·테스트 25건이 접수돼 총 분석은 **1,214건**이 됐다. 배포 점검 스크립트는 이 작업을 접수하지 않았으며 새 기록을 삭제하거나 재실행하지 않았다. 25건은 실패 상태로, 17건은 `primary_agent_failed`, 8건은 `TargetNotAllowedError`다. 오류 코드만으로 호출 비용 소진이나 상세 원인을 단정하지 않는다.

감사 이력에는 모델 프로필의 비활성화·재활성화·수정이 각각 1회 기록됐다. 마지막 확인 시 `gpt-5.4-mini`는 `draft`, Test 지정은 해제돼 있고 기존 vLLM 프로필도 비활성 상태다. **새 실제 분석 전 프로필 전체 검증과 Production/Test 역할 지정을 다시 확인해야 한다.** 유료 검증이나 역할 복원은 자동으로 수행하지 않았다. 이 배포 이후 활동을 배포 직전 설정 보존 검사와 구분한다.

후속 대조에서 배포 전 분석·답안·Agent 실행·감사 등 기존 행은 모두 보존됐다. 프로필 1건의 상태·검증 시각·수정 시각·Test 지정 차이를 별도 확인했으며 다른 기존 행의 손실은 없다. 새 기록을 포함한 암호화 값 20,879개도 복호화 검사를 통과했다. 이후 사용자 변경이 계속될 수 있으므로 이 숫자는 최종 점검 시점의 스냅샷이다.

## DB와 백업

대기·처리 중 분석과 모델 검증이 모두 0건임을 확인했다. SQLite backup API로 만든 사본에 `0016_evidence_editor → 0017_validation_data`를 적용한 뒤, 실제 서비스 네 개를 정지하고 최종 백업을 다시 만들었다. 실제 업그레이드와 데이터 대조를 마친 뒤 같은 버전의 API·worker·UI를 기동했다.

- 기존 21개 테이블의 모든 기존 행·열을 해시로 대조했다. 마이그레이션 버전 자체를 제외하고 기존 값을 보존했다.
- 분석 **1,189건**, 암호화 값 **20,556개**의 복호화, SQLite 무결성·외래 키 검사를 통과했다. 원문·키·모델 본문은 검사 출력에 넣지 않았다.
- 테이블 4개와 필요한 컬럼을 추가하고 참고 답안의 보류 제한을 조정했다. 기존 서비스 키는 모두 Production으로 유지했다.
- 새 데이터셋·키·분석을 검증 목적으로 서비스 DB에 만들지 않았다. 재평가·답안 저장·LLM 호출도 실행하지 않았다.

사전 검사 도중 이전 배포의 근거 정리 꺼짐 가정을 제거하고 현재 값의 보존 여부를 비교하도록 바꿨다. 업그레이드 후에는 SQLite WAL 보조 파일 접근을 위해 검사 컨테이너 마운트를 조정했다. 실제 DB 연결은 읽기 전용이며, 오류 해결 후 데이터 대조를 통과했다. 앱 코드나 운영 설정을 이 문제 때문에 변경하지 않았다.

- 프런트엔드 **36개 테스트 파일**, Vite 빌드 통과. 기존 500KB 초과 번들 경고와 Starlette/AnyIO 사용 중단 예고는 남아 있다.
- 구현 단계 전체 백엔드 실행 및 후속 검증의 상세 수치는 [기능 검증 기록](Validation_Datasets_2026-09-15.md#검증-범위)에 있다. 이번 배포에서 전체 백엔드 테스트를 다시 통째로 실행한 것은 아니다.

실제 vLLM/Gemma4 품질·동시 처리량, 유료 OpenAI 실행, 장시간 대량 처리, 별도 운영서버 배포는 이번 검증 범위가 아니다.

## 재기동·복구·게시

현재 전용 Compose와 최종 백업의 정확한 위치·명령은 비공개 `.local-deploy/README.md` 맨 위에 보존한다. 기본 Compose 단독 실행은 기존 포트·모드·비밀값과 달라질 수 있으므로 사용하지 않는다. 이전 이미지와 백업을 보존했으며 볼륨 삭제나 `down -v`는 하지 않았다.

0017 기능을 사용한 DB는 구버전 worker와 혼용하지 않는다. downgrade·과거 백업 덮어쓰기는 배포 이후의 분석·감사 이력을 잃을 수 있으므로 자동 수행하지 않는다. 복구 시 현재 DB도 먼저 보존하고 배포 이후 데이터와 암호화 키·코드 호환성을 확인한다.

GitHub 게시 대상은 기존 `nagix999/waf-ai-console` main이다. 기존 이력을 잇는 별도 임시 복제본을 사용하며 작업 폴더의 비어 있는 읽기 전용 `.git`은 수정하지 않는다. 비밀 환경값, `.local-deploy`, DB·백업·원문, 의존성·빌드 산출물은 제외한다. 새 태그를 만들거나 기존 태그를 덮어쓰지 않는다.
