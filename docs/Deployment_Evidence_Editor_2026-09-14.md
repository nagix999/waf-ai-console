# 분석 화면·평가·근거 정리·동시 처리 배포 — 2026-09-14

## 적용 결과

기존 로컬 Docker 환경의 API·분석 worker·모델 검증 worker·웹 UI를 교체했다. 다른 운영서버에 접속하거나 그 서버를 배포한 기록은 아니다. 앱 버전은 기존 0.2.0을 유지한다.

- UI: `http://127.0.0.1:18080`, API: `http://127.0.0.1:18000`.
- `moduagent`, Production/Test의 기존 `gpt-5.4-mini` Primary와 동일 Verifier 배정을 유지했다. 공통 지침 v2.12와 관리자 편집 지침·프로필 검증 상태도 변경하지 않았다.
- 분석 목록·테스트 문항 요약은 말줄임하고 마우스·키보드 포커스로 전체 내용을 보여 준다.
- 평가 상세는 보류 참고 답안을 포함한 3×3 행렬과 보류 지표를 제공한다. 기존 이진 지표의 분모는 유지한다.
- Agent 설정에 근거 정리 프로필과 동시 처리 설정을 배포했다. **근거 정리는 두 용도 모두 꺼짐**, 동시 분석·서버별 호출 상한은 **각각 1**이다. 동시 처리 수 증가나 근거 정리 활성화는 이번에 수행하지 않았다.

상세 계약은 [화면·평가·근거 정리](Evidence_Editor_and_Three_Way_Evaluation_2026-09-14.md), [동시 처리](Concurrency_2026-09-14.md)를 따른다. 조회·보고서 다운로드에 LLM을 사용하지 않으며 이번 배포 검증에서도 분석이나 모델 검증 작업을 생성하지 않았다.

## DB와 설정 보존

진행·대기 중 작업 0건을 확인하고 SQLite backup API로 사전 사본을 만든 뒤 **사본에서 0014 → 0015 → 0016 업그레이드**를 검증했다. 실제 적용 전에는 네 서비스를 정지하고 최종 일관성 백업을 다시 만들었다.

- 기존 19개 테이블의 모든 기존 행·열을 해시로 대조했다. 마이그레이션 버전 자체를 제외하고 기존 값을 변경하지 않았다.
- 분석 1,189건, 암호화 값 20,556개의 복호화, SQLite 무결성·외래 키 검사를 통과했다. payload·키·원문을 검사 출력에 넣지 않았다.
- 실제 HTTP·브라우저 확인 후에도 기존 모든 행을 보존했다. 관리자 원문·Agent 이력·다운로드에 따른 감사 5건만 추가됐으며 분석·Agent 실행·모델 검증 작업은 늘지 않았다.
- `0015_concurrency`로 테이블 2개를 추가했다. `0016_evidence_editor`로 Agent 설정 4개 컬럼과 테스트의 암호화 설정 컬럼을 추가했다. 기존 테스트의 새 설정은 미기록 상태로 보존하며 근거 정리를 소급 실행하지 않는다.
- 포트·볼륨·네트워크·환경값·실행 명령을 유지했다. worker 두 역할의 종료 유예는 새 동시 처리 계약에 따라 120초다. 새 운영 패키지는 없다.
- 기존 개발용 비밀값은 변경하지 않았다. 앞선 배포 기록에서 안내한 공개 개발 기본값 문제는 남아 있으므로 이 로컬 설정을 운영에 복사하지 않는다. 기존 암호화 키는 데이터 이전 절차 없이 교체하지 않는다.

- 백엔드 1,951항목 전체 실행에서 1,950항목 통과, 문서 일치 검사 1항목은 테스트 컨테이너의 `/backend` 경로 누락으로 실패했다(643초). 코드 변경 없이 경로를 읽기 전용으로 연결한 뒤 해당 항목을 다시 실행해 통과했다. 최종적으로 모든 항목을 확인했으나 전체를 한 번 더 통째로 실행한 결과는 아니다. 외부 네트워크·운영 DB·실제 LLM 없이 검사했다.
- 중단 전 전체 테스트 세션은 최종 결과가 남지 않아 새 이미지의 Python으로 위 검증을 다시 수행했다. 최초 컨테이너 수집 단계의 예제 파일 경로 누락도 연결 설정으로 해결했다. 앱·테스트 코드를 이 배포 과정에서 수정한 것은 아니다. 기존 Starlette/AnyIO 사용 중단 예고 경고는 남아 있다.

실제 Gemma4/OpenAI의 근거 묶음 품질, 추가 지연·비용, GPU 처리량·적정 동시성은 이번에 검증하지 않았다. 다음 검증은 합의된 소량의 테스트에만 근거 정리를 켜고 원래 설명과 대표 설명·누락·지연을 비교하는 것이다. 운영 배정이나 동시 처리 상한을 자동으로 올리지 않는다.

## 재기동과 복구

현재 전용 Compose 명령과 비공개 백업 위치는 `.local-deploy/README.md`의 맨 위 기록에 있다. 기본 Compose를 단독 실행하면 기존 포트·모드·비밀값과 달라질 수 있으므로 사용하지 않는다. 데이터 볼륨을 삭제하거나 `down -v`를 실행하지 않았다.

새 설정과 v3 실행 스냅샷은 구버전 worker와 혼용하지 않는다. 기존 이미지와 업그레이드 전 DB 백업을 보존했다. 단순 downgrade나 과거 백업 덮어쓰기는 이후 분석·감사 이력을 잃을 수 있으므로 자동 수행하지 않는다. 복구 시에는 현재 DB도 먼저 보존하고 이후 생성 데이터·키·코드 호환성을 확인한다.

GitHub 게시에는 기존 main의 이력을 잇는 별도 임시 복제본을 사용한다. 작업 폴더의 비어 있는 읽기 전용 `.git`은 수정하지 않는다. 비공개 `.local-deploy`, 환경 파일, 키, DB/백업, 의존성·빌드 산출물은 게시에서 제외한다. 새 버전 태그 생성이나 기존 태그 덮어쓰기는 하지 않는다.
