# UI/UX 정리와 실패 재실행

이 문서는 1차 구현 기록이다. **후속 세부 화면 정리와 Docker 재배포까지 완료**했으며 현재 상태는 [세부 UI/UX 및 배포 기록](UI_UX_Detail_Deployment_2026-09-08.md)을 따른다. 아래 검증 수치와 배포 전 안내는 1차 작업 당시 기준이다. 실제 모델 재실행은 수행하지 않았다.

## 화면 구성

| 화면 | 변경 |
| --- | --- |
| 대시보드 | API 키 별칭·기간 선택, 동일 범위의 평가 지표·일별 그래프·최근 분석. 지표 미측정 날짜는 0으로 표시하지 않음 |
| 분석 결과 | 기본 검색과 핵심 지표 우선. 혼동행렬·추가 지표·출처별 통계는 평가 상세에서 확인. ID는 목록에서 숨김 |
| 테스트 결과 | 테스트명 목록은 분석 결과 → 테스트에만 유지. 실행 정보와 다른 테스트 비교는 별도 창. 비교 상세에서 돌아오면 선택·필터 복원 |
| 테스트 분석 | 단건 분석 / 배치 파일 분석. 중복 테스트 목록 제거. 정상 접수 후 해당 테스트로 이동; 일부 접수 거부 시 오류를 먼저 표시 |
| 분석 상세 | 판정·통신 정보 중심. 이벤트 ID·모델·단계별 시간은 이벤트·실행 정보. PDF·Excel 및 실패 재실행 제공 |
| 설정 | 모델·지침·스키마·내부 연결·키 목록 중심. 작성·적용·삭제 창 분리, 닫았다 열어도 편집 초안 유지 |
| Production API | 검색 목차에서 선택한 항목만 표시. 다운로드는 현재 서버 정의서 전체를 유지 |

고정 화면 안내에서 ‘합성’ 표현을 ‘테스트 데이터’, ‘예시 입력’, ‘기대 답안’으로 바꿨다. 기존 사용자가 저장한 이름·분석 원문·답안 출처 값은 일괄 치환하지 않는다. API enum `synthetic_expected`와 실제 테스트 데이터의 생성 방식도 바꾸지 않는다.

테스트명을 비우면 해당 접수의 자동 생성 요청 ID를 이름으로 사용한다. 같은 요청을 재전송하면 이름과 멱등성 키가 유지된다. 이 자동 이름은 서버의 `test_run.id`와 별개다. 단건 분석의 이벤트 ID도 비우면 자동 생성한다. 예시 입력은 placeholder로만 표시하며 실제 요청 본문에 자동으로 넣지 않는다. 비어 있는 선택 포트는 0이 아니라 생략한다. 모델 기본 설정값과 기존 저장된 스키마 정의는 예시 입력과 구분하여 유지한다.

긴 설명은 마우스·키보드 포커스·터치로 여는 `?` 도움말에 둔다. 삭제·외부 전송·호출 비용 등 행동 전 경고는 확인창 본문에 남긴다. 도움말은 Escape로 닫고 모달 안에서는 첫 Escape가 도움말만, 다음 Escape가 해당 모달만 닫는다. 접근성 설계 참고: [W3C hover/focus 지침](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html), [ARIA tooltip 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/).

## 실패 재실행

- 관리자 `GET /api/v1/analyses/{id}/retry-eligibility`로 조건을 확인하고, 비용 확인 후 `POST /api/v1/analyses/{id}/retry`로 접수한다.
- 요청은 `idempotency_key`, `cost_acknowledged: true`만 받는다. UI가 모델·프롬프트를 임의로 지정하지 않는다.
- 기존 실패 행을 덮어쓰지 않는다. 원본당 자식 한 개를 연결하며, 자식도 실패하면 그 자식에서 다시 실행할 수 있다.
- 당시 입력·공통 지침·스키마·실행 모드·모델 등록 설정·검증 정책을 고정한다. 원래 프로필의 검증·허용 대상·외부 전송 승인을 접수 및 실행에서 확인한다.
- 과거 설정이 누락되거나 모델 등록 설정이 달라졌으면 현재 모델로 대체하지 않고 차단한다. 모델 검증 150건의 개별 실패는 LLM 설정에서 새 검증을 진행하도록 안내한다.
- 참고 답안이 입력에 섞였거나 최초 입력 지문이 일치하지 않으면 차단한다. 답안은 재실행 모델 입력에도 추가하지 않는다.
- 기본 목록·대시보드·평가는 원본만 집계한다. 자식은 상세 링크로 확인하며 `include_retries=true`는 실행 이력 조회에만 사용한다. 재실행 성공이 과거 테스트의 실패·고정 답안·평가 지표를 변경하지 않는다.
- 같은 등록 설정을 보장하는 기능이지 서버 뒤의 모델 가중치나 응답의 비트 단위 재현을 보장하지 않는다.

## 키별 집계와 삭제

새 Production 최초 접수에 실제 인증한 서비스 키 ID를 기록한다. 같은 이벤트의 중복 접수는 최초 귀속을 변경하지 않는다. 과거 분석은 source_system만 보고 키를 추정하지 않는다.

`GET /api/v1/dashboard/summary?days=7&service_api_key_id=<UUID>`는 해당 키·기간의 집계, `evaluation_summary`, UTC 접수일별 `trend`를 반환한다. 최근 목록과 목록 이동에도 같은 키·기간을 전달한다. 답안 표본의 지표이며 운영 전체 정확도가 아니다. 삭제한 키·없는 키의 전용 대시보드는 404다. 귀속 미기록 및 삭제 키의 분석은 전체에서 보존된다.

`DELETE /api/v1/admin/service-api-keys/{id}`는 인증을 차단하고 키 목록·키별 대시보드에서 제거한다. 키 삭제 기록, 기존 분석과 감사 이력은 남긴다. 재요청은 204이며 기존 `/revoke` API는 호환용으로 유지한다. 이미 인증·접수한 작업을 취소하지는 않는다. 삭제한 키의 별칭도 기존 이름 유일성 정책에 따라 재사용할 수 없다.

## PDF·Excel

- 관리자 단건 GET: `/api/v1/analyses/{id}/report.pdf`, `/report.xlsx`.
- 같은 최종 보고서 모델로 판정·근거·추가 확인·최신 답안 비교·시간을 구성한다. 단건 Accuracy/F1을 만들어 넣지 않는다.
- HTTP 전체 원문, 추가 입력 필드, Agent 입출력, 지침·스키마 원문, 별도 디코딩 자료와 기술 부록은 제외한다. 근거 발췌에는 내부 정보가 포함될 수 있고 다운로드 파일은 평문이므로 보관·반출에 주의한다.
- 관리자 권한·접근 감사·`Cache-Control: no-store`. 미완료·모의 분석은 409, 한도 초과 413, 생성 실패 503. 부분 보고서는 만들지 않는다.
- 한도: 본문 512,000바이트, 1,000항목, PDF 80페이지, 최종 파일 10 MiB.
- ReportLab 5.0.1과 NanumGothic 일반/굵게 및 OFL 라이선스를 배포 패키지에 포함한다. 외부 문서 변환·글꼴 로딩은 없다. PDF 동적 텍스트는 마크업 해석을 막으며 Excel은 문자열 셀만 생성해 수식·매크로·외부 관계를 만들지 않는다.

## 배포 전 주의

신규 마이그레이션은 `0013_analysis_retries_keys`다. 키 삭제 메타데이터와 분석의 키 귀속·재실행 연결·멱등성·암호화 실행 설정을 추가한다. 기존 이벤트 중복 제약을 원본 행에 한정하는 부분 고유 인덱스로 바꾸므로 SQLite 분석 테이블 재구축이 필요하다.

배포 승인을 받은 뒤 일관된 DB·암호화 키 백업을 확보하고 API·worker·model-tester를 중지해야 한다. Alembic 전용 연결에서 마이그레이션하고 전후 행 수·FK 검사 후 같은 버전의 API·두 worker를 시작한다. 애플리케이션의 FK가 켜진 운영 연결에서 직접 재구축하지 않는다. 새 귀속·실행·삭제 이력이 생긴 뒤 이전 버전으로 downgrade하는 작업은 차단되며, 롤백에는 배포 전 백업 검토가 필요하다. 1차 작업에서는 운영 마이그레이션을 실행하지 않았고, 이후 사용자 승인에 따라 실제 배포 DB에 적용했다.

## 1차 검증과 당시 남은 확인

- 백엔드 전체 1,370개 통과(769개 + 601개 격리 실행). 이전 키 테이블이 없던 역사적 fixture 한 곳은 최신 FK가 역유입되지 않도록 수정하고 다시 통과했다. 실제 FK 정책은 유지했다.
- 프런트엔드 295개 통과, Vite 빌드 확인.
- 브라우저 회귀 22개 시나리오: 탐색 9, 공통 지침/비교 3, 주요 작업 4, 설정 6. API를 모의 응답으로 대체했고 390px·다크 모드·초안·중첩 모달·키보드·이중 클릭을 확인했다.
- PDF 한글 텍스트·글꼴 임베딩, XLSX 구조·문자열 왕복·수식 차단, wheel의 글꼴·라이선스·의존성 포함 확인.
- 실제 화면 최초 검토에는 기존 서비스의 읽기 기능을 사용했다. 구현 검증 중 실제 분석 재실행·키 삭제·LLM 호출은 하지 않았다.
- 미검증: 운영 DB 마이그레이션/재배포, 실제 모델 호출·비용·품질, 다중 PDF 생성 부하, 실제 Microsoft Excel/각 PDF 뷰어 호환성. 화면 조작 회귀는 Chromium 기준이다.
