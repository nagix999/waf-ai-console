## 다음 작업 우선순위

1. **새 설명의 실제 모델 품질 확인.** 기존 가상 데이터에서 파싱 난이도·Hard·Medium 각 10건, 총 30건을 고정해 이전 결과와 비교한다. 정탐/오탐/보류가 가능한 사례를 포함하고, 답안 자체도 먼저 점검한다. 판정 정확도뿐 아니라 정탐·오탐 근거 분류, 구체적인 보류 이유, 실제로 필요한 추가 확인, 출력 실패, 토큰·시간을 본다. 보류가 줄어도 과탐·미탐·잘못된 확정이 늘면 개선으로 보지 않는다. `gpt-5.4-mini` 유료 실행은 별도 승인 후 진행하고 Gemma4는 GPU 환경에서 같은 사례로 확인한다. 실제 회사 로그는 외부로 보내지 않는다.
2. **근거에서 원문으로 바로 이동.** 근거를 누르면 해당 로그 위치와 앞뒤 내용을 표시한다. 위치는 서버가 확인하고, 같은 문자열이 여러 곳에 있어도 엉뚱한 위치를 가리키지 않게 한다. 원문과 변환 결과를 구분하고 기존 원문 권한·감사를 유지한다.
3. **AI가 받은 자료의 범위 표시.** 요청 원문·이벤트 정보·파싱 참고정보 각각의 포함/생략 범위를 당시 실행 기록으로 표시한다. 수집 누락, 모델 입력 길이 제한에 따른 생략, 파서의 부분 인식을 구별한다. 화면에서 나중에 다시 파싱한 값을 당시 입력이라고 표시하지 않는다.
4. **추가 확인을 분석가 작업으로 연결.** 필요한 확인에만 상태와 확인 결과를 남기고 최종 검토와 연결한다. AI의 원래 판정·설명은 보존하고 분석가의 확인을 모델이 검증한 사실로 취급하지 않는다. 저장 구조·권한 변경은 설계 합의 후 진행한다.
5. **검증 결과에 따라 Verifier 실행 조건 조정.** 어떤 사례를 바로잡았고 어떤 사례에서 보류·비용만 늘었는지 분리해 측정한다. 독립 분석과 기존 결합 정책을 먼저 유지하고, 근거가 확보된 조건부터 작게 조정한다. 오케스트레이션 LLM 추가는 계속 뒤로 둔다.
