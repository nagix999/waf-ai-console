# 원문 인용 교정 v2

2026-09-10. 합의한 1차 범위인 출처 연결·인용 교정·출력 오류 정보 개선이다. 코드와 오프라인 회귀 테스트 범위이며 Docker 배포, 활성 지침 변경, 실제 LLM 호출은 포함하지 않는다. 기존 [Agent 설정 계약](Agent_Settings_and_Grounding_v0.2.0.md)의 근거 교정 절에는 이 문서가 우선한다.

후속 사용자 요청으로 로컬 Docker에 반영하고 [동일 100건 실모델 재평가](evaluations/Citation_Repair_V2_GPT54Mini_100_2026-09-10.md)를 완료했다. 참고 답안 일치는 80→63건, 보류는 23→36건으로 악화됐다. 인터넷 단절로 실패한 59건만 기존 설정의 연결 재실행으로 복구했으며, 기존 이력·답안·모델·공통 지침은 유지했다. 인용 보존 동작은 확인했지만 보류 감소 목표는 달성하지 못했다. 아래 내용은 원래 구현·오프라인 검증 기록이며 후속 평가 중 판정 코드를 추가 변경하지 않았다.

## 변경 이유

[100건 평가](evaluations/Parser_Stress_GPT54Mini_100_2026-09-10.md)에서 줄바꿈을 바꾼 인용, 도구의 original을 이벤트 필드처럼 인용하는 오류, 전체 결과 재작성 중 유효 근거 소실을 확인했다. 이 실험의 참고 답안은 고정된 가상 기대값이며 운영 정확도의 증명이 아니다. 기존 데이터·답안·평가 결과는 변경하지 않았다.

## 1. 디코딩 힌트와 원문 연결

`decoded_payload_hints.raw_source_field=payload`, `source_offsets=original_payload_characters_end_exclusive`를 추가한다. 각 항목의 기존 `start/end`는 수신 원문의 문자 위치이며 end는 미포함이다. 문자 위치는 Python Unicode 문자 기준이고 바이트/UTF-16 인덱스가 아니다. 원문, 디코딩 값, 변환 단계, 경고를 수정하지 않는다.

모델이 `decoded_payload_hints.items.0.original` 또는 `items[0].original`을 인용하면 서버가 다음을 모두 검사한 뒤 최종 근거 필드만 `payload`로 연결한다.

- 해당 힌트가 실제 제출된 user 입력에 포함됨.
- `raw_payload[start:end] == original`이며 발췌문이 그 original 안에 정확히 존재함.
- 그 위치 전체가 모델에 제출된 하나의 연속 원문 구간 안에 있음.

같은 문자열이 다른 위치에 남아 있다는 이유로 생략된 위치를 인정하지 않는다. `decoded`, 다른 항목의 문자열, 다른 이벤트 필드, 존재하지 않는 경로는 자동 연결하지 않는다. URL 디코딩, 줄바꿈 정규화, 유사 문자열 비교로 인용을 통과시키지 않는다.

연결은 모델을 추가 호출하지 않는다. 모델의 최초 출력과 필드 연결 내역·원문 위치는 암호화된 실행 이력에 보존하고, 평문 메타데이터에는 연결 건수만 기록한다. 일반 결과에는 연결된 원문 필드와 발췌문을 사용하며 전체 디코딩 내용을 복사하지 않는다.

## 2. 제출된 입력 범위 확인

입력 구성기가 선정한 원문 구간을 두 역할의 검증기에 그대로 전달한다. 원문에 있더라도 모델 입력에서 빠진 발췌문은 `excerpt_not_submitted`로 제외한다. 서로 다른 구간을 이어 붙이거나 다른 HTTP 필드에 남아 있는 중복 문자열로 검증하지 않는다.

이벤트 메타데이터도 원본 필드와 제출된 같은 필드 양쪽에 발췌문이 있어야 한다. 길이 제한으로 붙인 생략 기호는 원문으로 인정하지 않는다. 선정 구간은 `agent_input` 단계의 암호화된 출력에 함께 기록한다. 기존 저장 원문과 과거 이력은 수정하지 않는다.

## 3. 전체 재판정 대신 인용만 교정

최초 Primary·Verifier는 기존에 고정한 모델과 공통 판정 지침, `WAFAnalysisOutput` 계약을 그대로 사용한다. 근거 출처 연결 후에도 잘못된 인용이 있으면 해당 역할에만 최대 한 번 교정을 요청한다.

교정 출력은 별도 내부 계약 `EvidenceCorrectionOutput`을 사용한다.

```json
{
  "corrections": [
    {"index": 0, "field": "payload", "excerpt": "짧은 연속 원문"}
  ],
  "requires_reanalysis": false
}
```

교정 요청에는 잘못된 근거의 원래 인덱스·고정 오류 코드·필드·발췌문·해석을 비신뢰 user JSON으로 전달한다. 모델 출력이나 입력 원문을 system 지침에 보간하지 않는다. 수정 대상 전체의 해석을 무조건 복사해 입력을 늘리지 않고, 피드백 객체 4,096자 이내에서 항목 단위로 선택한다. 해석이나 인용을 중간에서 잘라 새 근거를 만들지 않는다. 단 하나의 항목도 담을 수 없으면 불필요한 호출을 생략하고 보류한다.

- 서버는 요청한 인덱스의 `field/excerpt`만 수정한다. 유효했던 근거와 기존 `interpretation_ko`, 요약·심각도·신뢰도·튜닝 제안은 모델이 덮어쓸 수 없다.
- 교정을 요청하지 않은 인덱스·중복 인덱스·범위 밖 인덱스와 임의 출력 필드를 허용하지 않는다.
- 인용은 기존 해석을 그대로 뒷받침해야 한다. 의미를 바꾸거나 재판단이 필요하면 `requires_reanalysis=true`로 표시하도록 요구한다. 이 플래그가 추가 모델 호출이나 자동 재판정을 시작하지는 않는다.
- 교정 뒤에도 미해결 인용이 남거나 재판단을 요청하면 보류·UNKNOWN으로 처리하고 튜닝을 비활성화한다. 검증을 통과한 기존/교정 근거는 보류 결과에도 보존한다.
- 교정 후 시그니처·이벤트명·IP 등 이벤트 메타데이터만 남으면 확정 판정을 복구하지 않는다. 원문 또는 실제 추가 필드의 유효 인용이 있어야 한다. 추가 필드에 무엇이 들어 있는지의 의미 검증은 이 규칙으로 보장하지 않는다.
- 교정 호출 자체가 실패하면 기존처럼 Primary는 분석 실패, 필요한 Verifier는 최종 보류다. 실패한 교정 대신 이전 확정 판정을 조용히 채택하지 않는다.

v1은 일부 인용이 탈락해도 하나만 남으면 확정할 수 있었다. **v2의 교정 경로는 미해결 근거를 남겨 둔 채 확정하지 않도록 더 보수적이다.** 출처 연결로 불필요한 교정은 줄일 수 있지만 이 안전 조건 때문에 일부 문항의 보류는 늘 수 있다. 실제 보류율·오판·비용 효과는 실모델 비교 전에는 알 수 없다.

교정 전용 고정 지침과 계약은 `evidence-repair-v2`로 기록한다. 기존 활성 판정 지침 v2.6/policy-N을 바꾸거나 Test/Production을 분리하지 않는다. 교정은 전체 판정과 다른 작업이므로 전체 판정 출력을 요구하는 지침을 붙여 계약을 충돌시키지 않는다. 같은 교정 지침을 두 용도와 두 역할에 공통 적용한다. 이미 저장한 판정 지침·모델 스냅샷을 덮어쓰지 않으며, 이후 실행에는 당시 배포된 교정 코드 버전이 사용된다.

## 4. 출력 계약 오류를 구체적으로 전달

판정 계약의 `ValueError`를 고정 `PydanticCustomError`로 구분한다. 평문 이력과 형식 교정 지시에 원문 값이나 임의 예외 메시지를 넣지 않고 아래 코드·위치·고정 안내만 전달한다.

| 코드 | 교정할 조건 |
| --- | --- |
| `decisive_verdict_requires_evidence` | 확정 판정에는 원문 근거가 필요함 |
| `true_positive_requires_threat_severity` | 정탐은 CRITICAL/HIGH/MEDIUM/LOW |
| `false_positive_requires_none_severity` | 오탐은 NONE |
| `inconclusive_requires_unknown_severity` | 보류는 UNKNOWN |
| `recommended_tuning_requires_scope_proposal_risk_and_validation` | 튜닝 제안의 범위·내용·위험·검증이 모두 필요함 |
| `duplicate_correction_index` | 인용 교정에서 같은 인덱스는 한 번만 사용 |

일반 검증 오류 유형도 Pydantic의 고정 유형과 위 코드만 허용한다. 영문·숫자만 들어 있다는 이유로 임의 오류 문자열을 로그나 지시에 전달하지 않는다. 최상위 실패 분류 `output_validation_failed`와 기존 API 계약은 유지한다.

## 5. 호출·이력·호환성

한 역할은 최초 판정 + 기존 형식 교정 최대 1회 + 인용 교정 최대 1회다. 인용 교정 안에서 형식 교정을 다시 시작하지 않는다. 기존 전송 재시도와 요청 직전 자격·egress 검사는 유지한다. 다른 모델로 장애 우회하거나 Verifier에 Primary 결과를 전달하지 않는다.

`grounding_history`는 최초 구조화 출력, 출처 연결 결과, 교정 응답과 적용 결과, 교정 입력·지침을 기존 암호화 저장에 남긴다. raw provider body·private reasoning은 저장하지 않는다. metadata의 `evidence_grounding_retry`에는 버전·모드·시도별 사용량·오류 코드·복구 여부·재검토 여부·출처 연결 건수를 기록한다. 교정 복구는 인용 검사를 통과했고 재검토 요청이 없다는 뜻이며 정답률을 뜻하지 않는다.

결과의 `diagnostics.version`은 `evidence-repair-v2`다. 관리자 집계는 기존 v1과 v2의 완료 분석을 함께 지원한다. 실패·미기록 자료를 측정된 완료 자료로 간주하지 않고 과거 결과를 재작성하지 않는다. 교정/형식 재시도 사용량은 기존 방식으로 합산하며 마지막 시도의 usage를 중복 합산하지 않는다.

새 DB 마이그레이션·운영 의존성은 없다. 결과 버전은 `waf-analysis-v2`를 유지하고 외부 접수 API는 변경하지 않는다. 파서 확장, 디코딩 의미 판정 지침, Verifier 실행 조건 변경, 조사 도구는 후속 범위다.

## 검증과 남은 확인

오프라인 회귀는 CR 인용, 유효 근거 보존, 잘못된 원문 출처·디코딩 값·누락 위치 거부, 교정 범위 제한, 이벤트 메타데이터만 남은 경우의 보류, 안전한 오류 정보, 두 provider의 모의 HTTP 요청·출력 검증, 역할별 독립성·암호화 이력과 기존 집계를 대상으로 한다. 원래 100건의 참고 답안을 수정하지 않는다.

원문 인용의 정확한 출처와 문자열 일치는 검사하지만 **그 인용이 해석을 의미적으로 뒷받침하는지는 증명하지 못한다.** 악성/정상 의미 판단, Gemma의 새 교정 계약 준수, 실제 토큰 예산·처리시간·보류율·오판율은 실모델 재평가가 필요하다. 이번 작업에서는 운영 DB·배포 설정·활성 프롬프트·LLM 프로필을 변경하지 않는다.

### 실행 결과

- 현재 백엔드 테스트 수집 범위는 **1,647건 / 63개 파일**이다. 실제 LLM 대신 모의 응답을 사용했다.
- 전체 파일을 중복 없이 세 묶음으로 검증했다. 첫째 504건 통과, 둘째 694건 통과, 셋째 445건 통과·1건 실패였다. 실패는 기존 시간 측정 테스트의 모의 함수가 새 `sources` 키워드 인자를 받지 못한 것이며, 인자를 전달하도록 수정했다.
- 수정 후 시간 측정·신규 인용 교정·역할 설정·디코딩 통합·worker 관련 **97건 재통과**. 여기에는 앞선 실패 항목과 전체 분할 실행 이후 추가한 회귀 3건이 포함된다. 최종 범위에서 남은 확인된 실패는 없다.
- 순수 인용 교정·근거 검증·형식 교정·입력 예산·판정 정책 **162건도 재통과**했다. 위 수치와 중복되므로 합산하지 않는다.
- 파싱 난이도 46번의 긴 원문을 실제로 잘라 구성한 입력에서도 말미 JNDI의 원문 위치 연결이 유지됨을 확인했다. 이 테스트는 모의 판정으로 출처 연결을 검사한 것이며 실모델 정확도 재평가가 아니다.
- Starlette/AnyIO의 기존 폐기 예정 API 경고가 남아 있다. 한 병렬 실행에서는 pytest 캐시 쓰기 권한 경고가 발생해 후속 검증은 캐시 쓰기 없이 실행했다. 소스·운영 디렉터리 권한은 바꾸지 않았다.
- 샌드박스 안에서 FastAPI TestClient의 스레드 대기가 멈추는 현상을 확인했고, 승인된 샌드박스 밖 실행에서 메모리/임시 DB 기반 통합 테스트를 수행했다. 실제 서비스·LLM에는 연결하지 않았다.

대표 재검증 명령:

```bash
cd backend
.venv/bin/python -m pytest -p no:cacheprovider -o addopts='' -q \
  tests/test_worker_timing.py tests/test_citation_correction.py \
  tests/test_agent_configuration.py tests/test_decoder_integration.py \
  tests/test_moduagent_worker.py
```
