# 요청 문맥 판단 v1 · GPT-5.4-mini 150건 평가

2026-09-10. 로컬 Docker 반영과 실제 모델 평가를 완료했다. 파싱 난이도 50건, 기존 Hard 50건에 사용자 요청의 **Medium 50건**을 추가했다. 세 묶음 모두 실행 실패 없이 완료했으며 참고 답안 일치는 **119/150건(79.33%)**이다.

**정상 요청 과탐은 줄었지만 필요한 보류를 확정하는 오류가 늘었다. 이번 결과만으로 운영 확대를 권고하지 않는다.** 아래 오류는 고정된 참고 답안 기준이며 실제 운영 정답 검증과는 다르다. 로컬 배포 상태는 유지했고, 추가 모델 호출·정책 변경·운영서버 배포는 자동으로 진행하지 않았다.

## 적용 범위

공통 지침 `waf-system-v2.8` / `waf-judgment-v2.8`은 언어 문법·입력 위치·주변 값을 함께 판단하도록 보강했다. 인용문·코드 예시·설정 값과 실행 구문을 구분하고, 디코딩 이후에도 원래 값을 감싼 구조를 함께 해석하도록 했다. JSON이나 경로명 하나만으로 정상으로 판단하지 않는 반대 조건도 넣었다.

기본 Primary 지침은 3,191→3,692자다. 긴 문항별 예시 없이 501자를 추가했으며, 이전보다 짧아진 것은 아니다. Production/Test에 동일하게 적용한다. 기존 후보 선택·파서·디코더·모델 지정·편집 지침 policy-2·Verifier 실행 및 결합 정책은 유지했다. 이전 실행은 당시 지침을 유지한다. 새 DB 변경·운영 패키지는 없다. 설계와 공식 문서 참고 내용은 [구현 기록](../Context_Judgment_v1_2026-09-10.md)에 정리했다.

## 평가 조건

- 실제 연결된 `gpt-5.4-mini`, context 32,768 / 최대 출력 3,072 / timeout 120초. Primary와 독립 Verifier는 같은 프로필을 사용한다.
- `samples/waf-parser-stress-v1/parser_stress_50.json`, `samples/waf-dummy-v1/hard_50.json`, `samples/waf-dummy-v1/medium_50.json`을 수정 없이 사용했다. 각 50건의 참고 답안은 공격 20 / 정상 20 / 보류 10건이다.
- 참고 답안·난이도·문항 분류는 모델 입력에서 제외했다. 필드 정의는 이력에만 기록한다. 실제 사내 로그는 사용하지 않았다.
- 같은 100건은 직전 v2.7 결과와 비교했다. Medium은 대응하는 직전 평가가 없으므로 개선율을 제시하지 않는다. 개발에 사용한 문항을 재사용한 단일 실행이며 독립 평가셋이 아니다.
- 이번 배포 전 프로필의 연결 검증 동시성이 3→10으로 바뀌고 재검증된 상태였다. 현재 설정을 보존했다. 모델·대상·생성 예산과 일반 분석 worker의 동시성은 바뀌지 않았지만 프로필 지문이 달라져 비교 API에도 설정 차이 경고가 기록된다. 모든 조건이 완전히 같은 실험 또는 지침 변경의 인과 효과로 표시하지 않는다.

세 테스트는 웹 UI의 테스트별 결과에서 확인할 수 있다: `파싱 난이도 50건 · 문맥 판단 v1 평가`, `기존 Hard 50건 · 문맥 판단 v1 평가`, `Medium 50건 · 문맥 판단 v1 평가` (모두 gpt-5.4-mini / 2026-09-10). 실행 ID·파일 해시·문항별 판정은 [상세 JSON](Context_Judgment_GPT54Mini_150_2026-09-10.json)에 있다.

## Medium에서 추가로 확인한 문제

정상 문항 중 `파일명 중간의 점 두 개`는 공격으로, `SVG 파일명 속 이벤트 단어`는 보류로 판정됐다. `SQL 시그니처와 불일치하는 인코딩 SVG 구문` 공격 문항도 Primary 공격 / Verifier 정상으로 갈려 보류됐다.

보류가 참고 답안인 10건은 모두 확정됐다(공격 9 / 정상 1). 소유권·신뢰 경계·대상 승인 범위·설정 기능·실행 정책처럼 판정을 가르는 조건이 주어지지 않은 문항과 잘린 JSON 본문 문항이 포함된다. 다만 이런 답안의 적절성도 별도로 검토해야 한다. 서버 동작을 모른다는 이유만으로 모든 요청을 보류하거나, 공격 성공 증명을 요구하는 식으로 일반화해서는 안 된다. 이번에는 답안을 사후 수정하지 않았다.

## Verifier·원문 검증·처리량

150건 중 Verifier는 126건에서 실행됐다. Primary 기준 답안 일치 123건이 최종 119건으로 바뀌었다(2건 개선 / 6건 악화). 이는 이번 문항과 현재 결합 정책에서 관측한 변화이지, Verifier를 끈 별도 실험이나 보편적인 효용 부정은 아니다. Verifier 실행·결합 정책을 자동 변경하지 않았다.

## 코드·배포 검증과 보존

백엔드 전체 **1,691항목 통과**, 관련 119항목 통과, Medium을 추가한 150문항 원문 후보 검사 1항목 재확인을 완료했다. 기존 Starlette/AnyIO 폐기 예정 경고 1건이 있으며 새 실패는 없다. 오프라인 테스트는 모의 공급자 응답과 가상 데이터로 계약·경계·이전 버전 호환성을 검사하며 모델 정확도 평가는 위 실제 실행과 구분한다.

일관된 DB 백업 후 로컬 API·두 worker만 재배포했다. 배포 소스 99개와 실행 이미지의 일치, 의존성 불변, 서비스 상태, PDF/Excel 생성, 프록시 연결을 확인했다. 기존 분석 739건·모델 설정·키·편집 지침·과거 암호문을 보존하고 이번 분석 150건 및 관련 평가·감사 이력을 추가했다. 총 분석은 889건이다. DB 무결성·외래 키 검사와 기존 행 비교가 통과했다. 웹 UI 이미지·운영서버·다른 프로젝트는 변경하지 않았다.

## 다음 범위 제안 — 아직 미구현

우선 본문 누락·잘림·서로 다른 길이·상충 값처럼 **입력에서 확인 가능한 완전성 문제를 구조화**하고, 해당 문제가 실제 판정을 가르는 경우에만 확정 제한과 추가 확인 항목에 연결한다. 이어 원문에 있는 구문을 올바르게 해석했는지 확인하는 제한된 의미 검증과 Verifier의 변경 기여를 별도 평가하는 것이 필요하다. 특정 문항 ID·경로명 허용 목록으로 정답을 맞추지 않는다.

이번 평가에서 Gemma4·실제 운영 로그·사용하지 않은 독립 문항은 검증하지 않았다. 보류 답안의 독립 검토와 새로운 평가셋이 필요하며, 추가 유료 실행은 이번 150건 범위에 포함해 자동 진행하지 않는다.
