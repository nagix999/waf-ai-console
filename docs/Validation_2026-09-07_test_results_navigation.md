# 분석 결과의 테스트 실행 목록 연결 검증

기준일: 2026-09-07. 범위는 프런트엔드 코드 수정과 합성 검증이다. 사용자 요청에 따라 실행 중인 Docker 서비스는 재배포하지 않는다.

## 변경 범위

- 분석 결과의 **테스트** 탭은 이름 있는 테스트 실행 목록을 기본으로 표시한다.
- 테스트명을 선택하면 기존 실행 상세의 평가 지표·Confusion Matrix와 문항별 분석 결과를 함께 표시한다.
- 목록의 이름 검색 초안·적용값·페이지와 실행 상세의 평가 범위·문항 필터·페이지를 부모 상태에 보존한다. 문항 상세에서 돌아올 때 해당 실행을 유지하고 다른 실행 선택 시 문항 필터를 초기화한다.
- 테스트 입력·파일 업로드의 실행 결과와 설정의 이름 있는 150건 검증 결과는 분석 결과의 동일 실행 상세로 연결한다.
- 전체·프로덕션은 기존 단건 분석 목록·검색·평가 지표를 유지한다. 테스트 목록·문항 검색 상태와 운영 분석 검색 상태를 분리한다.
- 테스트명 없이 저장된 이전 분석은 **테스트 문항 전체 보기**에서 이름 있는 실행의 문항과 함께 조회한다. 실행 ID가 없는 이전 검증 링크는 기존 source 제한 검색을 유지한다.
- 검색 0건·이름 있는 실행 없음·빈 페이지·조회 실패를 구분한다. 이전 요청의 늦은 응답을 차단하고 401은 로그인 상태 처리로 연결한다.

- Production 빌드 성공, 69개 모듈.
- 신규 결과 화면 검증 6개와 테스트 실행 상태·조회·탐색 관련 보강 8개를 포함한다.
- 초기 신규 테스트의 CSS 클래스 전체 문자열 단언 2건은 실제 복수 클래스 마크업에 맞게 수정했다. 제품 동작을 완화하거나 실패 테스트를 제외하지 않고 전체 재실행했다.

## 실제 브라우저의 합성 검증

별도 임시 프로필의 Chrome에서 실제 App을 실행하고 모든 API를 합성 응답으로 대체했다. 실제 서비스/API에는 접속하지 않았으며 쓰기 요청과 외부 대상 요청은 하네스가 거부한다.

- 분석 결과 → 테스트 진입 시 개별 분석 API 대신 테스트 목록 API를 조회한다.
- 테스트명 → 해당 실행의 지표·Confusion Matrix·문항 목록 → 문항 상세 → 실행 결과 왕복을 확인했다.
- 난이도 `hard`, 유형 `sqli`, FN 셀과 문항 offset 25가 상세 왕복 후 보존됐다.
- 적용된 테스트명 검색, 아직 적용하지 않은 검색 초안, 목록 offset 10이 목록 왕복 후 보존됐다.
- 기존 자료를 포함하는 테스트 문항 목록과 '분석 구분: 테스트' 조건 해제 → 전체 이동을 확인했다.
- Production의 단건 목록·검색·평가 지표, 대시보드에서 넘어온 기간·판정 필터를 유지하고 테스트 source 조건이 섞이지 않음을 확인했다.
- 1280px·375px에서 테스트 목록·실행 상세·Production 화면의 문서 가로 넘침이 없었다. 목록과 모바일 실행 상세 스크린샷을 시각적으로도 확인했다.
- 런타임 예외·미등록 API 요청·쓰기 요청은 모두 0건이었다.

이 검증은 합성 응답을 사용한 UI 동작 검증이며 배포 서비스나 실제 모델 검증이 아니다. 임시 하네스와 스크린샷은 `/tmp/waf-test-navigation-smoke-aR5HW2/`에 있으며 영구 시험 데이터로 취급하지 않는다.

## 적용하지 않은 변경과 한계

- Backend/API·DB 스키마·저장 데이터·모델/프롬프트·키·실행 중인 서비스 설정은 변경하지 않았다.
- 과거 분석을 임의로 묶거나 테스트명을 생성하지 않았다. 이름 있는 실행이 없으면 실행 목록이 비어 있을 수 있으며 기존 개별 결과로 이동할 수 있다.
- 테스트 상세는 접수 당시 고정 답안, 개별 분석 검색은 최신 답안 기준을 유지한다. 두 지표를 같은 모집단으로 오인하지 않도록 안내한다.
- 실제 LLM 호출·유료 검증·운영 데이터 재분석은 수행하지 않았다.
- Docker 재배포를 하지 않았으므로 현재 실행 중인 웹 UI에는 이 코드가 아직 반영되지 않았다.
