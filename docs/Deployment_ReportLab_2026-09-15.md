# ReportLab PDF 배포 기록

2026-09-15, 현재 작업 환경의 로컬 Docker 서비스를 재배포했다. 별도 운영서버를 원격 배포한 기록은 아니다. 앱 버전은 0.2.0을 유지한다.

## 적용

- 분석 PDF를 ReportLab 5.0.1로 전환하고 Chromium·Playwright 패키지, 브라우저 설치 단계와 전용 렌더러/번들을 제거했다.
- 웹 보고서 내용 생성기·파서를 로컬 Node 프로세스로 재사용한다. Node 실행 파일과 변환 번들은 이미지에 포함하며 별도 Node 서버·외부 다운로드는 없다.
- 웹/PDF 모두 정탐·오탐·참고의 제목 칸과 로그 발췌만 배경색을 적용한다. 본문·순서를 보존하며 PDF에는 페이지별 그룹 제목 반복·페이지 번호·목차를 제공한다.
- 기존 관리자 권한·접근 감사·부록·디코딩·테마 선택·크기/시간 제한을 유지한다. Excel과 운영 API 정의서 PDF는 변경하지 않았다.

자세한 구성, 제한과 폐쇄망 이미지 반입은 [PDF 안내](ReportLab_PDF_2026-09-15.md)를 따른다. 웹과 같은 문구를 사용하지만 웹 CSS를 실행하는 방식은 아니므로 줄바꿈·표 폭은 다를 수 있다.

## 데이터와 설정

대기/처리 중 분석 및 모델 검증이 0건임을 확인했다. 네 서비스를 중지한 뒤 SQLite backup API로 600 권한의 일관된 백업을 만들었다.

- DB: 기존 `0018_dataset_source_deleted` 유지. 새 마이그레이션 없음.
- 분석 1,214건, 25개 테이블, 암호화 값 20,884개 보존 및 복호화·DB 무결성·외래 키 검사 통과.
- `moduagent`, 현재 모델/역할·지침·동시 처리·API Key·암호화 키·명령·네트워크·볼륨·포트 유지.
- 실제 분석/키 삭제, 설정 복원, 신규 분석 접수, 실제 LLM 호출 없음.

UI는 `http://127.0.0.1:18080`, API는 `http://127.0.0.1:18000`이다.

## 검증

- 최종 API 이미지의 PDF·내보내기 관련 68개 검사 통과. 임시 DB·가상 데이터만 사용하고 네트워크를 차단했다.
- 전체 백엔드 2,113개 중 2,112개 통과. 문서 원본 비교 1건은 테스트 컨테이너의 `/backend/app/data/production_api.md` 마운트 누락으로 실패했다. 경로를 연결해 별도 재실행하고 통과했으며 제품 코드 수정은 필요하지 않았다. 최종 미해결 실패는 없다.
- 프런트엔드 41개 테스트 파일 및 Docker 빌드 통과.
- 브라우저 없는 이미지에서 가상 보고서 3종 × 밝은/어두운 테마 = 6개 PDF 생성. 총 26페이지에서 81/108/148개 본문 항목의 보존과 페이지 경계를 각각 확인했다. 본문 비교에서는 레이아웃 공백·줄바꿈·반복 머리말/꼬리말을 제외했다. 주요 근거 페이지도 이미지로 확인했다.
- 추가로 디코딩·부록을 함께 포함한 실제 PDF를 생성해 해당 항목 보존 확인.
- 개발용 UI 검사 16개 조건 통과: 세 보고서 × 두 테마 × PC/모바일 12개, 기존 보고서·다운로드·키 삭제 모달 가상 시나리오 4개. 실제 API 요청/삭제/LLM 호출 없음.
- 배포 후 HTTP 36개 통과: 로그인·권한·Origin 거부, 분석/테스트 평가, 키 삭제 미리보기, 밝은/어두운 PDF·부록·디코딩·잘못된 옵션 거부, Excel, 운영 API 정의서 PDF, OpenAPI, 웹 산출물 일치.
- API healthy, 네 서비스 실행·재시작 0. API와 두 워커의 128개 파일이 현재 소스와 일치한다. 실행 이미지에 Playwright·Chromium 실행 파일·브라우저 경로·구 PDF 번들이 없음을 확인했다.

새 API 이미지 크기는 409,378,748 bytes이며 이전 이미지의 1,496,709,001 bytes에서 감소했다. ReportLab 렌더러의 동시 부하·장시간 운영·실제 Gemma/OpenAI 품질 재평가는 이번 범위가 아니다. 기존 Vite 청크 크기 경고와 Starlette 사용 중단 예고는 남아 있다.

## 배포와 복구 자료

현재 비공개 구성은 `.local-deploy/reportlab-20260915-FvOvTO/compose.json`이다. 이 파일과 백업은 Git에 포함하지 않는다. 기존 프로젝트 이름과 설정을 유지한 재기동 명령:

```bash
docker compose -p waf-ai-console \
  -f .local-deploy/reportlab-20260915-FvOvTO/compose.json \
  up -d --no-build --pull never --wait
```

- API/worker/model-tester: `waf-ai-console-api:reportlab-20260915-FvOvTO`, 이미지 ID `7456ca36dbdf7842f0bf03324d316d74723ce2a796891cdfed6a19a7f70879cd`.
- Frontend: `waf-ai-console-frontend:reportlab-20260915-FvOvTO`, 이미지 ID `5d8b89480f8c243e17588d42a400089e8ff2be78eb030068b815414e6ca40889`.

같은 비공개 폴더의 `backup.db`와 이전 Compose/이미지를 보존한다. 사용하지 않는 로컬 브라우저 PDF 번들은 `obsolete-report-ui/`로 옮겼다. 복구용 구 이미지와 개발용 외부 UI 테스트 브라우저는 배포 서비스에서 사용하지 않으며 임의로 삭제하지 않았다. 새 데이터가 생긴 뒤 DB를 덮어쓰거나 `down -v`를 실행하지 않는다.
