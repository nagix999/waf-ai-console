# 분석 요약·3×3 평가·근거 정리

아래는 구현 당시 코드·오프라인 검증 기록이다. 후속 [로컬 배포·검증](Deployment_Evidence_Editor_2026-09-14.md)에서 DB 0016과 UI를 반영했다. 근거 정리 활성화와 실제 LLM 호출은 하지 않았다.

## 화면

- 전체 분석 목록과 테스트 문항 목록의 분석 요약을 최대 90자로 표시하고, 긴 경우 `...`을 붙인다.
- 문장 자체에 마우스를 올리거나 키보드 포커스/터치하면 전체 내용이 나타난다. `?` 아이콘을 추가하지 않는다. Escape로 닫을 수 있고 긴 내용은 툴팁 내부에서 스크롤한다.
- Confusion Matrix는 참고 답안(행)과 AI 최종 판정(열)을 정탐·오탐·보류 3×3으로 표시한다. 보류 답안의 정탐 확정·오탐 확정·보류 일치를 구분하며 테스트 문항 목록의 셀 필터에도 연결한다.

## 평가 기준

기존 이진 Accuracy·Precision·Recall·F1·Macro F1·MCC 등의 분모는 바꾸지 않는다. 기존 지표는 **참고 답안이 정탐·오탐이고 AI가 확정한 문항**을 사용한다. 기존 커버리지·보류율은 이진 답안 중 AI 보류를 포함한다. 전체 참고 답안 일치율(`matches / evaluable`)은 기존처럼 세 판정 모두 포함한다. 같은 의미의 전체 점수를 중복 추가하지 않는다.

보류 답안을 별도로 관리하기 위해 아래 지표를 더한다. 계산할 분모가 없으면 null/계산 불가다.

| 지표 | 계산 | 해석 |
| --- | --- | --- |
| 보류 답안 일치율 | 참고 보류·AI 보류 / 참고 보류 전체 | 보류 클래스의 Recall. 높을수록 필요한 보류를 놓치지 않음 |
| 보류 답안 확정률 | 참고 보류·AI 정탐 또는 오탐 / 참고 보류 전체 | 위 일치율의 보수. 낮을수록 기대에 어긋난 확정이 적음 |
| 보류 Precision | 참고 보류·AI 보류 / AI 보류 전체 | 높을수록 불필요한 보류가 적음 |
| 보류 F1 | 2 × 보류 일치 수 / (2 × 보류 일치 수 + 보류 답안 확정 수 + 이진 답안의 AI 보류 수) | 보류 Precision과 Recall의 균형 |

예: 참고 보류 10건에서 AI 보류 6·정탐 3·오탐 1이면 보류 답안 일치율은 60%, 확정률은 40%다. 이 4건을 실제 공격을 놓친 미탐 또는 정상 요청을 공격으로 본 과탐으로 부르지 않는다. 실제 공격 여부가 확정된 답안이 아니기 때문이다. 참고 답안이 정말 정보 부족으로 보류해야 하는 사례인지도 검수해야 한다.

이 행렬은 [scikit-learn의 표준 혼동행렬 정의](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.confusion_matrix.html)처럼 행에 참고값, 열에 예측값을 둔다. 보류는 이 서비스의 업무상 판정 상태이며 별도의 공격 유형이 아니다. 실패·진행 중·미라벨·모의 실행·출처 불명·답안 오염 결과는 기존처럼 제외한다. 답안 출처·AI 열람 여부별 구분과 고정된 테스트 답안도 유지한다.

API의 `confusion_matrix`에 `expected_hold_positive`, `expected_hold_negative`, `expected_hold_match` 3개가 추가된다. 기존 6개 필드는 유지한다. 이제 전체 9개 합은 `binary_evaluable`이 아니라 `evaluable`과 같다. `metrics`에 `expected_hold_match_rate`, `expected_hold_decided_rate`, `hold_precision`, `hold_f1`을 추가한다. 기존 `basis=decided_binary`는 기존 이진 지표의 기준이며, 새 보류 지표에는 위의 별도 분모를 적용한다.

## 근거 정리 LLM

Primary → 조건부 독립 Verifier → 서버 최종 판정 → **선택적 근거 정리** 순서다. 정리 단계는 판정·심각도·신뢰도·튜닝 결정을 바꾸지 않는다.

설정 → Agent 설정 → 모델 배정에서 운영·테스트별 `근거 정리 사용`과 프로필을 지정한다. 기본은 꺼짐이다. `Primary와 동일` 또는 현재 설정으로 전체 검증된 별도 프로필을 사용한다. OpenAI 선택에는 기존 외부 전송·비용 동의가 필요하며 원문 발췌가 마스킹 없이 전송될 수 있다. 사용 해제 시 해당 역할 배정도 해제한다. 다른 프로필로 자동 우회하지 않는다.

1. 기존의 완전 중복 제거는 코드에서 수행한다. 같은 출처·발췌·근거 방향 안에 여러 설명이 있는 경우만 정리 후보가 된다. 기록된 원문 위치가 다르면 묶지 않는다.
2. LLM은 의미가 같은 후보를 묶고 **기존 설명 중 대표 설명을 선택**한다. 새 문장을 생성하는 방식이 아니다. 의미·조건·범위가 다르거나 확실하지 않으면 분리하도록 지시한다.
3. 출력은 구성원 번호와 대표 번호만 허용한다. 서버는 알려진 번호인지, 전체 근거가 한 번씩 포함됐는지, 대표가 구성원인지, 같은 출처·정탐/오탐/참고 방향인지 검증한다. 누락·중복·교차 병합은 전체 거부한다.
4. 저장된 `evidence_presentation`을 화면·Markdown·PDF·Excel의 공통 표시 경로에서 적용한다. 판단 쟁점의 근거 번호를 대표 번호로 다시 연결하되, 쟁점과 아직 확인되지 않은 조건은 그대로 유지한다. 원래 `analyst_assessment`, 최종 판정 근거, Primary/Verifier 출력은 덮어쓰지 않는다.
5. 모델 변경·사용 중지·연결 허용 해제·시간 초과·잘못된 출력이면 원래 근거를 표시한다. 정리 단계만 실패로 기록하고 최종 분석을 실패나 보류로 바꾸지 않는다. 실행 소유권을 잃은 worker는 예외를 숨기거나 결과를 저장하지 못한다.

역할별 상한은 출력 1,024토큰(프로필이 더 작으면 작은 값), 입력 본문 UTF-8 16,000바이트, 모델 응답 최대 30초(프로필이 더 짧으면 짧은 값), 큐 대기와 모델 실행 합계 최대 90초다. 모델 선택·DB 저장 시간은 별도다. 프롬프트와 출력 스키마 공간을 포함한 보수적 입력 예산 검사를 수행한다. 출력 교정/전송 재시도 없이 최대 한 번 호출한다. 공통 동시 처리 슬롯을 사용하므로 같은 vLLM 서버의 다른 역할과 호출 상한을 공유한다. 실행 비교의 기록된 사용량에도 호출을 시도한 근거 정리 단계를 포함하며, 생략한 단계는 포함하지 않는다.

두 용도에 동일한 `evidence-editor-v1` 고정 지침을 쓴다. 명명 테스트는 접수 시, 일반 운영은 최초 실행 시 프로필 지문과 지침 본문·버전·해시를 암호화해서 고정한다. 실행 스냅샷은 v3이며 v1/v2는 근거 정리를 하지 않는다. 이전 테스트의 미기록 설정도 꺼짐으로 유지하고, 재실행은 당시 설정을 복사한다. 후보 모델 150건 전체 검증에는 근거 정리 모델을 사용하지 않는다.

입출력은 암호화된 `llm_evidence_editor` 단계 이력에 저장하며, 평문 메타데이터에는 버전·프로필·안전한 상태·시간/사용량만 기록한다. 원문과 provider의 임의 오류 본문을 로그·평문 오류에 넣지 않는다. 조회·보고서 다운로드는 LLM을 호출하지 않는다.

[OpenAI 구조화 출력 문서](https://developers.openai.com/api/docs/guides/structured-outputs)를 참고해 번호 기반 계약을 사용하지만, 형식 검증은 의미의 동일성을 보장하지 않는다. 실제 Gemma/OpenAI 모델이 서로 다른 해석을 잘 구별하는지, 대표 설명의 품질·추가 지연이 적절한지는 별도 실제 평가가 필요하다. 기존 결과를 소급 정리하지 않는다.

## DB 및 적용

새 운영 의존성은 없다. Alembic `0016_evidence_editor`가 필요하다. `agent_configurations`에 두 용도의 사용 여부·프로필 컬럼 4개, `test_runs`에 암호화된 정리 설정 컬럼 1개를 추가한다. 기존 모델 배정과 이력은 유지하고 기존/신규 설치를 모두 지원한다.

배포 시 worker와 API를 함께 업그레이드하고 기존 배포 절차에 따라 DB 백업 후 `alembic upgrade head`를 수행한다. 여기서는 실행하지 않는다. 새 스냅샷이나 설정을 사용한 뒤에는 단순 downgrade를 차단한다. 이전 코드로 되돌릴 때는 업그레이드 전 백업을 이용하는 절차가 필요하다.

## 검증

단위/통합 테스트는 합성 fixture·임시 SQLite·모의 HTTP만 사용한다. 실제 LLM 비용이나 사내 데이터 전송은 없다. 브라우저 검증은 격리 Vite와 모의 API로 수행하고 외부 요청을 차단한다.

- `backend/tests/test_evidence_editor.py`: 번호 계약, 교차 병합·누락 거부, 대표 표시/보고서, 역할 검증·동의, 오류/사용 중지 대체 표시, 설정 고정·재실행·소유권 상실, 실제 ModuAgent의 vLLM/OpenAI 요청 직렬화와 단일 호출.
- `backend/tests/test_evidence_editor_migration.py`: 실제 이전 스키마 형태에서 업그레이드, 기본 꺼짐·배정 보존·외래키·사용 후 rollback 차단.
- 기존 평가/조회 테스트: 9개 셀, 답안 출처별 집계, 이진 지표 분모 보존.
- `frontend/src/evidencePresentation.test.mjs`: 읽기 전용 표시/보고서, 참조 번호 연결, 오류 시 원본 유지, 보류 셀 검색, 검증된 역할 배정.
- `frontend/scripts/evidence-editor-smoke.mjs`: 실제 컴포넌트의 데스크톱·모바일 설정 저장, 요약 말줄임/hover/focus/Escape, 긴 툴팁과 비실행 HTML 문자열, 3×3 셀 필터/지표.

실행 결과:

- 전체 백엔드: 1,946건 실행, 1,945건 통과. 남은 1건은 실행 비교 테스트에 예전 6셀 기대값이 남아 있던 것으로 확인해 9셀로 수정했다. 수정 후 해당 비교 파일 21건이 모두 통과했다. 전체 스위트를 수정 후 다시 한 번 통째로 실행한 것은 아니다.
- 추가 고정 설정/재실행/소유권/마이그레이션 검증 22건 통과. 마지막 관련 회귀 97건에서는 위와 동일한 기존 기대값 1건만 실패했고 나머지 96건은 통과했다. 해당 기대값 수정 후 위의 21건 재검증으로 마무리했다.
- 프런트엔드 전체 35개 테스트 파일 통과, Vite 빌드 통과. 기존 500KB 초과 청크 경고는 남아 있다.
- 데스크톱 1,360px·모바일 390px 브라우저 확인 통과. 로컬 참고 화면: `/tmp/waf-editor-ui-fXofnY`. API·모델 호출은 모의 처리했고 외부 요청은 차단했다.

위 구현 당시에는 Docker 재배포·설정 활성화·실제 LLM 정리 품질·처리량 검증을 수행하지 않았다. 후속 배포에서는 백엔드 1,951항목을 확인하고(컨테이너 경로 누락 1건 별도 재검증), 실제 HTTP·배포 화면까지 검증했다. [후속 기록](Deployment_Evidence_Editor_2026-09-14.md)을 따르며 설정 활성화·실제 LLM 정리 품질·처리량은 여전히 미검증이다.
