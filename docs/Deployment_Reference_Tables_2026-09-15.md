# 참고 답안·테이블 개선 배포 — 2026-09-15

## 배포 결과

현재 작업 환경의 로컬 Docker 네 서비스를 재배포했다. 별도 운영서버를 배포한 기록은 아니다. 앱 버전은 **0.2.0**을 유지하며 새 태그는 만들지 않는다.

- UI: `http://127.0.0.1:18080`, API: `http://127.0.0.1:18000`.
- Test·Production 단건/파일 요청의 `expected_verdict` 자동 등록. 이벤트·스키마 정의·모델 입력과 답안을 분리한다.
- 테스트 목록·상세의 최신 참고 답안 기준 평가와 저장 후 갱신. 접수 당시 답안·저장한 평가·AI 결과는 보존한다.
- 주요 목록의 TanStack Table 전환과 공통 표 스타일, 서버 정렬·선택 범위·요약 말줄임·모바일 스크롤.
- 기존 선택적 정리 모델의 근거·추가 확인사항 대표 선택 확장. 당시 고정한 이전 지침·판정·원본을 보존한다.
- 앞서 게시된 vLLM 기능 검증 출력 상한 보완도 배포에 포함한다. 기존 검증 결과나 실제 모델 출력 설정을 변경하지 않는다.

상세 계약은 [참고 답안과 테이블](Reference_Evaluation_and_Tables_2026-09-15.md), [확인사항 정리](Follow_Up_Organization_2026-09-15.md), [vLLM 검증 출력](LLM_Validation_Output_2026-09-15.md)을 따른다.

## 데이터·설정 보존

대기/처리 중 분석과 모델 검증이 각각 0건인 상태에서 네 서비스를 정지하고 SQLite backup API로 일관성 백업을 생성했다. 새 이미지로 기동한 직후 **25개 테이블의 모든 행·열 해시가 백업과 일치**했다. HTTP 점검 뒤에도 조회 감사의 추가만 허용해 기존 행 보존을 재확인했다.

- 분석 **1,214건**, 암호화 값 **20,882개** 복호화 및 무결성·외래 키 검사 통과.
- DB **`0017_validation_data`** 유지, 신규 마이그레이션 없음.
- `moduagent`, 현재 모델 프로필·역할 배정·근거 정리·동시 처리·공통/편집 지침·서비스 키와 암호화 키 보존.
- 기존 환경값·명령·포트·볼륨·네트워크 유지, 재배포 직후 재시작 0회.
- 설정이 과거 배포 기록과 달라도 현재 값을 유지했다. 모델 검증·역할 복원·새 분석 접수는 수행하지 않았다.

모델 지정과 검증 성공 여부는 배포 정상 기동과 별개다. 실제 분석 전 설정 → Agent 설정·LLM 프로필에서 현재 배정과 검증 상태를 확인해야 한다.

## 검증

- 실제 HTTP **32개**: 로그인, 미인증/다른 Origin 거부, Test·Production 평가 조회, 최신/접수 당시 답안 기준, 서버 정렬, 과거 원문·Agent 이력, PDF/Excel 및 운영 API 정의서 PDF, OpenAPI 요청 계약.
- API·두 worker의 소스 **120개 파일**과 작업 코드 일치. 실제 웹의 JS/CSS가 이번 빌드 산출물과 일치.
- 이번 배포 이미지 런타임의 오프라인 백엔드 회귀 테스트 **72건** 통과. 운영 DB나 네트워크를 연결하지 않았다.
- 프런트엔드 **39개 테스트 파일**, Vite 빌드 통과.
- 가상 데이터 브라우저 **8개 시나리오** 통과: 답안 저장 즉시 점수/행 갱신, 과거 평가 보존, 선택 범위·키보드 정렬, 전체 요약 표시, 라이트/다크 및 모바일, 미완료 평가 저장 안내. 외부 요청·브라우저 오류 0건.
- 앞선 구현 단계 관련 백엔드 **412건** 통과 기록은 기능 문서에 보존한다. 전체 백엔드 테스트를 이번 배포에서 다시 실행한 것은 아니다.

기존 Vite 500KB 초과 번들 경고와 Starlette 사용 중단 예고는 남아 있다. 이전 확인된 Vite/esbuild 의존성 보안 경고는 이번 배포에서 업그레이드하지 않았다. 실제 Gemma/OpenAI 품질·동시 부하·유료 API 호출·장시간 운영은 미검증이다.

## 재기동·복구·Git

실제 배포 Compose, 백업 및 이전 이미지 정보는 비공개 `.local-deploy/README.md` 맨 위에 기록한다. 같은 구성으로 재기동하며 기본 Compose만 실행해 포트·모드·비밀값을 초기화하지 않는다. 볼륨 삭제·DB 복원·downgrade는 수행하지 않았다. 배포 이후 새 데이터가 생길 수 있으므로 복구 시 현재 DB도 먼저 보존하고 코드·스냅샷 호환성을 확인한다.

GitHub 게시 대상은 기존 `nagix999/waf-ai-console`의 main이다. 원래 작업 폴더의 비어 있는 읽기 전용 `.git`은 수정하지 않고 기존 main을 잇는 게시용 복제본을 사용한다. 승인된 소스·문서·테스트·의존성 잠금 파일만 복사하며 비밀 환경값, DB/백업, `.local-deploy`, 의존성 설치물·빌드 산출물은 제외한다.
