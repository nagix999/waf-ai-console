## 백업과 데이터 보존

모든 writer 종료 후 SQLite backup API로 `pre-0012-20260907T140308Z.db`를 생성했다. 백업은 리비전 **0011**, 크기 26,288,128 bytes이며 권한 600, 상위 비공개 디렉터리는 700이다. 비밀 설정과 백업은 출력·공유·커밋하지 않는다.

기존 완료·실패 분석에 현재 스키마를 소급해서 넣지 않았다. 기존 분석/테스트의 신규 스키마 연결과 스냅샷은 null로 유지됐다. 대기·실행 중 분석/모델 검증은 0건이며 분석 재실행이나 새 모델 검증을 만들지 않았다.

마이그레이션 종료 후 SQLite WAL/SHM 파일이 없어 읽기 전용 volume mount 검사가 한 차례 실패했다. 보조 파일 생성이 가능한 mount로 조정하되 SQL 연결은 `mode=ro`로 유지해 재검증했고 통과했다. 이 실패는 실제 migration 실패나 데이터 손상이 아니며, 복원·추가 migration·기존 행 수정은 하지 않았다.

## 운영·복구 안내

현재 구성은 `.local-deploy/v0.2.0-20260907T140308Z-Sd5UYR/compose.json`이다. 비밀값이 포함되므로 내용을 출력·공유·커밋하지 않는다. 같은 폴더의 검증 JSON과 `.local-deploy/README.md`에 로컬 재시작·복구 자료 위치를 남겼다. 기본 `docker-compose.yml` 단독 실행으로 기존 모드·포트·키를 바꾸지 않는다.

백업 복사본 `migration-rehearsal.db`는 **0012 검사 산출물**이며 원래 **0011 백업**과 다르다. 이전 이미지 설정만으로 자동 복귀하거나 downgrade하지 않는다. 기본 스키마 이력이 생성됐으므로 `0012` downgrade도 차단된다. 복구가 필요하면 writer와 신규 접수를 중지하고 현재 DB도 별도 백업한 뒤 신규 데이터 손실·키 복원·호환성을 검토하고 별도 승인을 받아야 한다. 백업 존재는 덮어쓰기나 볼륨 삭제의 승인이 아니다.

Test LLM은 아직 미지정이다. 테스트 실행 전 관리자가 검증된 프로필을 명시적으로 Test에 지정해야 하며 Production으로 자동 대체하지 않는다.
