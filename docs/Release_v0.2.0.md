# WAF AI Analysis Console v0.2.0

## 이번 릴리스

- 설정 → 입력 스키마: 기본 11개 필드 보호, 사용자 필드와 타입·필수·null·제한·하위 구조 편집.
- 필드 설명을 포함한 불변 버전, 변경 비교, 합성 샘플 검증 후 명시적 적용, 적용 이력과 이전 버전 복귀.
- 접수 당시 정의를 분석·테스트·후보 검증에 암호화해 고정. 추론 이력에는 필드 정의를 기록하되 LLM 입력에 설명을 추가하지 않음.
- Production 접수 검증·온라인 API 정의서·Markdown 다운로드·Swagger/OpenAPI에 같은 활성 스키마 반영.
- v0.1.0 이후 합의하여 구현한 OpenAI/vLLM 프로필, Production/Test 역할, 프롬프트 버전, Internal Egress, 서비스 키 관리, 이름 있는 테스트/평가 지표, 분석가용 상세/보고서/디코딩 개선을 포함.

## 업그레이드 주의

- DB는 Alembic `0012_input_schemas`까지 필요. 운영 데이터·암호화 키를 백업하고 API와 모든 worker를 중지한 뒤 마이그레이션 및 같은 버전 배포를 진행할 것.
- 입력 스키마 변경은 새 접수에 적용. 기존 접수·재전송·테스트·답안·분석 이력을 다시 쓰지 않음. 새 필수 필드로 합성 150건이 부적합해지면 접수를 거부함.
- 추가 필드의 숫자·boolean·객체·배열 입력에는 JSON 업로드 사용. CSV는 기존 포트만 숫자로 변환.
- 기존 환경변수 배포 키는 사용하지 않음. 설정에서 서비스 API Key 발급 후 수집기 전환 필요.
- vLLM은 Internal Egress의 개별 내부 IP/포트 등록 필요. 기존 호스트명 allowlist를 자동 가져오지 않음.
- 실제 모델 테스트는 검증된 Test 프로필을 명시적으로 지정해야 함. Production으로 자동 대체하지 않음.
- 필드 설명은 기존 공개 OpenAPI에도 반영되므로 키·실제 WAF 원문·개인정보를 기입하지 말 것.

## 검증과 한계

오프라인 합성 테스트, 프런트엔드 빌드, 브라우저 화면/동작, 마이그레이션 보존 검증을 수행했다. 상세 수치와 미검증 항목은 `docs/Validation_v0.2.0_2026-09-07.md`를 참고한다.

실제 GPU/vLLM/OpenAI 호출, 운영 부하/판정 품질, 운영 DB 마이그레이션·Docker 재배포는 이 릴리스 게시에 포함하지 않는다. 기존 보안 점검의 미조치 항목은 `docs/Security_Assessment_2026-09-07.md`를 따른다. API Key, .env, DB, 개인 배포 설정·백업은 저장소에 포함하지 않는다.
