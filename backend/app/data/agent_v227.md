# v2.27 후보: 통합 해석과 원문 연결

## 적용 범위

Primary → 조건부 독립 Verifier → 기존 서버 판정 → 근거 정리와 핵심 응답 흐름을 유지합니다. 파서와 수신 이벤트, 모델 선택 및 호출 상한은 변경하지 않습니다. 같은 모델을 두 역할에 지정할 수 있고 공통 판정 기준은 같으며 역할별 검토 관점만 다릅니다. Verifier에는 Primary 출력이 전달되지 않습니다. 필요한 Verifier 실패나 판정 불일치는 계속 보류입니다.

이 후보는 `waf-system-v2.27`, `waf-judgment-v2.27`, `evidence-pipeline-v8`로 식별합니다. 이전 v2.26 지침 전체는 `legacy_prompts_v226.py`에 동일하게 보존하고 이전 90개 고정 실행 파일은 수정하지 않습니다. 새 실행기 `app.worker_entrypoint_v227`은 기존 실행과 새 후보를 스냅샷 기준으로 구분합니다. Compose와 배포 도구는 새 실행기를 사용하도록 연결합니다. 코드 변경만으로 승인된 운영 지침을 교체하지 않으며 공식 Ground Truth 평가와 관리자 운영 검토가 필요합니다.

DB migration과 운영 의존성 추가는 없습니다. 공개 `waf-analysis-v3` 필드, 타입, 역할별 최대 5개 및 전체 최대 10개 근거 한도를 유지합니다. UI와 보고서 및 내보내기는 같은 핵심 응답을 사용합니다. 근거 정리가 필요한 경우 준비 전 `processing/result=null`을 유지합니다.

## 내부 출력

모델은 근거 배열의 숫자 인덱스를 직접 생성하지 않습니다. 한 해석의 대표 원문과 필수 관련 원문을 직접 선택합니다.

```json
{
  "source_id": "c12",
  "related_sources": [
    {
      "source_id": "c13",
      "contribution_ko": "앞의 입력값을 실행 대상으로 처리하도록 지정한 요청 위치입니다.",
      "supports": "context"
    }
  ],
  "interpretation_ko": "명령 형태의 값과 이를 실행 대상으로 지정한 문맥이 결합되어 서버 처리 변경을 시도하는 입력으로 해석됩니다.",
  "supports": "attack_request"
}
```

위 내용은 합성 예시이며 실제 모델 품질 평가 결과가 아닙니다. 대표 `interpretation_ko`에 통합 의미를 한 번 설명하고 관련 원문에는 각 기여만 설명합니다. `supports`는 해당 원문의 기여이며 이벤트 판정이나 확신 수준이 아닙니다. 관련 원문은 중립이면 `context`를 유지합니다. 보류라는 이유로 타당한 공격 근거를 중립으로 바꾸지 않습니다.

대표와 관련 원문을 모두 합쳐 최대 5개입니다. 보통 핵심 해석 2~3개를 우선하되 필수 출처와 중요한 반대 근거를 버리지 않습니다. 같은 source ID라도 서로 다른 보안 해석에 필요하면 별도 항목으로 남길 수 있으나 한 해석 안의 중복 참조는 거부합니다.

`decision_issue.source_ids`도 선택한 원문을 직접 참조합니다. 서버가 이를 기존 근거 인덱스로 연결합니다. 시그니처의 `version=signature-assessment-v2`와 `explanation_ko=null`, 실제 `input_truncated`는 서버가 채우므로 모델 출력에서 제외합니다. 그 밖의 각 역할 요약, 위협 분석, 탐지 비교, 보류 조건, 판정 및 근거 의미는 해당 역할이 직접 작성합니다.

서버는 통합 해석과 관련 기여를 기존 단일 발췌 근거로 확장하고 기존 관계 구조를 생성합니다. 떨어진 원문을 한 발췌로 합치지 않으며 관련 원문을 `source_spans`에 숨기지 않습니다. 필수 연결은 관리자 이력 및 핵심 근거 선택에 유지됩니다. 암호화 이력에는 원래 모델 출력 `output`과 서버 변환 `expanded_output`을 구분해 기록합니다.

## 검증과 교정

- 최대 근거 수, 중복 참조와 선택하지 않은 보류 조건 참조를 검사합니다.
- 제출한 출처인지 확인하고 시그니처 및 등록 설명의 context 제한을 검사합니다.
- 확정 판정에는 같은 방향의 통합 해석과 요청 내용 출처가 있어야 합니다. 헤더의 존재만으로 정상이라는 문장의 의미적 오류까지 코드가 판별하는 것은 아닙니다.
- 같은 해석에 공격과 정상 방향을 묶지 않으며 기존 심각도, 요약, 탐지 비교 및 보류 조건의 검증을 유지합니다.
- 후속 원문 검증과 인용 교정에서 근거를 제외한 뒤에도 방향의 일관성을 확인합니다. 필수 원문을 잃은 통합 설명은 제외하고 기존 보류 정책을 적용합니다. 정상 근거가 사라졌다고 자동 정탐으로 바꾸지 않습니다.

새 검사에서 실패하면 같은 역할의 기존 출력 교정 한도(최초 포함 최대 4회)를 사용합니다. 오류 유형과 경로만 전달하고 임의 출력값이나 다른 역할의 답변은 보내지 않습니다. 출처나 방향의 일관성 오류는 원문으로 해석과 분류 및 판정을 함께 재검토하게 하며 분류만 뒤집도록 요청하지 않습니다. 한도를 늘리거나 일치할 때까지 반복하지 않습니다.

완결 JSON의 안전한 BOM/코드펜스 처리와 strict JSON Schema를 유지합니다. 새 계약에는 모델이 작성하는 관계 인덱스가 없으므로 과거 관계 인덱스 복구는 과거 실행기에만 남습니다. 기존 인용 교정은 별도 최대 1회이며 의미를 바꾸는 재판단을 교정으로 위장하지 않습니다. 추가 의미 검토 LLM 호출은 도입하지 않습니다.

두 역할의 결론이 다르다는 것만으로 요청 자체에 공격/정상의 두 타당한 해석이 있다고 요약하지 않습니다. 요청 내용 요약과 보류 판정을 분리하고 기존 역할별 결과와 정책 사유를 보존합니다.

## 검증 범위와 비교 방법

오프라인 테스트는 새 출력 계약, 두 provider의 실제 요청 구성과 모의 응답 교정, 원문 연결, v3와 핵심 응답, 역할 독립성, 실패/불일치 보류, 과거 실행 및 승인/재실행 보존을 확인합니다. 모의 성공은 Gemma의 판단 품질이나 실패율 개선을 증명하지 않습니다.

기존 비교 도구에 v2.26 기준 선택을 추가했습니다. 다음은 DB를 읽거나 모델을 호출하지 않는 실행 계획 확인입니다.

```bash
cd backend
python scripts/compare_security_analysis_v3.py --baseline-version v2.26
```

실제 실행에는 기존 명시적 모델 호출 옵션과 승인된 프로필 및 결과 경로가 필요합니다. 기존 합성 30건을 같은 모델과 관리자 지침으로 비교하되 이 시험은 공식 Ground Truth 평가가 아닙니다. 보고 시 첫 응답 성공과 최종 성공, 재시도와 보류, Verifier의 개선/악화, 원문에 맞지 않는 공격/정상 해석 및 핵심 공격 누락을 함께 확인해야 합니다. 처리 시간은 역할 호출뿐 아니라 대기와 근거 정리까지 포함한 기존 읽기 전용 시간 진단으로 확인합니다. 추가 의미 재검토 호출은 이 결과에서 효과가 확인될 때 별도 검토합니다.

실제 모델 호출, 운영 설정 변경, 재배포와 Git 업로드는 이 개발 작업에 포함하지 않습니다.

## 크기 측정과 검증 기록 (2026-11-23)

공백과 줄바꿈을 포함한 공통 고정 지침은 v2.26의 4,280자에서 4,325자로 늘었습니다. 반면 실제 전송용으로 정리한 JSON Schema는 4,014자에서 3,650자로 줄었습니다. 두 항목 합계는 8,294자에서 7,975자입니다. 관리자 지침, 역할 지침과 이벤트는 제외한 문자 수이며, 실제 토큰 수나 처리 시간 개선을 증명하지 않습니다.

새 후보 계약과 worker, 스냅샷, 비교 도구, 파서 연결, 핵심 근거 및 관계 회귀 테스트는 최종 227건 통과했습니다. 기존 실행 보존과 입력, 출력 교정 및 시간 진단 회귀 테스트는 572건 통과했습니다. 후보 구성과 운영 승격, API, 재실행, 핵심 근거 내보내기 및 지침 관련 테스트는 197건 통과했습니다. 이 실행에서 별도 옵션이 필요한 PDF 렌더러 3건은 제외했으며, 이어서 해당 옵션을 켜고 실제 Node/ReportLab 렌더러로 3건 모두 통과했습니다. 관련 backend 테스트 합계는 999건이며 전체 backend 테스트 모음을 실행한 것은 아닙니다. 배포 스크립트 단위 테스트는 별도 22건 통과했습니다. 기존 Starlette/AnyIO의 `BlockingPortal` 사용에 관한 deprecation 경고는 남아 있습니다. 외부 통신 없는 임시 컨테이너와 합성 데이터로 검증했으며 운영 DB나 승인된 운영 설정은 변경하지 않았습니다.

기존 고정 실행 90개 파일의 artifact SHA-256은 `108bf447e4ac0eb34baa78fa8e4477f42dbf95627b12abbef6b8a0269b4bd4cf`로 동일합니다. 새 실행 파일 14개를 추가한 v2.27 artifact는 `fa2868069cefa992cfee95fc6eb3750a331ec0d589cba8683b4658e4e2caea2d`입니다. 이전 공통 지침 전체도 바이트 단위로 보존했습니다.

실제 Gemma 모델의 첫 응답 성공률, 해석 정확도, 불필요한 보류와 처리 시간은 아직 측정하지 않았습니다. 새 계약은 검증 가능한 모순을 초기에 잡지만, 모델이 새 계약을 잘 지키지 못하면 오히려 교정이 늘어날 수 있습니다. 공식 평가 후 운영 적용 여부를 판단해야 합니다. 프런트엔드 파일은 변경하지 않았고 이번 작업에서 전체 프런트엔드 빌드나 브라우저 화면 검증은 수행하지 않았습니다.
