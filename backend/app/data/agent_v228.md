# v2.28 출력 한도 대응 후보

## 변경 범위

운영 v2.27에서 `model_output_incomplete`, `length/max_tokens`가 보고되었습니다. 실제 프로필 한도와 건별 사용량은 확인하지 않았으므로 기본값 3,072가 운영 값이라고 가정하지 않습니다.

기존 생성 스키마는 해석 5개에 각 관련 원문 4개를 허용해 최대 25개의 설명을 만들 수 있으나, 서버 검증은 확장 합계를 5개로 제한합니다. 새 내부 계약은 생성 단계부터 관련 항목까지 합계 5개입니다. 모델이 실제 25개를 출력했다거나 이 차이만이 모든 실패의 원인이라는 뜻은 아닙니다.

## 내부 근거 계약

```json
{
  "evidence": [
    {
      "evidence_id": "e1",
      "source_id": "c12",
      "interpretation_ko": "입력값과 실행 대상을 지정한 문맥이 결합되어 서버 처리 변경을 시도하는 요청으로 해석됩니다.",
      "supports": "attack_request",
      "related_evidence_ids": ["e2"]
    },
    {
      "evidence_id": "e2",
      "source_id": "c13",
      "interpretation_ko": "입력값을 실행 대상으로 다루도록 지정한 위치여서 앞의 해석에 필요합니다.",
      "supports": "context",
      "related_evidence_ids": []
    }
  ]
}
```

합성 부분 예시이며 완전한 모델 출력이나 실제 품질 평가 결과가 아닙니다.

- `evidence_id`는 해당 역할의 해석 번호(e1~e5), `source_id`는 제공된 원문 번호입니다. 배열 순서와 번호가 달라도 서버가 정확히 위치로 연결합니다.
- 대표 해석은 결합 의미를 한 번 설명하고 관련 항목은 자신의 기여만 설명합니다. 같은 원문을 다른 의미로 해석해야 하면 서로 다른 근거 번호를 사용합니다.
- `decision_issue.evidence_ids`는 이번 목록에서 선택한 해석만 참조합니다. 선택하지 않은 번호, 자기 참조, 중복/순환 연결 및 연결 그룹 내 공격/정상 혼합을 거부합니다.
- 기존 출처 및 허용 분류 검증, 확정 판정에 맞는 요청 내용 근거, 심각도와 요약 및 확인 조건의 정합성 검증을 유지합니다. 문장의 의미적 타당성을 코드가 보증하지는 않습니다.
- 서버는 기존 V224 선택 계약과 숫자 관계로 변환한 뒤 기존 원문 대조를 수행합니다. 필수 의존 원문을 잃은 해석은 제외하고 기존 보류 정책을 적용합니다. 분류나 판정을 자동으로 뒤집지 않습니다.
- 암호화 실행 이력은 모델의 `output`과 서버 변환 `expanded_output`을 구분합니다. 공개 v3에는 모델 내부 번호나 새 필드를 추가하지 않습니다.
- 기존 정규화가 원문/해석/분류가 완전히 같은 근거를 하나로 합친 경우에는 모든 출처를 먼저 대조한 뒤 자기 연결과 같은 연결의 반복만 제거합니다. 같은 대표로 합쳐진 항목의 나머지 필수 연결은 모두 유지하며 출처 이력과 원문 위치는 바꾸지 않습니다. 서로 다른 해석이나 누락 출처를 중복으로 간주하지 않습니다.

## 첫 호출과 재시도

공통 지침은 첫 호출부터 요약 1문장, 근거 해석 1~2문장, 관련 기여 및 기법/영향 각 1문장을 권장합니다. 필수 원문과 중요한 반대 근거는 유지하고 같은 설명의 필드 간 반복을 줄입니다. 새 계약의 실제 호출 지침에 프로필의 출력 토큰 한도와 완결 JSON 요구를 추가합니다. 문장 수는 새 하드 검증 조건이 아닙니다.

출력 한도와 최초 포함 최대 4회, 별도 인용 교정 최대 1회는 그대로입니다. 미완료 응답이나 잘린 JSON을 성공으로 인정하지 않습니다. 재시도에는 현재 오류와 간결한 작성 지시만 제공하고 이전 답변 전체나 다른 역할의 답변을 누적하지 않습니다. 새 근거 연결 오류는 기존 처리 시간 및 출력 집계의 고정 오류 분류에 추가합니다.

새 지침은 관계 번호 설명 때문에 v2.27보다 약간 길어집니다. 핵심 변화는 지침 입력 길이 축소가 아니라 생성 가능한 설명 수의 일치와 첫 응답의 반복 감소입니다. 실제 출력 토큰 감소나 생성 속도 개선은 별도 모델 평가 대상입니다.

## 배포와 보존

- 지침 `waf-system-v2.28`, 실행 구현 `evidence-pipeline-v9`, 실행기 `app.worker_entrypoint_v228`.
- 이전 전체 지침은 `legacy_prompts_v227.py`, 기존 104개 실행 파일은 같은 해시로 보존합니다. 새 구현을 포함한 manifest는 118개입니다.
- 승인된 Production 구성과 기존 접수/재실행은 당시 버전으로 처리합니다. 배포만으로 새 후보를 활성화하지 않습니다. 공식 Test → 승인된 Ground Truth 평가 → 운영 검토 및 승인 경로를 유지합니다.
- Primary/Verifier 독립 입력, 조건부 병렬 허용 범위, 필요한 Verifier 실패 및 판정 불일치 보류, 핵심 근거 준비 전 API 완료 금지, 근거 정리 구현을 유지합니다.
- 공개 API v3, DB schema, 파서, 운영 패키지와 프로필 한도 변경은 없습니다.

## 검증과 제한

오프라인 합성 테스트는 평면 스키마, 정확한 관계 변환과 필수 의존성, 두 provider의 실제 요청 직렬화 및 모의 응답, 출력 한도 중단과 기존 재시도 한도, 원문 교정, 공개 v3와 역할 독립성, 과거 실행 및 승인/재실행 보존을 확인합니다. 이 검증은 운영 모델 실패율이 특정 수치 이하로 내려간다는 보장이 아닙니다.

2026-11-23 관련 검증은 중복 실행을 제외해 백엔드 593건 통과, 1건 스킵입니다. 스킵은 별도 환경 설정이 필요한 PDF 릴리스 이미지 렌더링 검사입니다. 배포 스크립트 22건, 프런트엔드 관련 12건과 빌드도 통과했습니다. 기존 Starlette/AnyIO deprecation 및 프런트엔드 큰 번들 경고는 남아 있습니다. 전체 백엔드 테스트를 모두 실행했다는 뜻은 아닙니다.

기존 비교 도구에서 `--baseline-version v2.27`을 선택할 수 있습니다. 다음 명령은 모델 호출이나 운영 DB 조회 없이 비교 계획만 확인합니다.

```bash
cd backend
python scripts/compare_security_analysis_v3.py --baseline-version v2.27
```

실제 Gemma/vLLM 및 유료 외부 호출, 운영 지침 적용, Docker 재배포와 Git 업로드는 이번 범위에 포함하지 않습니다.
