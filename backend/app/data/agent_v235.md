# v2.35 출력 검증 실패 근거 기록 후보

완결된 구조화 응답이 출력 검증을 통과하지 못하면 당시 근거 번호, 출처 번호, 분류, 해석과 관련 번호를 제한된 진단 자료로 보존합니다. 통과하지 못한 설명은 올바른 근거나 최종 판정으로 취급하지 않습니다. 이후 재시도가 성공해도 이전 실패 시도의 자료는 구분하여 남깁니다.

자료는 기존 AgentStep의 암호화된 처리 결과에만 저장합니다. 관리자 실행 이력의 처리 결과에서 조회하고 접근 감사를 유지합니다. 일반 로그, 평문 실행 메타데이터와 공개 분석 API v3, 보고서와 다운로드에는 추가하지 않습니다. 원본 provider 응답, private reasoning과 해석 외 임의 필드는 저장하지 않습니다. 불완전 JSON과 거절, 크기/깊이/중복 키 검증을 통과하지 못한 자료는 추측하여 복원하지 않습니다. 개수와 길이 제한으로 생략된 부분은 구분합니다.

고정 지침 표기는 `waf-system-v2.35`, 실행 구현은 `evidence-pipeline-v15`, 실행 명령은 `python -m app.worker_entrypoint_v235`입니다. v2.34의 193개 해시 고정 실행 파일과 지침 전체를 보존하며 이전 대기 작업과 재실행은 당시 실행기로 보냅니다. 분석 지침 본문과 역할, 생성 스키마, 재시도 횟수, 모델 한도, 원문 검증, Verifier 조건과 실패/불일치 보류 정책은 변경하지 않습니다.

## 확인 경로와 저장 형식

관리자 화면 **실행 → 해당 1차 분석/추가 검증 단계 → 처리 결과 → 검증을 통과하지 못한 출력**에서 시도별 기록을 펼칩니다. JSON의 같은 자료는 `output_validation_history`에 있습니다. `grounding_attempt=1/2/3`은 초기 분석/출처 교정/판정 재검토 호출이며 `attempt`는 해당 호출 안의 출력 시도입니다. 근거 번호는 그 시도 안에서만 유효하고 다른 시도의 같은 번호나 최종 API 근거 번호와 동일하다고 볼 수 없습니다.

각 스냅샷은 원래 근거 위치(`position`, 0부터), 유효한 형식의 근거/출처 번호, supports, 해석과 관련 번호만 선택합니다. 근거 최대 5개, 연결 최대 4개, 해석당 최대 2,000자와 UTF-8 JSON 인코딩 6,000바이트, 근거 스냅샷 전체 32 KiB 제한입니다. `truncated`, `omitted_evidence_count`, `interpretation_truncated`, `omitted_fields`로 저장하지 못한 부분을 알립니다. 잘못된 타입과 번호 및 임의 필드는 추측하거나 문자열로 변환해 기록하지 않습니다. 원문 발췌는 새로 복사하지 않으며 당시 입력에서 출처 번호로 확인합니다.

입력과 정책, 출처 제한은 v2.34에 위임하고 도메인 계약도 그대로 재사용합니다. 새 파이프라인은 진단 추출기를 포함한 새 실행 파일을 해시로 고정합니다. 기존 Production 구성과 Test 기본 설정, 모델 프로필 및 저장 데이터를 변경하지 않습니다. 새 후보의 운영 반영은 공식 평가와 관리자 승격 경로를 유지합니다. 별도 DB migration이나 운영 의존성 및 추가 모델 호출은 없습니다.

기존에 저장되지 않은 과거 실패 시도의 설명은 복원하지 않습니다. 실제 모델 호출과 운영 배포, 효과 측정은 이번 오프라인 검증 범위에 포함하지 않습니다.
