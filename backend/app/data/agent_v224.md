# Agent v2.24 후보 실행 계약

## 2026-11-19 지침 개정

이번 개정은 공통 지침과 과거 지침 복원 목록만 변경합니다. 실행 계약은 같은 v2.24이고 새 `fixed_rules_hash`와 `instructions_hash`로 별도 후보를 식별합니다. 직전 `prompts.py` 전체는 `legacy_prompts_v224.py`에 바이트 그대로 보존하며 파일 SHA256은 `94f166e554a46a63e3e5a8d0f7b7b361a226d97edee06e2017591e937f2dca49`입니다. 알 수 없거나 모호한 해시는 최신 지침으로 대체하지 않고 차단합니다.

판정은 관측된 내용과 결합 의미를 우선합니다. 전체 코드나 성공 결과가 없더라도 남은 근거가 공격 시도를 뒷받침하면 판단할 수 있습니다. 누락된 정보의 값에 따라 공격/정상 해석이 실제 달라지고 기존 근거로 구분할 수 없을 때만 `missing_condition_ko`에 무엇이 없어 어떤 구분이 어려운지 설명합니다. 보이지 않는 공격 구문을 정상 근거로 삼거나, 시그니처와 반복 문자열 및 잘림 추정만으로 공격을 확정하지 않습니다. 누락 구간이 정상 해석을 바꿀 구체적 이유가 있을 때는 보이는 부분의 정상성을 전체로 확대하지 않습니다.

근거 설명은 보통 1~2문장으로 값의 역할과 해석을 작성하되 복합 해석은 필요한 만큼 유지합니다. 통합 설명은 대표 근거에 한 번 작성하고 관련 발췌는 개별 기여를 설명합니다. 요약은 핵심 동작과 보안 의미, 세부 분석은 기법과 조건부 영향을 맡아 반복 생성을 줄입니다. 문장 수를 강제하거나 응답을 코드로 잘라내지는 않습니다. 필수 관련 발췌와 반대 근거, 원문 인용 규칙을 유지합니다.

공통 지침은 공백과 줄바꿈 포함 5,311→5,284자, UTF-8은 10,475→10,352바이트입니다. 기본 관리자 지침을 포함한 Primary/Verifier는 각각 5,667→5,640자, 5,691→5,664자입니다. 이벤트와 출력 JSON Schema는 제외하며 실제 토큰 수나 생성량 및 처리시간 감소를 증명하는 값은 아닙니다.

기존 실행 구현 66개 파일과 `evidence-pipeline-v5`의 SHA256 `7b7ad16e74c7b0784ad28d161f32443db4a1e304d1c03b01eccf06f6fe126830`은 그대로입니다. 파서, 내부 출력 필드와 순서, 공개 API v3, 결과 준비 조건, Verifier 실행과 실패/불일치 정책, 근거 정리 및 출력/재시도 한도는 바꾸지 않습니다. 완전 중복 제거와 정리 불필요 시 생략은 이미 구현되어 있어 추가하지 않습니다.

기존 Production 승인과 접수된 작업 및 실패 재실행은 당시 지침과 암호화 스냅샷을 유지합니다. 이전 공식 평가가 새 지침의 승인이 되지 않으며 새로운 공식 테스트와 관리자 검토 후에만 운영 반영할 수 있습니다. 관리자 편집 지침과 Test/Production 모델 설정을 변경하거나 실제 모델을 호출하지 않습니다. DB migration과 운영 의존성 추가도 없습니다.

정적 지침 검사와 합성 오프라인 회귀 테스트는 지침 보존, 독립 역할, 공개 계약 및 승인 경로를 확인합니다. 실제 Gemma/Qwen의 보류율, 잘못된 확정 판정, 첫 응답 성공률과 처리시간 효과는 별도 모델 평가가 필요합니다. 아래는 직전 구현 당시의 계약과 문자 수입니다.

## 변경 범위

- 입력 버전 `agent-input-v3`, 출처 목록 `evidence-selection-v5`, 실행 구현 `evidence-pipeline-v5`.
- 작은 입력은 기존 상한 안의 전체 후보를 한 번 구성하고 실제 JSON 크기로 검사한다. 초과하거나 원문 블록 상한에 도달하면 기존 이진 탐색으로 보완한다.
- 원문, source ID와 위치, 디코딩 링크, 입력 검사 예약 공간, 시그니처 및 등록 설명의 context 제한은 유지한다.
- 기존 v2.23 전체 지침은 `legacy_prompts_v223.py`에 동일하게 보존하고 과거 baseline은 버전과 내용 해시로 복원한다.

## 수신 사실과 누락 추정

모델 입력의 `capture_context`는 다음 사실만 기록한다.

| 필드 | 의미 |
| --- | --- |
| received_payload_bytes | 수신 문자열의 UTF-8 바이트 수. 네트워크 전체 요청 크기가 아님 |
| received_tail_submitted | 실제 수신 문자열의 마지막 구간이 모델에게 전달되었는지. 빈 문자열은 false |
| payload_omitted | 서버가 수신 payload의 일부 구간을 모델 입력에서 생략했는지 |

`input_truncated`는 기존처럼 실제 모델 입력 생략을 뜻하며 메타데이터나 파서 힌트 생략도 포함할 수 있다. 장비가 저장하기 전에 버린 내용의 추정과 혼동하지 않는다.

내부 역할 출력에만 `capture_assessment={status, reason_ko}`를 요구한다. status는 possible, no_clear_signs, unknown이고 이유는 최대 240자다. 뚜렷한 징후가 없다는 값은 완전성 확인이 아니다. 길이나 특정 한도, 반복 문자와 CVE만으로 절단이나 공격을 확정하지 않으며, 원래 불완전한 요청과 수집 누락 가능성을 함께 고려한다.

공통 지침은 5,311자로 직전 5,086자보다 225자 늘었다. 기본 관리자 지침을 포함한 Primary/Verifier는 각각 5,667/5,691자다. 이벤트와 출력 JSON Schema는 제외한 문자 수이며 실제 토큰 수나 전체 처리시간 감소를 뜻하지 않는다. 별도 누락 추정 호출은 추가하지 않는다.

추정은 암호화된 원래 출력에 보존하고 공개 결과, 평문 메타데이터 및 판정 Guard에 복사하지 않는다. 추정 자체로 Verifier를 호출하거나 자동 보류하지 않는다. 남은 요청 내용이 공격 시도를 뒷받침하면 전체 코드나 성공 결과가 없어도 판단할 수 있다. 실제로 판정을 바꿀 미확인 조건만 missing_condition_ko에 작성한다.

## 역할 실행과 실패

Primary가 성공한다는 전제에서 서버의 실제 입력 생략으로 Verifier가 필요하다고 미리 확인되는 경우만 병렬 실행한다. 같은 서버의 기존 호출 상한이 1이면 순차 처리한다. 서로 다른 서버는 각각의 공통 상한을 준수한다. WAF 허용/차단이나 수집 누락 추정만으로 검증을 먼저 호출하지 않는다.

역할별 입력과 설정은 분리하고 Verifier는 Primary 출력이나 참고 판정을 받지 않는다. 분석 Session의 단계 저장은 소유 조정기만 수행하며, 권한 및 호출 슬롯 확인은 별도의 짧은 Session을 사용한다. 각 역할이 끝날 때 해당 단계가 종료된다. 논리적 단계 번호와 실제 시간 순서가 다를 수 있으므로 단계별 시간을 합해 전체 시간으로 표시하지 않는다.

Primary 실패 시 분석 실패, 필요한 Verifier 실패나 불일치는 보류다. 취소 시 남은 로컬 작업을 회수하고 슬롯을 해제하되 원격 GPU 처리가 취소되었다고 보장하지 않는다. 실제 요청 직전에도 프로필, 권한, 내부 전송 제한 및 작업 소유권을 다시 검사한다.

출력 교정은 최초 포함 최대 4회, 인용 교정은 별도 최대 1회다. 완결 JSON의 기존 안전 복구를 유지하고 관계 중복 정리 후에도 새 capture 계약까지 재검증한다. source ID 추측, supports/판정 변경, 누락 조건 삭제나 불완전 JSON의 추정 완성으로 오류를 숨기지 않는다. JSON Schema는 기존과 같이 공급자에 전달하며 운영 vLLM의 실제 적용 여부와 모델 품질은 별도 확인 대상이다.

## 근거 정리와 결과 준비

기존 표시 작업과 처리기를 유지하며 새 실행기의 작업 풀만 제한적으로 병렬화한다. 상한은 4개이고 기존 분석 및 서버 호출 설정에 따라 더 작아진다. 기본 설정 1은 그대로다. 모든 호출은 서버별 공통 슬롯을 공유하고 설정 축소 시 새 작업만 제한한다. 진행 중인 요청을 강제로 취소하지 않는다.

핵심 근거 정리 전 API는 기존처럼 processing/result=null이다. 정리 실패의 기존 결정적 핵심 선택을 유지하며 전체 저장 근거를 대신 노출하지 않는다. API와 UI, 보고서 및 내보내기는 같은 핵심 근거를 사용한다. 조회는 작업이나 모델 호출을 만들지 않는다. 공식 평가와 운영 승격의 표시 검증 조건도 유지한다.

## 배포 및 확인 범위

실행 명령은 `python -m app.worker_entrypoint_v224`이며 Compose와 재배포 도구가 이 명령을 사용한다. 이전 명령과 엔진은 삭제하지 않는다. 이미 접수된 분석과 실패 재실행은 당시 스냅샷의 경로를 유지한다. 새 DB migration, 패키지, 외부 큐나 서비스는 추가하지 않는다.

새로 접수하는 Test는 기존 계약에 따라 최신 후보 v2.24를 고정한다. 이는 저장된 Test 모델 설정이나 이미 접수한 테스트의 지침을 변경하는 동작이 아니다. 승인된 Production은 기존 구성을 유지한다.

합성 테스트에서 입력 예산과 출처 동등성, 큰 입력 상한, 내부 필드 비노출, 병렬 완료와 취소, 기존 오류 교정, 과거 승인 및 재실행 보존과 근거 정리의 공통 제한을 확인한다. 실제 Gemma/Qwen 품질, 운영 부하와 전체 지연 감소는 이 코드 테스트로 입증하지 않는다. 운영 적용은 승인된 Ground Truth 공식 테스트와 관리자 검토 후에만 허용한다.

영구 이벤트 루프, 공유 HTTP 연결 풀, 단계 커밋 통합과 PostgreSQL/Redis 전환은 이번 구현에 포함하지 않는다. SQLite 작업 예약과 필수 진행/복구 커밋은 보존한다. 시간 진단은 각 호출의 슬롯 대기를 중복 없이 집계하되 과거 미기록 값을 0으로 채우지 않는다.
