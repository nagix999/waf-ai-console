# 테스트 처리 성능 집계

`평가 → 테스트 → 테스트 선택 → 통계 요약`의 **처리 시간과 출력**에서 선택한 문항 전체를 집계합니다. 난이도와 유형, 집계 전 필터 및 답안 기준을 적용합니다. 필드별 집계의 검색, 정렬과 페이지 변경은 성능 집계 범위를 바꾸지 않습니다.

## 표시 항목

| 항목 | 계산 기준 |
| --- | --- |
| 결과 준비 시간 | 접수부터 분석과 필요한 근거 정리 작업이 끝날 때까지 |
| 처리 시간 | 분석 시작부터 판정 처리 종료까지. 앞선 접수 대기는 제외 |
| P95 | 측정값을 정렬했을 때 95% 위치에 있는 시간 |
| 첫 호출 시간과 출력 토큰 | 역할의 최초 출력 시도 기록 |
| 전체 출력 토큰 | 같은 문항의 해당 역할에서 출력 재시도, 원문 교정 및 기록된 조건부 근거 재검토까지 합산 |
| 재시도 문항 | 해당 역할에서 출력 재시도가 한 번 이상 기록된 문항 |
| 출력 재시도 시간 | 첫 시도 이후 출력 교정 시도의 시간 합계 |
| 원문 교정 시간 | 근거 출처를 교정하는 후속 호출의 시간 |
| 근거 재검토 | 출처 교정 후 남은 근거로 판정을 다시 검토한 문항 수와 평균 시간. 해당 문항이 있을 때만 표시 |
| 모델 대기 | 서버의 동시 호출 슬롯을 기다린 시간 |
| 근거 정리 대기와 처리 | 판정 이후 별도로 진행하는 정리 작업의 시간 |
| 오류 사유 | 저장된 출력 검증 오류를 항목과 유형별로 집계 |

각 평균과 P95는 해당 측정값이 있는 문항으로 계산합니다. 미기록은 0으로 채우지 않습니다. 토큰 합계는 모든 시도의 사용량이 기록된 문항만 포함하며, 일부 시도의 사용량이 없으면 그 문항의 총량은 미기록입니다. 첫 출력량과 전체 출력량의 기록 문항 수가 다르면 두 평균의 차이를 재시도 출력량으로 해석할 수 없습니다. 출력 검증 실패, 출력 한도 초과 및 응답 시간 초과는 시도 횟수로 구분합니다. 한 문항에서 여러 오류가 나올 수 있으므로 오류 사유별 건수의 합계는 재시도 문항 수와 다를 수 있습니다.

단계별 시간과 재시도 시간은 서로 포함되거나 병렬로 겹칩니다. 이들을 더해서 전체 시간이라고 해석하면 안 됩니다. 모델 시도 시간에는 통신과 출력 검증이 포함되므로 순수 GPU 생성 시간이 아닙니다. 이 집계만으로 출력 토큰 증가가 지연의 원인이라고 확정하지 않습니다.

실패 항목을 재실행하면 문항별 결과와 같은 최신 실행을 사용합니다. 저장한 평가를 선택하면 해당 평가가 선택한 실행을 따릅니다. 이전 실패 실행과 새 성공 실행을 서로 다른 문항으로 중복 집계하지 않습니다. 처리 중인 문항에 남은 이전 실행 기록도 현재 실행 시간으로 섞지 않습니다.

## 관리자 조회 API

```http
POST /api/v1/test-runs/{run_id}/performance-summary
Content-Type: application/json
```

```json
{
  "reference_basis": "latest",
  "difficulty": "hard",
  "case_filter": null
}
```

기존 `TestReadScope`의 `evaluation_id`, `reference_basis`, `difficulty`, `test_category`, 각 미입력 필터와 `case_filter`를 사용합니다. 그룹 집계, 페이지 및 정렬 조건과 URL query parameter는 받지 않습니다. 관리자 인증이 필요하며 응답은 `Cache-Control: no-store`입니다. 서비스 API Key에 접근 권한을 추가하지 않습니다.

응답 버전은 `test-performance-summary-v1`입니다. `cases`, `statuses`, `timings`, `phases`, `roles`, `display`에 집계값을 제공합니다. 역할별 `tokens.first_attempt_output_tokens`와 `tokens.output_tokens`를 비교해 첫 답변 생성량과 재생성으로 늘어난 양을 구분할 수 있습니다. 문항별 원문이나 모델 출력, 암호문, 임의 오류 메시지는 반환하지 않습니다.

v2.31 조건부 재검토는 역할별 `decision_review_ms`, `reported_decision_reviews`, `cases_with_decision_reviews`로 구분합니다. 원문 교정 시간에는 재검토를 합치지 않으며 전체 시도와 토큰 및 대기에는 중복 없이 포함합니다. 호출 수와 문항 수를 구분하고, 과거 미기록은 0으로 추정하지 않습니다. `evidence_grounding_retry`의 인식 가능한 재검토 표식과 시도 기록이 있는 경우만 집계합니다. 이 추가는 관리자 통계 응답에만 적용하며 공개 분석 v3 필드는 바꾸지 않습니다.

성능 자료는 별도 요청으로 가져오므로 필드별 집계의 페이지나 정렬을 바꿀 때마다 다시 계산하지 않습니다. 선택 범위가 바뀌거나 다시 조회할 때 갱신하며, 진행 중인 분석과 근거 정리 작업은 화면이 보이는 동안 주기적으로 확인합니다.

DB migration, 운영 의존성, 모델 호출 및 공개 분석 응답 v3 변경은 없습니다. 저장된 실행 수치와 허용된 오류 유형만 SQL에서 추출하며 원문 및 단계 이력을 복호화하지 않습니다.

## 검증 기록

- 새 집계 관련 backend 테스트 14건과 기존 시간 진단, 실행 통계, 문항 필터 및 통계 내보내기 회귀 테스트 139건이 통과했습니다. 전체 backend 테스트 모음을 실행한 것은 아닙니다.
- 프런트엔드 전체 테스트 790건이 통과했고, 이후 추가한 출력 실패 유형 표시와 읽기 전용 조회의 갱신 처리 관련 테스트 11건도 통과했습니다. 두 실행은 중복 테스트를 포함하므로 합산하지 않습니다. 최종 production build도 통과했습니다.
- 실제 React 화면을 합성 API 응답으로 실행해 SK/Light/Dark, KR/EN, 모바일 넘침, 키보드 조회, 집계 범위 변경, 그룹 페이지 이동, 누락 및 오류 표시와 늦은 응답 차단을 확인했습니다. 브라우저 오류와 외부 요청은 없었으며 스크린샷 8장을 저장했습니다.
- 합성 508건에서 SQL 8회로 집계했습니다. 동시 테스트 부하에서 약 2~3.7초가 측정됐으며 운영 환경의 처리 시간 보장은 아닙니다.
- 기존 Starlette/AnyIO deprecation 경고와 프런트엔드의 큰 번들 경고는 남아 있습니다. 운영 DB 및 실제 모델을 사용한 검증, 서비스 재배포와 Git 업로드는 수행하지 않았습니다.
