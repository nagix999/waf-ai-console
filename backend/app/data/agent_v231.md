# v2.31 남은 근거로 판정 재검토

## 목적

출처 교정 전후 기록은 정탐인데 최종 출력만 보류로 바뀌는 경우가 있습니다. 교정 결과의 `requires_reanalysis=true`는 기존 해석을 그대로 사용할 수 없다는 뜻이며, 그 중간 판정이 최종 검증을 통과했다는 뜻은 아닙니다. 기존 보류 처리는 유지하되 일부 근거가 잘못됐다는 이유로 독립적으로 확인된 다른 근거까지 일괄 제외하는 경로를 줄입니다.

시그니처를 공격/정상 요청 근거로 허용하지 않습니다. 시그니처는 장비의 탐지 기록이고 등록 설명은 규칙의 일반 정보이며, 둘 다 `context`로 판정에 참고합니다. 탐지된 사실과 요청에서 공격을 확인한 사실, 일반 설명과 실제 관측을 구분합니다. 공통 지침은 두 줄만 바꾸며 4,513→4,593자입니다. 실제 토큰 변화나 모델 순응도를 측정한 수치는 아닙니다.

## 처리 순서

1. 기존처럼 초기 구조화 출력, 원문 위치와 제출 범위 및 출처 역할을 검사합니다. source ID만 잘못됐다면 기존 출처 교정 1회를 사용합니다.
2. 교정 후에도 출처가 맞지 않거나 재해석이 필요한 근거는 제외합니다. 이를 필수 근거로 참조한 해석도 반복 확인하여 제외합니다. 명백히 같은 원문/해석/분류의 별칭도 함께 제외합니다. 순환 관계도 반복 없이 처리합니다.
3. 다른 독립 근거는 유지합니다. 한 그룹의 필수 원문을 잃었다는 이유만으로 별도의 유효 그룹까지 제거하지 않습니다. 어느 그룹이 잘못됐는지 모호하거나 실제 요청에 연결된 공격/정상 근거가 하나도 없으면 기존 보류를 유지합니다.
4. 초기 생성과 출처 교정을 완료했고 시도 및 입력 예산을 확인할 수 있을 때만 같은 역할과 프로필로 남은 근거를 최대 1회 재검토합니다. Primary의 재검토에 Verifier 출력은 전달하지 않습니다.
5. 재검토 모델은 남은 모든 근거 번호와 새 판정/확신도/요약/세부 분석/실제 미확인 조건/해석 충돌 여부만 반환합니다. 모든 근거를 유지해야 하며, 반대 근거 삭제나 source ID/해석/분류/의존 관계 변경은 허용하지 않습니다. 순서는 서버의 기존 순서를 사용합니다. 해석이나 분류를 바꿔야만 확정할 수 있으면 보류하도록 안내합니다.
6. 원래 근거와 결합해 전체 출력 계약, 실제 원문과 출처 역할 및 판정 방향을 다시 검사합니다. 통과하면 새 판정을 사용하고, 재검토 실패나 불완전 출력이면 기존 안전한 보류를 유지합니다. 선택적 재검토 실패만으로 완료 가능한 분석 전체를 실패시키지 않습니다.
7. 필요한 Verifier의 실패나 두 역할의 판정 불일치는 여전히 최종 보류입니다. 이후 핵심 근거 선택, 표시, API와 보고서는 최종 유효 근거 및 관계를 사용합니다.

예를 들어 시그니처에만 연결된 주장 A와 A에 의존한 해석 B, 독립적으로 원문을 확인한 해석 C가 있으면 A/B는 제외하고 C로 판정을 재검토합니다. C가 공격 방향이라는 이유만으로 정탐을 자동 유지하지 않습니다. 남은 정상 방향 근거가 있다면 함께 전달하며, 모델은 정탐/오탐/보류 중 다시 판단합니다.

## 호출과 입력 예산

기존 최초 포함 구조화 출력 최대 4회와 출처 교정 최대 1회의 **논리 시도 합계 5회**를 늘리지 않습니다. 예를 들어 초기 3회와 출처 교정 1회를 사용했다면 재검토 1회가 가능하고, 초기 4회와 교정 1회를 사용했다면 불가능합니다. 시도 기록이 누락되거나 일관되지 않아도 추가 예산을 추정하지 않습니다.

재검토 자체의 출력 검증 시도, 프레임워크 턴과 전송 시도는 각각 최대 1회입니다. 기존 초기/출처 호출의 provider 전송 재시도는 별도이므로 위의 논리 5회가 기존 전체 HTTP 전송 횟수라는 뜻은 아닙니다. 프로필의 출력 토큰 한도와 제한 시간은 바꾸지 않습니다.

재검토에는 남은 검증된 원문 후보와 고정된 해석, 기존 서버의 수집 관측만 제공합니다. 잘못된 판정과 요약/영향 설명은 중립 값으로 대체합니다. 새 원문 범위를 추가하지 않으며 원래 역할의 예약된 입력 예산 안에서 한 번 직렬화합니다. 초과하면 근거나 반대 정황을 잘라내지 않고 재검토를 건너뜁니다. 모델 지시와 원문/해석의 비신뢰 데이터 경계를 구분합니다.

기존 `signature_assessment`와 `capture_assessment`는 이전 모델의 비교/추정 기록으로 보존합니다. 해당 문장을 새로운 요청 관측으로 사용하지 않도록 지시하지만, 의미를 코드로 검증하거나 제외된 해석의 문구가 이 기록에 전혀 없다고 보증하는 것은 아닙니다. 원문 연결 검증도 해석의 의미적 타당성을 증명하지 않습니다.

## 기록과 집계

- 초기와 출처 교정의 암호화된 grounding 기록은 수정하지 않습니다. 재검토는 세 번째 `kind=decision_review` 기록으로 추가하며 최종 유효 출력/출처/관계를 같은 기록에서 일치시킵니다. 중간 `resolved_output`의 판정과 서버 최종 판정이 다른 이유를 추적할 수 있습니다.
- 재검토 결과와 관계를 소비하는 어댑터만 새 버전으로 구분합니다. 이전 인덱스를 새 목록에 그대로 적용하거나 다른 역할의 근거로 대신하지 않습니다.
- 기존 grounding 메타데이터의 `recovered`는 출처 교정 성공을 뜻합니다. 재검토 성공과 혼동하지 않도록 별도 `evidence_decision_review` 메타데이터에 버전/시도/복구/생략 사유를 기록합니다. 강제 보류 요약은 출처 역할 문제, 필수 관계 누락, 방향성 근거 없음 또는 재검토 실패를 구분하는 고정 문구입니다.
- 테스트 처리 시간 집계의 역할별 추가 숫자는 `decision_review_ms`, `reported_decision_reviews`, `cases_with_decision_reviews`입니다. 근거 연결 교정과 분리하고 전체 시도/토큰에는 중복 없이 포함합니다. 누락된 과거 값은 0으로 만들지 않습니다. 해당 문항이 있을 때만 기존 UI 표에 근거 재검토 문항 수와 평균 시간을 표시합니다. 새 탭이나 공개 분석 응답 필드는 추가하지 않습니다.

## 보존과 적용

고정 지침은 `waf-system-v2.31`, 기본 저장 지침은 `waf-judgment-v2.31`, 구현은 `evidence-pipeline-v12`, 실행기는 `app.worker_entrypoint_v231`입니다. 기본 초기 출력의 필드와 생성 스키마는 v2.30과 같고, 별도의 축소된 재검토 출력 계약만 내부에 추가합니다.

이전 공통 지침을 `legacy_prompts_v230.py`에 바이트 단위로 보존합니다. v2.30의 146개 실행 파일과 개별 파일 해시 및 manifest 해시 `9ba048d9570ed1b9e9aad103276bb1aa7cf58209cf1080d234791d62c9f6462f`는 유지합니다. v2.31은 새 15개 파일을 더한 161개 파일로 고정합니다.

공개 API `waf-analysis-v3`, DB와 migration, 운영 의존성, 보안 및 egress 검사, 동시 처리 제한, 과거 실행/실패 재실행과 운영 승인 경로는 유지합니다. 새로운 관리 통계 필드 외에 API 변경은 없습니다. 배포 설정이 새 실행기를 가리키더라도 승인된 Production 지침은 자동으로 바뀌지 않습니다. 개선 비교는 새 후보의 공식 테스트에서 진행하며 승인 Ground Truth 평가와 관리자 운영 승격이 필요합니다.

## 검증 범위와 제한

합성 원문과 모의 provider 응답으로 실제 ModuAgent 경로를 검사합니다. 잘못된 시그니처 주장 제외, 독립 그룹 보존, 필수 관계의 전이 제외, 반대 근거 누락 거절, source/분류/해석 불변, 입력과 시도 예산, 실패한 선택적 재검토의 안전한 보류, 필요한 Verifier 실패/불일치를 포함합니다. 공개 v3와 내보내기, 운영 승격/재실행, 과거 버전 해시 및 통계와 프런트엔드도 회귀 검사합니다.

실제 Gemma 품질과 실패율/보류율/정확도 및 지연시간 변화는 아직 검증하지 않았습니다. 정상 경로에는 추가 호출이 없지만 오류 사례는 호출이 하나 늘 수 있습니다. 실패가 보류로 바뀐 것만으로 품질 향상을 판단하지 않으며 실제 모델 비교에서 잘못된 확정 판정 증가 여부도 함께 확인해야 합니다. 이번 작업은 실제 LLM 호출, Production 설정 변경, Docker 재배포와 Git 업로드를 포함하지 않습니다.

최종 관련 검증은 신규 계약/실행기/worker/지침 및 도우미 118건, 버전 보존/공통 실행/처리 시간 통계 등 295건, 공개 v3/핵심 근거/내보내기/운영 승격/재실행 등 125건이 통과했습니다. 별도 배포 스크립트 22건, 프런트엔드 관련 테스트 13건과 production build 및 `git diff --check`도 통과했습니다. 마지막 수정 후 보존/라우팅 50건을 다시 확인했으며 위 295건과 중복이므로 합산하지 않습니다. 전체 백엔드/프런트엔드 테스트 모음을 모두 실행한 것은 아닙니다.

실제 PDF 렌더링 1건은 릴리스 이미지 전용 옵션 미지정으로 건너뛰었습니다. 기존 Starlette/AnyIO deprecation 경고와 프런트엔드의 큰 번들 경고는 남아 있습니다. 이번 작은 통계 표시 변경에 대한 실제 브라우저 화면 검토는 수행하지 않았습니다. DB 스키마 변경이 없어 migration 실행은 추가하지 않았습니다.

최종 v2.31 manifest는 161개 파일이며 해시는 `f897189ddc2ff13eb465be81ad4bde092833c76c4a20e08564303a79dcca48cc`입니다. 기존 146개 파일과 원본 지침의 바이트 보존을 확인했습니다. 시작 commit은 `ec731b4`이며 과거 버전의 코드나 데이터는 제거하지 않았습니다.
