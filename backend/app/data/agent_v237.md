# v2.37 통합 해석과 참고 원문 연결 후보

> 2026-11-27: 운영 서버의 테스트에서 실패와 지연이 증가했다는 보고에 따라 신규 기본값에서 철회했다. 새 테스트는 v2.36을 사용하며 아래 내용은 기존 실행의 호환과 감사용 계약이다. [복원 범위](agent_rollback_v236.md)를 참고한다.

## 적용 범위 (철회 이전 계약)

고정 지침은 `waf-system-v2.37`, 실행기는 `app.worker_entrypoint_v237`, 실행 구현은 `evidence-pipeline-v17`이다. 입력은 기존 `agent-input-v4`, 원문 후보 목록은 `evidence-selection-v5`, 암호화된 관계 기록은 `evidence-relations-v1`을 유지한다.

v2.37은 당시 새 후보였다. 승인된 Production과 Test 기본 설정을 자동 변경하지 않으며 **후보 테스트 → 승인된 Ground Truth 공식 평가 → 운영 반영 검토 → 관리자 승격**을 거쳐야 운영에 적용할 수 있는 계약이었다. 코드 배포가 지침 승격을 대신하지 않는다. 과거 접수와 실패 재실행은 당시 고정 지침과 구현을 유지하고, v2.20부터 v2.36까지의 고정 실행 파일을 수정하지 않는다.

당시 Test 기본 설정의 프로필과 정책 선택은 그대로였으며 새 접수에 v2.37의 고정 지침을 저장했다. 철회 후 새 테스트는 v2.36을 사용한다. 이미 접수한 Test와 과거 실패 재실행의 지침을 소급 변경하지 않는다.

DB migration과 새 패키지 또는 외부 서비스 의존성은 없다. 공개 분석 API `waf-analysis-v3`의 필드와 타입은 유지한다. 파서 메타데이터의 `engine_version`에는 이미 구현한 `http-capture-v2` 허용값을 추가한다. 내부 생성 스키마와 공개 응답 스키마는 서로 다른 계약이다.

## 해석과 참고 원문 구분

모델의 `evidence`는 해석과 필요한 원문 기여를 합쳐 역할별 최대 5개인 평면 목록이다. 각 항목에는 기존 `evidence_id`, `source_id`, `interpretation_ko`, `supports`를 유지하고 연결 필드만 `related_evidence_ids`에서 `contributes_to_evidence_ids`로 바꾼다.

| 항목 | 연결 목록 | 분류와 설명 |
| --- | --- | --- |
| 독립 해석 | `[]` | 공격/정상/참고 중 타당한 방향. 관측과 결합 의미 및 그 방향을 뒷받침하는 이유를 설명 |
| 참고 원문 기여 | 이번 목록의 독립 해석 번호 1~4개 | `context`만 허용. 해당 값이나 위치가 대상 해석에 제공하는 정보를 설명 |

빈 연결 목록이 반드시 공격 또는 정상 해석을 뜻하지 않는다. 보류 상황이나 필요한 참고 해석도 `[]`를 사용한다. 참고 원문을 참조한다는 이유로 독립적인 방향 해석을 `context`로 낮추지 않는다. 하나의 중립 기여를 공격 해석과 정상 해석이 함께 사용할 수 있으며, 독립적인 반대 해석이 있다는 이유만으로 연결 분류 오류를 만들지 않는다.

불필요한 관측이나 같은 논점을 표현만 바꿔 추가하지 않는다. 필요한 원문이 하나면 하나로 충분하다. 반대로 여러 원문이 필수라면 개수를 줄이려고 버리거나 서로 다른 발췌를 합성하지 않는다. 독립적인 공격 또는 정상 주장은 참고 기여 안에 숨기지 않고 별도 해석으로 작성한다.

기여 항목끼리의 연결, 자기 연결과 없는 번호는 허용하지 않는다. 같은 유효 대상 번호의 단순 반복만 순서를 유지해 정리하고 전체 계약을 다시 검증한다. 해석, 분류나 출처를 서버가 의미에 따라 바꾸는 복구는 하지 않는다.

## 기존 근거 처리와 API 연결

모델과 서버 내부 관계의 방향은 다음처럼 다르다.

```text
모델 출력: 참고 원문 e2 → 이 원문이 뒷받침하는 해석 e1
서버 내부: 해석 e1 → 이 해석에 필요한 원문 e2
```

서버가 기여 목록을 뒤집어 기존 `related_evidence_ids` 관계로 변환한 뒤 `SecurityAnalysisOutputV234.model_validate`의 엄격한 검증을 수행한다. 검증을 건너뛴 객체 생성이나 분류 자동 변경을 사용하지 않는다. 항목과 순서, 원문 번호, 설명과 분류는 그대로이고 새 항목을 복제해 만들지 않는다.

기존의 출처 존재 여부와 실제 제출 구간, 원문 일치, `allowed_supports`, 확정 판정의 요청 내용 근거 및 판정/심각도 정합성 검사를 유지한다. 시그니처와 등록 설명은 계속 참고 내용 전용이다. 여러 원문을 연결했다는 이유로 시그니처를 공격/정상 요청 근거로 사용할 수는 없다.

최종 v3 근거의 `field`, `excerpt`, `source_spans`, `origins`, 역할별 근거와 판정 조건 참조는 기존 생성 경로를 따른다. 하나의 공개 근거 객체에 서로 다른 발췌를 이어 붙이거나, 다른 모델의 문장을 실제 작성 출처로 바꾸지 않는다. 선택적 근거 정리와 핵심 근거 선택 및 UI/보고서/다운로드의 공통 응답도 유지한다.

출처 교정에 실패한 기여는 이를 필요로 하는 해석과 함께 제외한다. 독립적인 다른 해석과 중요한 반대 근거는 남긴다. 한 해석만 제외되면 공유 기여는 살아 있는 다른 연결을 유지하며, 기여 대상이 모두 사라지면 그 항목도 제외한다. 고립된 참고 기여를 새 독립 해석으로 취급하지 않는다. 남은 근거의 판정 재검토는 모든 살아 있는 근거와 연결을 고정한 상태에서 기존 한도 안에서만 수행한다.

## 기존 교정 재시도

별도 연결 검토 LLM이나 정상 경로의 새 필수 호출은 추가하지 않는다. 초기 구조화 출력과 내용 오류는 최초 포함 최대 4회, 출처 교정은 기존 최대 1회이며 남은 근거의 판정 재검토도 기존 합계 논리 시도 예산을 늘리지 않는다. 두 역할은 각각 자신의 출력만 교정하고 Primary 결과를 Verifier에 전달하지 않는다.

완결 응답에서 기여 분류나 기여 대상 및 번호 오류가 발견되면 `evidence_contribution_correction`을 기존 교정 입력에 추가할 수 있다. 이 자료는 같은 시도의 전체 근거와 당시 판정 및 시도 번호를 담은 비신뢰 초안이다. 해석은 항목당 최대 2,000자이며, 별도 초안 한도는 JSON 16,000자 및 UTF-8 32 KiB다.

원래 입력과 전체 초안을 합쳐 기존 입력 문자 예산 안에 들어갈 때만 전달한다. 설명을 잘라 보내거나 반대 근거를 일부만 골라 빼지 않고, 공간을 만들려고 원문 입력을 줄이지 않는다. 구조나 예산 조건을 만족하지 않으면 초안 없이 기존 교정을 사용한다. 화면용으로 제한하여 저장한 진단 스냅샷을 교정 원본으로 재사용하지 않는다.

`length/max_tokens` 등 출력 중단과 거절, 모호하거나 불완전한 JSON을 완결 초안으로 취급하지 않는다. 새 완결 응답이 나오거나 출력이 중단되면 과거 초안과 번호를 그대로 이어 쓰지 않는다. 필요한 Verifier의 실패/판정 불일치 보류 및 최종 판정 정책을 유지한다.

## 관리자 실패 기록

`rejected-evidence-v2`는 같은 시도의 근거 번호, 출처, 분류, 해석과 `contributes_to_evidence_ids`만 선택해 암호화된 단계 처리 결과의 `output_validation_history`에 저장한다. 최대 근거 5개, 연결 4개, 해석당 2,000자와 JSON 인코딩 6,000바이트 및 스냅샷 32 KiB 제한을 적용하고 생략/절단을 표시한다. 불완전하거나 거절된 응답과 provider 본문, 숨겨진 추론 및 임의 필드는 저장하지 않는다.

조회 위치는 **실행 → 해당 모델 단계 → 처리 결과 → 검증을 통과하지 못한 출력**이다. 새 기록은 **이 원문이 뒷받침하는 해석**, 기존 v1 기록은 **이 해석에 필요한 근거**로 표시한다. 과거 기록의 방향을 새 의미로 바꿔 읽지 않으며 재시도 성공 뒤에도 실패 시도는 구분해 남긴다. 검증에 실패한 자료는 최종 판정의 근거가 아니다.

실제로 추가한 교정 초안도 `next_retry_context`에 암호화해 저장한다. 관리자 권한과 열람 감사 및 캐시 금지 정책을 유지하며 일반 로그, 평문 메타데이터/통계와 공개 v3 및 보고서에는 해석 문장을 노출하지 않는다. 과거에 저장하지 않은 설명을 복원하거나 다시 모델에 요청하지 않는다.

## 수집 구분자와 파서 호환

기존 v2.36의 선택형 수집 경계 처리를 그대로 사용한다. 확인된 벤더 프로필에서만 `field_separator=slash_at_slash`를 선택하고, 기본값과 미등록/모호한 형식은 원문을 유지한다. 원문 발췌 위치와 디코딩 연결, 수신 UTF-8 바이트 수와 실제 끝부분 전달 여부를 보존하며 구분자 제외를 입력 예산 절단으로 집계하지 않는다.

실제 헤더 값이 수집 경계와 같은 모양이면 자동으로 구별할 수 없다. 장비가 `/@/`를 예약하고 실제 값의 같은 문자열을 이스케이프하거나 별도로 구별한다는 사실을 확인한 경우에만 선택해야 한다. 이 변경은 벤더명이나 문자열 등장만으로 구분자를 자동 삭제하는 기능이 아니다. 자세한 지원 범위와 설정 경로는 [v2.36 계약](agent_v236.md#선택적-수집-구분자-처리)을 따른다.

파서 메타데이터의 새 엔진 값은 엄격한 v3 저장/응답과 구형 v2 호환 변환 및 보고서 경로에서도 허용한다. 원래 옵션은 공개 응답에 포함하지 않고 버전, 엔진과 내용 해시만 반환한다. 기존 `generic-http-v3`, `http-capture-v1`과 과거 v1/v2 결과는 다시 쓰지 않는다.

## 검증 범위와 남은 제한

합성 데이터와 모의 응답으로 내부 연결 계약, 엄격한 변환, 필수 출처의 제외 전파와 공유 기여, 기존 교정 예산 및 실패 기록의 저장/표시를 확인한다. 과거 버전의 해시와 실행 분기 및 공식 평가/운영 승인 경로, 새 파서 메타데이터의 v3/구형 응답 호환성도 회귀 검증 대상으로 둔다. 실제 수행한 테스트와 빌드 결과는 작업 완료 보고에 구분해 기록한다.

2026-11-26 오프라인 검증 결과:

- 관련 Backend 32개 테스트 파일에서 529건 통과, 별도 release 이미지가 필요한 기존 PDF 렌더러 검사 4건 제외
- 빈 DB의 Alembic head 적용과 기존 데이터가 있는 DB의 업그레이드 검사 통과
- Frontend 전체 898건과 Vite build 통과, 배포 스크립트 단위 검사 23건 통과
- 기존 v2.36 고정 실행 파일 220개의 SHA와 지침 원본 바이트 일치, `diff --check` 통과

Backend 전체 검사는 기존 장시간 대기 사례 때문에 중단했고 위의 변경 관련 회귀 검사를 완료했다. 기존 Starlette/AnyIO 폐기 예정 API 안내와 Frontend 번들 크기 경고가 남아 있다. 실제 PDF 렌더링, 브라우저 시각 검토와 실제 모델 품질 검증을 수행한 것으로 간주하지 않는다.

참고 기여를 모델이 `context`라고 작성했다는 사실만으로 그 설명이 실제로 중립적임을 서버가 증명할 수는 없다. 독립적인 공격/정상 주장을 잘못 참고 기여로 작성하는 의미 오류는 실제 모델 평가가 필요하다. 자동 분류 변경이나 검사 제거로 이를 숨기지 않는다.

실제 Gemma/vLLM의 판정 품질, 실패율과 보류율, 출력 토큰 및 전체 처리시간 개선은 미검증이다. 기존 교정 횟수는 늘리지 않지만 오류 사례의 입력 길이는 증가할 수 있다. 새 구조가 모든 근거를 하나로 합치거나 실패율과 지연을 특정 수치로 낮춘다고 보장하지 않는다. 이번 작업에서는 운영 데이터를 읽거나 실제 모델 호출, 유료 검증, 재배포와 Git 업로드를 수행하지 않는다.
