# v2.26 후보: 요청 행위 분석과 구조화 출력 최적화

시작 commit은 `1643f4f`입니다. 현재 내부 출력 `SecurityAnalysisOutputV224`, 공개 `waf-analysis-v3`, 파서와 독립 Verifier 및 최종 결합 정책을 유지합니다. DB migration이나 새 운영 의존성은 없습니다.

## 공통 지침

첫머리에서 WAF 탐지 이벤트를 검토하는 보안 관제 분석가의 업무를 정의합니다. 대상과 동작 및 값의 역할을 파악하고, 개별 관측과 필요한 결합 문맥을 해석합니다. 중요한 반대 근거와 실제로 판정을 바꿀 미확인 조건을 검토한 뒤 근거를 분류하고 판정과 요약을 작성합니다.

근거 설명은 관측 내용과 요청에서의 역할 및 공격/정상 해석의 이유를 연결합니다. 사실의 단순 존재나 프로토콜 형식 소개로 끝내지 않으며 양쪽 근거, 가능성과 보류 조건을 억지로 만들지 않습니다. 상세 사고 과정을 추가 출력하거나 새로운 모델 단계를 만들지 않습니다.

WAF 탐지는 검토할 공격 가설의 맥락입니다. 탐지 또는 차단 사실 자체는 공격 증거가 아니고 해당 시그니처와 맞지 않는다고 전체 요청이 정상인 것도 아닙니다. 시그니처와 설명은 계속 context로만 인용합니다. 관측된 동작을 보안 지식으로 해석하되 보이지 않는 목적, 신원, 권한, 환경과 서버 처리 또는 누락된 공격 코드를 만들지 않습니다.

Primary는 요청 행위와 결합 문맥에서 핵심 근거를 선택합니다. Verifier는 같은 원본을 독립 분석하고 자신의 근거에 과장, 성급한 정상 해석과 불필요한 보류가 있는지 점검합니다. Primary의 답변을 받지 않으며 공통 판정 기준은 같습니다. 관리자 편집 지침과 모델 배정을 자동 변경하지 않습니다.

지침과 스키마 크기 측정은 다음과 같습니다. 공백/줄바꿈을 포함하고 실제 tokenizer 측정은 아닙니다. 이벤트와 재시도 안내는 제외합니다.

## 출력 안정성

ModuAgent 0.6.2는 기존부터 두 provider에 `response_format.type=json_schema`와 `strict=true`를 전송합니다. 이번 변경은 Guided Decoding을 처음 도입하는 것이 아닙니다. v2.26의 현재 모델과 구조화 복구 경로에 한해 스키마 준비를 일치시킵니다.

- 기존 OpenAI strict 어댑터와 동일하게 기본값 주석을 제거하고 모든 객체 키를 required로 명시합니다. nullable의 null 허용은 유지합니다.
- 중첩된 title 주석만 제거합니다. 응답 형식 이름인 최상위 title과 실제 속성/정의 이름, description, 참조, enum/const 및 모든 검증 제한은 보존합니다.
- 모델 결과는 기존 도메인 codec과 전체 Pydantic 검증을 통과해야 합니다. 의미를 추측해 enum, supports, 판정이나 설명을 교정하지 않습니다.
- 오류 필드의 타입, 허용값, 범위와 길이 및 배열 개수를 실제 신뢰된 스키마에서 추출해 다음 교정 요청에 전달합니다. 임의 예외 메시지나 모델 출력값은 사용하지 않습니다.
- 기존 최초 포함 최대 4회와 전송 재시도 상한, 출력 토큰 및 제한 시간은 유지합니다. 실패한 출력 전체를 교정 입력에 덧붙이거나 대화가 누적되지 않습니다.
- BOM/전체 코드펜스와 완결 JSON 처리, 손실 없는 근거 관계 복구는 재사용합니다. 불완전 JSON과 의미가 모호한 관계를 추측해 성공시키지 않습니다.

구조화 실행 메타데이터에는 고정된 `schema_preparation=schema-guided-output-v1`과 `compact_strict_wire_schema=true`를 기록합니다. 교정 버전은 `structured-output-repair-v6`입니다. 공개 API에는 새 필드를 추가하지 않습니다.

## 보존과 적용

직전 `prompts.py` 전체는 `legacy_prompts_v225.py`에 바이트 단위로 보존했습니다. SHA-256은 `251518da4b037532a18dfbe6e4fcf52dcfc9695ca7fce977a5b6f2059441fd75`입니다. v2.25의 기존 78개 artifact 파일도 수정하지 않으며 해시는 `c4d9ea4d9eac15f00bfc474f4c33a1830a3ead303fa269a7b775e96ed9490a65`입니다.

새 후보는 `waf-system-v2.26` 및 `waf-judgment-v2.26`, 실행 구현은 `evidence-pipeline-v7`로 식별합니다. manifest는 기존 78개와 신규 12개 파일을 고정하며 입력/출처/관계 계약은 같은 버전을 사용합니다. 새 실행기 `python -m app.worker_entrypoint_v226`은 암호화된 스냅샷에 따라 이전 실행과 새 후보를 구분합니다. Compose와 배포 도구의 실행 명령을 연결하되 코드 변경 자체가 재배포는 아닙니다.

기존 승인과 대기/실패 재실행은 당시 지침과 실행 해시를 사용합니다. 새 후보의 평가를 이전 버전 평가로 대신하지 않으며 승인된 Ground Truth 공식 테스트와 관리자 운영 검토 후에만 Production에 반영합니다.

## 검증과 제한

검증은 합성 입력과 모의 HTTP 전송을 사용하는 격리된 Python 3.12 환경에서 수행합니다. 실제 운영 데이터와 유료 API는 호출하지 않습니다. 테스트는 스키마 제약과 검증 및 호출 계약을 확인하며 실제 모델의 해석 품질을 점수화하는 평가가 아닙니다.

실제 Gemma/vLLM의 첫 시도 성공률과 최종 실패율, 판정 정확도, 사실 나열 감소 및 처리시간 개선은 모델 평가 전까지 미검증입니다. 기존 출력 계약의 의미적 의존 조건과 근거 관계는 JSON Schema만으로 모두 강제되지 않으며 최종 서버 검증이 계속 필요합니다.

2026-11-23 검증 결과입니다. 아래 묶음에는 일부 같은 테스트가 포함되므로 건수를 합산하지 않습니다.

- 출력 스키마와 오류 교정, 기존 JSON 및 관계 복구, OpenAI와 의미 계약 관련 6개 모듈 316건 통과. 실제 ModuAgent 0.6.2의 모의 HTTP 요청으로 두 provider의 전송 본문과 교정 요청을 확인했습니다.
- 새 실행과 이전 실행의 라우팅, 작업 소유권과 취소, 고정 입력 및 지침, 실패 재실행과 공식 평가/운영 승인 관련 통합 검증 186건 통과. 승인된 v2.25 baseline이 배포 후에도 같은 지침과 코드로 복원되는 것을 포함합니다.
- 후보 구성과 Production 승인, 일반 테스트와 API 핵심 근거, egress 및 입력 보호 관련 24개 모듈 705건 범위를 검증했습니다. 입력 보호 문장의 정확한 표현 검사는 문구를 보완한 뒤 재검증했으며 최종 유효 결과는 703건 통과, 기존 선택 실행 조건에 따른 2건 건너뜀입니다.
- 마지막 지침 수정 후 입력 보호와 공통 지침, 과거 버전 보존 및 편집 지침 관련 17개 모듈 444건 통과. 위 범위와 겹치는 테스트가 포함됩니다.
- 배포 도구 단위 테스트 22건과 `git diff --check` 통과. 기존 v2.25 artifact의 78개 파일과 해시는 동일하고 신규 artifact는 90개 파일을 포함합니다.
- 전체 backend 테스트 전수 실행이나 프런트엔드 build는 이번 작업에서 수행하지 않았습니다. 프런트엔드와 DB schema는 수정하지 않았고 실제 모델 호출, 운영 설정 변경, Docker 재배포와 Git 게시도 수행하지 않았습니다.
