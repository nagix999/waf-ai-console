# 시그니처 설명 관리

관리자가 등록한 시그니처 설명은 WAF의 탐지 의도를 해석하는 참고 정보다. 실제 요청에서 관찰한 공격 구문이나 정오탐 정답이 아니며, 설명을 등록했다고 정탐으로 고정하지 않는다. 등록한 URL을 분석 중 자동으로 접속하지 않는다.

## 불변 설명집

하나의 버전에 여러 벤더와 시그니처의 설명을 저장한다. 항목을 추가, 수정하거나 제거하면 기존 버전을 덮어쓰지 않고 새 버전을 생성한다. 운영에 적용한 버전과 이전 실행 기록은 보존한다. 이름은 120자, 변경 사유는 1000자, 벤더는 120자, 시그니처는 1000자, 설명은 2000자, 참고 출처는 1000자 이내다. 설명집은 최대 200개 항목과 정규화 JSON의 UTF-8 256 KiB 중 작은 한도를 따른다. 초과한 내용을 조용히 자르지 않는다.

벤더는 앞뒤 공백을 제거하고 Unicode casefold로 비교한다. 시그니처는 앞뒤 공백만 제거해 정확히 일치시킨다. 부분 일치와 정규식, 유사도 매칭은 하지 않으며, 동일한 매칭 키의 중복 항목은 거부한다. 벤더가 다르면 같은 시그니처 이름에도 다른 설명을 등록할 수 있다.

설명과 참고 출처를 포함한 전체 항목은 암호화 저장한다. 일반 목록에는 설명과 출처를 포함하지 않는다. 관리자 조회와 저장, 매칭 확인은 감사 이력에 남긴다. 외부 서비스 API 키에는 관리 권한이 없다.

## 관리자 API

기본 경로는 `/api/v1/admin/signature-explanations`다. 모든 경로에 관리자 인증과 기존 동일 출처 보안 검사를 적용한다.

| 메서드와 경로 | 동작 |
| --- | --- |
| `GET /` | 버전 목록. `limit=1~100`, 기본 25, `offset` 지원 |
| `POST /` | 새 불변 설명집 생성 |
| `GET /{version_id}` | 해당 버전의 전체 항목 조회 |
| `POST /match` | 선택한 버전에서 벤더와 시그니처 매칭 확인. 모델 호출 없음 |
| `POST /{version_id}/activate` | 직접 활성화 거부. `409 production_promotion_required` |

새 버전 요청 예시:

```json
{
  "name": "탐지 설명 변경안",
  "change_reason": "벤더 문서를 확인해 탐지 의도 보완",
  "parent_id": null,
  "entries": [
    {
      "waf_vendor": "Example WAF",
      "signature": "Example signature",
      "signature_explanation": "탐지 대상 동작과 해석 시 주의할 내용을 기록합니다.",
      "reference_source": "벤더 문서명 또는 URL. 선택 항목이며 기본값은 빈 문자열입니다."
    }
  ]
}
```

빈 `entries`도 저장할 수 있으나, 운영에서 설명을 제외하는 변경 역시 공식 평가와 운영 검토를 통과해야 한다. `PATCH`와 `DELETE`는 제공하지 않는다. 항목 삭제는 새 버전에서 해당 항목을 제외하는 방식이다.

## 접수와 실행 고정

`signature_explanation_version_id=null`은 설명을 사용하지 않는 명시적인 선택이다. 최신 버전을 자동 선택하지 않는다. 기존 기록의 미기록 스냅샷도 설명 없는 과거 실행으로 처리한다.

명시적인 테스트 후보는 선택한 설명집을 사용한다. 후보를 지정하지 않은 새 일반 테스트와 서비스 Test API 세션은 저장된 Test 기본 구성의 설명집만 접수 시 고정하고, 기존 Test 모델 역할 선택은 유지한다. 이미 열린 세션의 뒤늦은 문항에도 그 세션의 당시 설명집을 사용한다. 기본 선택이 없으면 설명 없이 진행하며 Production 설명집을 자동 상속하지 않는다. 고정 150건 모델 기능 검증은 명시적인 빈 설명집을 유지한다.

테스트는 전체 설명집을 암호화해 고정하고, 개별 분석은 벤더와 시그니처에 매칭한 항목 하나만 암호화해 고정한다. 일치하지 않은 경우도 설명 없음으로 고정한다. 개별 스냅샷의 `entry_count`는 원래 설명집의 전체 개수이며, 실제 포함된 항목은 `entries`의 길이로 구분한다. 설명집 내용 해시와 개별 스냅샷 해시를 별도로 검증하며, 재실행은 당시 스냅샷을 보존한다. 새 설명집을 과거 분석에 소급 적용하지 않는다.

운영 적용은 공식 테스트와 승인된 Ground Truth 평가, 관리자 운영 검토 경로에서만 가능하다. 저장하거나 매칭 확인을 하는 작업은 운영 설정을 변경하지 않는다. 설명이 모델 입력에 포함되더라도 원본 접수 이벤트와 외부 이벤트 중복 판별값은 변경하지 않는다. 공개 `waf-analysis-v3` 결과 필드 구조도 유지한다.

외부 요청의 최상위나 `extra_fields` 안에 `signature_explanation` 및 설명집의 서버 관리 메타데이터를 지정할 수 없다. 실제 HTTP payload 안의 동명 파라미터는 이 예약 필드와 다르며 원문 그대로 보존한다. 이전에 같은 이름을 사용자 입력 스키마로 등록한 환경은 새 예약 필드와의 충돌을 전환 전에 확인해야 한다.

매칭한 설명은 선택한 Primary와 Verifier로 전달된다. OpenAI를 사용하면 설명도 외부로 전송되므로 사내 비밀이나 실제 로그를 설명에 넣지 않는다. 기존 외부 전송 승인과 내부 전용 데이터 및 egress 제한을 그대로 적용한다.

`0032_signature_explanations`는 버전 테이블과 단일 운영 선택 테이블, 분석과 테스트의 nullable 연결 및 암호화 스냅샷 컬럼을 추가한다. 기존 부모 테이블을 재생성하거나 분석 데이터를 소급 변환하지 않는다. 실행이나 설명집 이력이 생긴 이후에는 이력 손실을 막기 위해 downgrade를 거부한다. 구조를 실제로 제거하려면 이전 DB 백업이 필요하다.
