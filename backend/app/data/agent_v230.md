# v2.30 근거 출처 역할 교정

## 원인과 범위

운영에서 약 500건 중 20건이 실패하며 `output_validation_failed`와 `evidence_source_support_forbidden`이 주로 관찰됐다는 보고를 기준으로 보완합니다. 이 코드는 시그니처나 등록 설명 같은 context 전용 후보를 공격/정상 근거로 선택한 경우입니다. JSON 구문 오류나 출력 토큰 부족과는 다릅니다. 실제 실패 원문을 확보한 것은 아니므로 모든 사례가 단순 source ID 오선택이라고 단정하지 않습니다.

v2.29는 완성된 출력이라도 이 오류가 있으면 worker에 전달하기 전에 전체 답변을 최대 4회 다시 생성합니다. worker에 이미 존재하는 출처 교정 절차를 사용할 수 없어 같은 선택 오류가 전체 실행 실패로 이어질 수 있었습니다.

## 처리 순서

1. provider 응답 완료 여부와 완결 JSON, 필수 필드/타입/개수 및 근거 연결, 분류 충돌과 판정 방향을 검사합니다. 존재하지 않는 source ID는 이 단계에서 계속 거절합니다. 역할 오류와 함께 섞여 있어도 가려지지 않습니다.
2. worker의 초기 Primary/Verifier 호출에만 출처 역할 오류를 교정 대상으로 넘깁니다. 직접 계약 검증과 실행기는 기본적으로 엄격하며, 명시적인 내부 옵션 없이는 유예하지 않습니다. 확정 판정의 실제 요청 근거 검사도 역할 오류가 있는 경우에만 이 단계에서 유예합니다.
3. worker는 원문 발췌/위치/제출 범위와 출처의 허용 분류를 검사합니다. 시그니처와 등록 설명은 context 전용이며, 다른 필드에 명시된 `allowed_supports`도 검사합니다. 거절된 근거는 최종 결과 후보에서 제외합니다.
4. 잘못된 index의 source ID만 고치는 기존 교정을 최대 1회 실행합니다. 같은 해석과 supports 전체를 실제 원문이 뒷받침할 때만 수정하며, 분류/해석/판정/요약을 바꾸지 않습니다. 의미를 바꿔야 하거나 기존 해석이 시그니처에만 의존하면 `requires_reanalysis=true`로 표시합니다.
5. 교정 후에도 동일한 출처 제한과 원문 검사 및 확정 방향의 실제 요청 근거 검사를 다시 수행합니다. 미해결 근거와 필수 원문을 잃은 의존 해석은 제외하고 기존 보류 정책을 적용합니다. 전체 출력 교정, 출처 교정 자체가 실패한 경우의 정책도 유지합니다.

이 과정은 문장의 의미적 정확성을 코드로 보증하지 않습니다. 관련 없는 실제 원문을 선택해 의미를 바꾸지 않도록 교정 지침을 유지하며, 최종 설명 품질은 실제 모델 검토가 필요합니다. 시그니처를 공격 근거로 허용하거나 supports를 자동으로 context로 바꾸어 성공 처리하지 않습니다.

## 보존하는 계약

- 공개 `waf-analysis-v3`, UI/보고서/내보내기의 핵심 근거 및 완료 응답 조건을 유지합니다.
- 모델 출력 필드와 생성 스키마, 역할당 근거 최대 5개, 기존 순환 연결과 중복 참조 정리를 유지합니다.
- Primary와 독립 Verifier, 필요한 Verifier의 실패/판정 불일치 보류를 유지합니다.
- 토큰 한도와 제한 시간, 최초 포함 최대 4회 출력 교정과 별도 최대 1회 출처 교정은 늘리지 않습니다. 새로운 모델 단계도 없습니다.
- 실제 이벤트/후보/원문 위치와 입력 예산은 v2.29 그대로입니다. 공통 지침에서 field와 원문을 대조하고 실제 요청과 context 전용 출처를 구별하도록 짧게 보완합니다.
- 교정 전후 출력과 출처 이력은 암호화된 기존 grounding 이력에 남깁니다. 유예된 오류는 기존 실행 시도 메타데이터에 index와 고정 reason만 남기며 원문/모델 문장은 복사하지 않습니다.

## 버전과 적용

새 후보는 `waf-system-v2.30`, `evidence-pipeline-v11`, `app.worker_entrypoint_v230`입니다. v2.29 전체 지침은 `legacy_prompts_v229.py`에 보존하고 132개 과거 실행 파일은 수정하지 않습니다. DB migration과 새 운영 의존성은 없습니다. 과거 대기 작업과 실패 재실행은 원래 지침/코드를 사용합니다. 개선 비교에는 새 후보 테스트를 사용합니다.

배포만으로 승인된 Production 설정을 바꾸지 않습니다. 공식 Test → 승인 Ground Truth 평가 → 운영 검토와 관리자 승격 경로를 유지합니다. 실제 모델 호출/외부 전송/유료 검증, 운영 승격, Docker 재배포와 Git 업로드는 이번 변경에서 수행하지 않습니다.

## 검증과 해석

합성 데이터와 모의 provider 응답으로 실제 ModuAgent 직렬화 및 worker 교정을 확인합니다. 출처만 잘못된 공격/정상 근거의 복구, 같은 위반 반복, 일반 allowed_supports, 미등록 후보, 해석 재검토 요청과 필수 근거 유실, 엄격한 기본값과 과거 버전 보존을 검사합니다.

실제 Gemma의 실패율과 처리시간 개선은 미검증입니다. 새 테스트에서는 전체 실패와 함께 출처 교정 시도/복구, 보류 및 참고 판정 일치율도 비교해야 합니다. 실패가 보류로 바뀐 것만으로 품질이 개선됐다고 판단하지 않습니다.

이번 관련 검증은 새 교정/worker와 기존 근거 연결 219건, 버전/스냅샷/공통 실행 195건, API/핵심 근거/내보내기/운영 승인/재실행 125건이 통과했습니다. 별도 배포 스크립트 테스트 22건과 `git diff --check`도 통과했습니다. API 묶음의 실제 PDF 렌더링 1건은 릴리스 이미지 전용 옵션 미지정으로 건너뛰었으며, 기존 Starlette/AnyIO deprecation 경고 1종이 있습니다. 전체 백엔드 테스트를 모두 실행한 것은 아니며 프런트엔드 코드는 변경하지 않았습니다.

최종 v2.30 manifest는 146개 파일이며 해시는 `9ba048d9570ed1b9e9aad103276bb1aa7cf58209cf1080d234791d62c9f6462f`입니다. 기존 v2.29의 132개 파일 해시 `7b5da83dd890915dc6599b70f4f20ca3a4a5c836c9e9327dc11b1893a83586bb`와 개별 파일 해시가 모두 유지됩니다. 공통 지침은 출처 선택 안내 두 줄만 바뀌며 4,458→4,513자입니다. 실제 토큰 증가량이나 품질 개선을 측정한 수치는 아닙니다.
