# v2.25 후보: 근거 해석과 출력 안정성

시작 commit은 `bec3d91`입니다. 공통 판정 지침을 정리하고 의미를 보존할 수 있는 근거 연결 오류를 코드로 복구합니다. 공개 `waf-analysis-v3`, 파서, 내부 `SecurityAnalysisOutputV224`와 역할별 모델 선택 및 최종 결합 정책은 유지합니다. DB migration과 운영 의존성 추가는 없습니다.

## 근거 작성

근거는 관측한 내용, 요청에서의 역할과 공격/정상 해석을 뒷받침하는 이유를 연결합니다. 환경 헤더나 쿠키의 존재 자체는 정상성이나 인증 상태를 입증하지 않습니다. 중요한 해석에 기여하지 않는 사실은 참고 내용에도 채우지 않습니다. 해당 필드의 실제 값과 다른 입력의 조합에 의미가 있으면 보존합니다.

단독으로 중립인 관측도 결합해서 판단할 수 있으며 관련 원문과 중요한 반대 근거는 유지합니다. 설명을 채우기 위해 공격 의도, 인증과 서버 처리 또는 보이지 않는 공격 코드를 만들지 않습니다. 근거 개수나 문장 수를 채우지 않습니다. 이 기준은 모델 지침이며 서버의 의미적 정확성 보증은 아닙니다.

Primary는 대상과 동작 및 값을 연결해 분석합니다. Verifier는 다른 역할의 답변 없이 같은 입력을 처음부터 분석하고, 자신의 근거에 과장과 공격 부재를 정상으로 확대하는 해석, 불필요한 보류 조건이 있는지 검토합니다. 공통 판정 기준은 같습니다. 기존 설정에서 검증된 동일 프로필을 두 역할에 선택할 수 있으며 배포가 모델 배정을 자동 변경하지 않습니다. 같은 모델의 일치는 정확성 증명이 아니므로 실제 품질 비교는 별도입니다.

공백과 줄바꿈을 포함한 공통 지침은 5,284→4,391자, UTF-8은 10,352→8,735바이트입니다. 기본 관리자 지침과 역할을 포함한 Primary는 5,640→4,745자, Verifier는 5,664→4,840자입니다. 이벤트와 출력 JSON Schema는 제외한 값이며 실제 tokenizer 측정이나 속도 개선 결과가 아닙니다.

## 완결 출력의 근거 연결 복구

기존 완결 JSON 정규화와 정확한 중복 제거를 먼저 수행합니다. 추가 복구는 관계 오류 외의 전체 출력 계약과 제출 후보의 출처 및 허용 분류를 확인한 뒤, 원래의 유효한 대표→관련 연결을 하나도 추가하거나 제거하지 않는 경우에만 허용합니다.

- 같은 대표 번호가 여러 그룹에 나뉜 경우 연결을 하나로 정리합니다.
- 정상적인 다른 연결과 함께 들어간 자기 참조는 제거할 수 있습니다.
- 원문 출처, 근거 순서, 설명, supports와 판정 및 심각도는 그대로 유지합니다.
- 수정 결과는 전체 출력 계약을 다시 통과하고 worker의 기존 원문 위치 및 방향 검증도 거칩니다.

범위 밖 참조, 잘못된 번호 타입, 자기 참조밖에 없는 그룹, 공격/정상 분류 충돌이나 다른 출력 오류는 추측해 고치지 않습니다. 관계 목록을 비워 성공시키거나 필요한 원문을 삭제하지 않습니다. 기존 원인별 전체 교정 재시도와 최종 실패 처리를 유지합니다.

초기 검토에서는 연결만 고치는 LLM 호출을 고려했으나, 안전하게 허용할 수 있는 연결 집합은 서버가 정확히 계산할 수 있어 코드로 처리합니다. 추가 모델 호출은 없으며 기존 최초 포함 최대 4회와 별도 원문 인용 교정 한도, 출력 토큰 및 제한 시간은 그대로입니다. 모든 의미적 오류를 해결했다고 보장하지 않습니다.

## 버전과 승인

새 후보는 `waf-system-v2.25` 및 `waf-judgment-v2.25`, 실행 구현은 `evidence-pipeline-v6`로 식별합니다. 입력은 `agent-input-v3`와 `evidence-selection-v5`를 재사용하고 `capture_assessment`도 기존처럼 검증합니다.

직전 지침 전체는 `legacy_prompts_v224_semantics.py`에 바이트 단위로 보존합니다. 원래 `legacy_prompts_v224.py`와 과거 66개 고정 실행 파일 및 표시 구현도 유지합니다. 기존 운영 승인, 접수된 작업과 실패 재실행은 당시 지침과 실행 해시를 사용하며 새 후보에 승인이나 평가를 이전하지 않습니다.

새 실행기 `python -m app.worker_entrypoint_v225`는 암호화된 스냅샷에 따라 과거 처리기와 새 처리기를 선택합니다. 기존 파서 관리 작업, 모델 기능 검증과 제한된 별도 근거 정리 작업도 유지합니다. Compose와 재배포 도구에는 새 실행 명령을 연결하되 코드 변경 자체로 서비스를 재시작하거나 운영 모델을 변경하지 않습니다. Production 적용은 승인된 Ground Truth의 공식 테스트와 관리자 운영 검토를 거칩니다.

## 읽기 전용 실패 집계

기존 진단 도구의 역할별 `output_failures`에서 단계 완료/실패와 개별 시도의 출력 검증 오류, 출력 한도 중단, timeout 및 원인 미상 미완료를 구분합니다. 실패 후 완료된 문항과 오류 필드/유형별 시도 수도 확인합니다. 중첩 재시도와 최상위 기록은 중복 합산하지 않으며 과거 미기록 값은 미기록으로 남깁니다.

```bash
cd backend
python scripts/summarize_execution_latency.py \
  --database-file /secure/backups/waf.sqlite \
  --test-run-id TEST_RUN_ID
```

승인된 SQLite 백업을 읽기 전용으로 사용합니다. SQL에서 고정 오류 이름과 숫자만 추출하며 원문, 암호화된 입출력, 키나 임의 provider 문자열을 출력하지 않습니다. 공개 API나 웹 화면에 진단 필드를 추가하지 않습니다.
