# v2.36 기본값 복원 (2026-11-27)

## 복원 범위

v2.37 후보를 사용한 운영 서버의 평가 테스트에서 실패와 지연이 늘었다는 사용자 보고에 따라 신규 기본값을 v2.36으로 돌린다. 원인이 무엇인지는 이번 복원에서 확정하지 않으며 새 최적화나 모델 지침 개정을 함께 넣지 않는다.

- 고정 지침: `waf-system-v2.36`
- 프롬프트 버전: `waf-judgment-v2.36/policy-N`
- 추론 구현: `evidence-pipeline-v16`, `worker_v236`, `executor_v236`
- 내부 출력: `SecurityAnalysisOutputV234`와 `related_evidence_ids`
- 지침과 역할 및 관리자 지침 결합: 보관된 v2.36과 동일

`contributes_to_evidence_ids`를 생성하는 v2.37은 신규 테스트의 기본 경로에서 빠진다. 모델 프로필과 키, 출력 한도, 동시 처리, 파서와 수집 구분자, HTTP 원문, 공개 API v3 및 근거 정리와 PDF 기능은 변경하지 않는다. DB migration이나 새 의존성은 없다.

## 보존한 부분

기존 결과와 감사 기록 및 원문을 삭제하거나 덮어쓰지 않는다. v2.36과 v2.37 고정 실행 파일의 해시도 바꾸지 않는다. 원래 v2.37 지침은 `legacy_prompts_v237.py`에 바이트 단위로 보관하고 기존 승인 스냅샷 복원에 사용한다.

이미 접수한 v2.37 문항과 재실행은 v2.37을 유지한다. 결과나 실패를 소급 변경하거나 같은 테스트의 중간부터 지침을 바꾸지 않는다. 버전 분기용 `app.worker_entrypoint_v237`과 지원 버전 목록을 남겨 두는 이유도 이 때문이다. 실행기 이름이 v237이어도 새 v2.36 작업은 v236 엔진으로 보낸다.

`http-capture-v2` 파서 메타데이터의 허용값 누락 수정과 과거/신규 실패 기록의 조회 기능은 보존한다. 이를 제거하면 기존 결과 조회나 재실행에서 별도 오류가 생길 수 있다.

## 운영 서버 적용

이번 요청은 **평가 → 테스트**의 문제다. 승인된 Production 구성은 변경하지 않으며 DB의 승격/평가 기록도 수정하지 않는다. Git 이력 재작성, `reset --hard`, DB downgrade와 데이터 볼륨 삭제는 사용하지 않는다.

1. 이 복원 소스를 기존 서버에 반영하고 평소의 백업 포함 재배포 절차로 API와 worker를 함께 교체한다. 새 migration은 필요 없지만 기존 배포 스크립트의 마이그레이션 검사는 그대로 실행한다.
2. 진행 중인 v2.37 테스트를 더 실행하지 않으려면 해당 테스트에서 중지한다. 이번 코드 수정이 기존 테스트를 자동 중지하지는 않는다.
3. 같은 평가 데이터셋과 모델 설정으로 **새 테스트**를 만든다. 기존 실패 재실행 버튼은 원래 v2.37을 유지하므로 복원 확인용으로 쓰지 않는다.
4. 실행 이력에서 `waf-judgment-v2.36/policy-N`과 `waf-system-v2.36`을 확인한다.

서버가 이미 승인된 v2.37을 Production에서도 사용한다면 코드 기본값 변경만으로는 그 승인 구성을 바꾸지 않는다. 그 경우 이전 유효한 공식 평가 테스트를 기존 운영 반영 검토와 관리자 승격 경로로 적용해야 하며 DB 값을 직접 고쳐 우회하지 않는다.

## 검증의 한계

관련 Backend 12개 테스트 파일에서 190건이 통과했다. 신규 테스트 API의 v2.36 선택과 실제 ModuAgent 모의 HTTP 실행, 기존 v2.36/v2.37 승인 스냅샷 및 고정 실행 해시 보존, 두 버전의 실행 분기와 파서 결과 호환을 포함한다. `diff --check`도 통과했다. 경고는 기존 Starlette/AnyIO 폐기 예정 API 안내다. Frontend는 수정하지 않았으며 전체 Backend 검사나 실제 모델 성능 검사는 수행하지 않았다.

합성 데이터와 모의 응답으로 새 접수의 지침/계약 복원, 두 버전의 저장 스냅샷 및 실행 분기와 API 호환을 확인한다. 실제 Gemma의 실패율과 처리시간이 복원 후 얼마나 바뀌는지는 별도 측정이 필요하다. 운영 데이터나 실제 모델을 호출하지 않으며 운영 서버 재배포와 Git 업로드도 이번 코드 수정만으로 수행한 것으로 간주하지 않는다.
