# v2.39: 출처 교정 중단의 제한된 복구

## 목적과 적용 조건

출처 교정 실패가 최초 응답의 독립적인 유효 근거까지 사용할 수 없게 하던 경로만 보완합니다. 다음 조건을 모두 확인한 경우에만 기존 같은 역할의 재검토 경로를 엽니다.

- 최초 응답이 완결된 `SecurityAnalysisOutputV238`이며 원문 해소 결과가 있습니다.
- 오류는 `signature_support_not_allowed` 또는 `source_support_not_allowed`뿐입니다. 다른 원문 오류나 불명확한 교정 범위가 섞이면 복구하지 않습니다.
- 바로 다음 출처 선택 교정은 한 논리 시도이며 `model_output_incomplete` 계열 오류와 `length/max_tokens`가 함께 기록되어 있습니다.
- 최초 생성, 출처 교정과 재검토를 합쳐 기존 논리 시도 예산 5회 안에 있고, 재검토 입력과 원문 및 필요한 관계가 온전히 들어갑니다. 논리 시도 수는 HTTP 전송 수가 아닙니다.

처음부터 잘린 분석, 거절/차단 응답, 권한/통신 오류와 취소를 성공으로 전환하지 않습니다. 파서와 입력 절단 판정 기준, 시그니처의 참고 전용 제한도 그대로입니다.

## 처리 순서

1. 실패한 교정 JSON은 완결 형태처럼 보여도 사용하지 않습니다.
2. 최초 완결 응답과 당시 원문 검증 결과의 별도 사본에서 출처 오류 근거와 그 사본 및 의존 해석을 제외합니다. 유효한 반대 해석은 유지합니다.
3. 같은 역할과 프로필의 기존 `EvidenceDecisionReviewOutput`으로 최대 한 번 재검토합니다. 기존 판정과 요약 및 위협 설명을 유지할 의무를 주지 않으며, 남은 근거 전체를 보존합니다.
4. 재판정의 계약, 방향성 원문, 출처 정책 및 필수 연결을 다시 검증한 경우만 복구합니다. 이후 Verifier 필요성 판단과 최종 결합 및 핵심 근거 준비 경로는 그대로 수행합니다.
5. 새 경로의 검토가 불가능하거나 실패하면 원래 출처 교정 실패를 유지합니다. Primary는 기존 분석 실패, 필수 Verifier는 기존 최종 보류 정책으로 처리합니다.

출처 교정 자체는 성공했지만 재검토가 실패해 보류했던 이전 경로는 변경하지 않습니다. 이 패치는 모든 기술적 실패를 보류로 바꾸거나 유효 근거가 남았다는 이유만으로 예전 정탐을 유지하지 않습니다.

## 기록과 API

최초 응답과 실패한 교정의 두 원래 기록은 수정하지 않고 재검토 기록을 추가합니다. 실패한 교정 출력은 `null`이며, 새 검토가 검증을 통과하기 전 최초 요약/판정을 검토 결과처럼 기록하지 않습니다. 원문과 해석은 기존 관리자 전용 암호화 실행 이력에만 남깁니다.

단계의 `evidence_source_recovery` 메타데이터는 `source-length-recovery-v1`이며 `eligible`, `attempted`, `recovered`, `excluded_count`, 고정 `skipped_reason`으로 복구 대상/실행/성공을 구분합니다. 모델 이름이나 원문 및 임의 예외 메시지를 여기에 추가하지 않습니다. 원래 중단 원인은 `evidence_grounding_retry.attempts[1].output_validation_retry.attempts`에 유지합니다.

공개 API `waf-analysis-v3` 필드와 타입은 그대로입니다. 저장과 화면 및 PDF/Excel은 검증된 최종 근거를 같은 경로로 사용합니다. 해결되지 않은 Primary 실패는 실패 재실행 대상에 남으며 모델 검증과 공식 평가의 실패 없음 조건을 상태 변경으로 우회하지 않습니다. 정상적으로 재검토가 완료된 보류는 기존처럼 합법적인 분석 결과입니다.

## 버전과 기존 실행 보존

시스템 규칙 식별값은 `waf-system-v2.39`, 프롬프트 표시는 `waf-judgment-v2.39`, 파이프라인은 `evidence-pipeline-v19`입니다. 공통 지침 본문과 두 역할 문구, executor/생성 스키마/재검토 지침 및 입력은 v2.38 구현을 재사용합니다. 관계와 표시 처리도 기존 v2.38과 같고 공개 응답에 새 필드를 추가하지 않습니다.

v2.38의 258개 고정 파일은 SHA-256 `848f2827e946edb03ab83e0ac0191e3d19ba26bad9cf1a789a0774ff7d9d54e8`을 보존합니다. 새 worker와 래퍼 및 재사용하는 지침 원본을 새 manifest에 추가합니다. 기존 테스트와 실패 재실행 및 승인된 Production은 당시 스냅샷/구현으로 처리하며 과거 실패를 자동 복구하지 않습니다. 새 후보 비교는 새 테스트로 진행합니다.

현재 실행기는 `app.worker_entrypoint_v239`입니다. Compose와 재배포 코드의 신규 실행기만 갱신하며 이번 코드 작업에서 서비스 재배포, 운영 승격이나 Git 게시를 실행하지 않습니다. DB migration과 새 운영 의존성은 없습니다. 운영 적용은 승인 Ground Truth 공식 평가와 관리자 승격을 거칩니다.

## 영향과 제한

정상 경로는 모델 호출이 늘지 않습니다. 복구 대상은 기존에 도달하지 못했던 재검토와 후속 Verifier/근거 정리까지 실행될 수 있으므로 건당 처리시간과 비용이 증가할 수 있습니다. 출력 한도는 늘리지 않으며 중단 원인 자체를 없애는 변경도 아닙니다.

합성 응답 회귀는 제외/보존/버전/상태 불변 조건을 검사할 뿐 의미적 정확성을 보장하지 않습니다. 실제 Gemma/vLLM 성공률과 보류율, 오탐/미탐, 처리시간 및 호출 수 효과는 별도 검증이 필요합니다. 원래 실패 원인과 복구 성공을 따로 집계하고 실패율 감소만으로 품질 향상이라고 판단하지 않습니다.
