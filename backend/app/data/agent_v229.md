# v2.29 근거 연결 실패 보완

## 확인된 원인

보고된 v2.28 실패는 `output_validation_failed`, `provider_finish_reason=stop`, `evidence.related_evidence_ids / evidence_link_cycle`입니다. 마지막 시도는 출력 988토큰으로 한도 3,072토큰에 도달하지 않았습니다. JSON을 읽은 뒤 순환 연결 검사에서 거절된 사례이며, 다른 실패까지 모두 같은 원인으로 단정하지 않습니다.

v2.28은 모델에게 순환 없는 관계를 요구했지만, 생성 JSON Schema로 이 조건을 보장할 수 없었습니다. 함께 해석할 근거의 상호 연결 자체는 원문 불일치나 분석 오류를 뜻하지 않습니다. 그 이유만으로 전체 JSON을 최대 4회 다시 생성하고 실패 처리하던 조건을 바로잡습니다.

## 변경 내용

- 순환 연결을 삭제하거나 임의로 한쪽만 선택하지 않습니다. 방문한 번호를 기억하며 모든 연결과 그 끝의 근거를 검사합니다. 역할당 최대 5개 제한은 같습니다.
- 연결 전체에서 공격/정상 근거가 섞이는 경우는 계속 거절합니다. 독립된 반대 해석이 같은 중립 근거를 공유하는 기존 방식은 유지합니다.
- 같은 선택 번호의 반복만 순서를 보존해 정리합니다. 대상은 `related_evidence_ids`와 `decision_issue.evidence_ids`이며 다른 근거 선언, 출처, 설명, supports, 판정과 심각도는 바꾸지 않습니다.
- 원래 참조 개수와 타입 제한을 먼저 확인합니다. 없는 번호, 자기 참조, 중복된 근거 선언 ID나 원래 한도 초과를 추측해 복구하지 않습니다. 정리 뒤에도 전체 계약과 제공된 원문 후보를 검증합니다.
- 실제 JSON이 완결되고 모호하지 않을 때만 처리합니다. 잘린 JSON, 중복 JSON 키, 비정상 숫자나 provider 미완료 응답은 기존처럼 거절합니다.
- 정리 여부는 실행 시도의 `evidence_reference_normalizations`에 고정 코드만 기록합니다. 모델 문장이나 원문 값을 진단 필드에 복사하지 않습니다. 해당 코드는 `evidence_link_duplicates_removed`와 `decision_evidence_duplicates_removed`입니다.

## 원문과 API 보존

기존 핵심 근거 및 표시 계획은 이미 순환 연결의 전체 관련 원문을 반복 없이 탐색합니다. 새 출력 검사에서도 같은 기준을 사용합니다. 필수 원문이 사라지면 그 원문에 의존하는 해석까지 제외하는 기존 보류 처리를 유지합니다. 순환 연결을 허용한다는 이유로 근거를 검증하지 않거나 오류를 무시한 성공으로 처리하지 않습니다.

내부 출력 필드와 생성 Schema는 모델 제목을 제외하면 v2.28과 같습니다. 공개 `waf-analysis-v3`, UI와 보고서 및 내보내기의 결과 구조를 변경하지 않습니다. JSON의 모델 원문 전체는 기존처럼 저장하지 않으며, 검증/중복 정리를 마친 역할 출력과 서버 변환 결과를 암호화된 실행 이력에 보존합니다. 출처 이력과 실제 발췌는 그대로입니다.

공통 지침은 근거의 상호 연결을 허용한다는 문구만 바꿉니다. 분석 기준과 역할 지침, 모델 선택, 토큰 한도, 최초 포함 최대 4회와 인용 교정 최대 1회, 독립 Verifier와 실패/불일치 보류는 그대로입니다. 추가 LLM 단계는 없습니다.

## 버전과 운영 적용

새 후보는 `waf-system-v2.29`, `evidence-pipeline-v10`, `app.worker_entrypoint_v229`입니다. 기존 v2.28 전체 지침은 `legacy_prompts_v228.py`, 118개 고정 실행 파일은 기존 해시로 보존합니다. 새 manifest는 132개이며 DB migration과 운영 의존성 추가는 없습니다.

배포만으로 승인된 Production 지침을 바꾸지 않습니다. 공식 Test와 승인 Ground Truth 평가, 운영 검토 및 승인 경로를 유지합니다. 기존 실패의 재실행은 당시 v2.28을 그대로 사용하므로, 개선 비교에는 새 v2.29 후보 테스트가 필요합니다. 기존 결과와 실패 이력을 다시 쓰지 않습니다.

## 검증과 제한

검증 데이터는 합성 사례만 사용합니다. 동일한 모의 provider 응답으로 v2.28은 `evidence_link_cycle`로 실패하지만 v2.29는 연결을 모두 유지하고 추가 호출 없이 완료하는지 확인합니다. 이 테스트는 실제 Gemma가 생성한 응답이나 토큰 측정이 아닙니다.

2/3/5개 근거의 순환, 전이 연결, 핵심 근거 선택의 필수 원문 보존, 중복 참조 정리와 원본 불변, 잘못된 출처/자기/미선택 참조/분류 충돌의 거절, 역할별 출처와 승인/재실행 및 과거 실행 보존을 확인합니다. 실제 모델의 전체 성공률과 처리시간 개선은 별도 검증 대상입니다.

이번 관련 검증은 중복 실행을 제외해 새 처리 89건, 버전/스냅샷/입력/라우팅 관련 193건, 핵심 근거/API/승인/재실행 관련 130건으로 총 412건 통과했습니다. 배포 스크립트 22건과 `git diff --check`도 통과했습니다. 전체 백엔드 테스트를 모두 실행한 것은 아니며 기존 Starlette/AnyIO deprecation 경고는 남아 있습니다. 프런트엔드 코드는 변경하지 않았습니다.

운영 모델 호출, 지침 승격, Docker 재배포 및 Git 업로드는 이번 코드 수정 범위에 포함하지 않습니다.
