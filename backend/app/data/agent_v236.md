# v2.36 근거 해석 및 수집 경계 후보

## 변경 범위

고정 지침 `waf-system-v2.36`, 프롬프트 `waf-judgment-v2.36`, 실행기 `app.worker_entrypoint_v236`, 실행 구현 `evidence-pipeline-v16`, 입력 `agent-input-v4`로 구분한다. 기존 v2.35의 206개 실행 파일과 당시 지침은 바꾸지 않는다. 승인된 Production/Test 기본 설정, 접수된 작업과 과거 실패 재실행은 원래 고정 버전으로 처리한다. 이번 변경은 새 후보이며 코드 배포만으로 운영 지침을 자동 승격하지 않는다.

DB migration과 새 의존성은 없다. 공개 분석 API v3 및 모델의 생성 스키마는 그대로다. 관리자 파서 버전 생성 계약에는 새 엔진 `http-capture-v2`와 선택적 벤더 프로필 `field_separator`가 추가되며, 기존 설정의 직렬화/해시와 기본값은 보존한다.

## 근거 작성

관측한 동작/값의 역할과 공격/정상 해석의 이유를 연결한 뒤 분류한다. 사실만 있으면 공격/정상 방향을 붙이지 않고, 판정에 필요한 중립 기여만 `context`로 남긴다. 불필요한 관측으로 근거 개수를 채우지 않는다. 표준 기능/업무 데이터라는 설명과 분류가 일치하는지 점검하며, 기존 분류를 정당화하려고 의도나 환경을 만들지 않는다.

표준 동작이라는 사실과 실제 서비스 정책 준수는 별개다. 정책 위반은 확인된 적용 정책과 요청의 불일치로 설명하며 시그니처명에서 허용 목록을 추정하지 않는다. 시그니처와 등록 설명은 여전히 참고 내용 전용이고 실제 요청 근거를 대신하지 않는다.

결합 의미는 대표 항목에서 한 번 설명한다. `related_evidence_ids`는 해당 해석에 필요한 기여이며 같은 주제/발췌, 중복 설명이나 반대 의견을 묶는 기능이 아니다. 참조된 항목을 일괄 `context`로 바꾸지 않는다. 독립적으로 타당한 공격/정상 해석과 필수 원문, 중요한 반대 근거는 유지한다. 같은 출처의 서로 다른 타당한 해석을 금지하지 않는다.

기존 그래프 검사와 원문 출처 검증은 그대로이며 새 의미 검증 실패 조건은 추가하지 않는다. 화면의 연결 명칭은 **이 해석에 필요한 근거**, 오류 분류는 **연결된 근거의 분류 불일치**로 바꾼다. 연결 오류가 곧 실제 공격/정상 의견 충돌이라는 뜻은 아니다.

## 기존 교정 재시도 보완

`structured-output-repair-v13`의 최대 시도 수는 최초 포함 4회다. 출처만 고치는 호출과 이미 유효한 해석을 고정하는 판정 재검토의 역할은 바꾸지 않는다. 새 필수 LLM 단계나 Primary 결과의 Verifier 전달은 없다.

다음 조건을 모두 만족할 때만 직전 실패 자료를 다음 구조화 교정 입력에 포함한다.

- provider가 `stop`으로 완료했고 출력 검증 오류에 `evidence_support_conflict`가 있다.
- JSON이 완결/유한/비중복 키이며, 근거는 실제 생성 계약의 타입과 크기를 만족한다.
- 고유 해석 번호, 알려진 출처 번호와 실제 같은 응답의 연결 관계로 오류 경로를 검증할 수 있다.
- 전체 기존 원문 입력과 전체 해석 목록이 기존 입력 문자 예산 안에 들어간다.

입력의 `evidence_conflict_correction`에는 버전, 직전 시도 번호, 당시 판정, 전체 근거 최대 5개와 검증된 연결 경로만 포함한다. 해석은 항목당 최대 2,000자를 온전히 유지한다. 별도 초안 한도는 JSON 16,000자 및 UTF-8 32 KiB다. 초안을 줄이거나 중요한 반대 근거를 골라 빼지 않는다. 예산 부족/구조 오류이면 초안 없이 기존 교정으로 돌아간다. 원본 이벤트나 원문 후보를 삭제해 공간을 만들지 않는다. 입력 문자 예산은 기존 근사 토큰 예산이며 실제 tokenizer의 정밀한 토큰 보증은 아니다.

초안은 비신뢰 사용자 JSON에만 들어가며 시스템 지침으로 승격하지 않는다. 모델은 원문을 대조해 설명, 분류, 필수 연결과 판정을 함께 다시 작성할 수 있고 잘못된 방향은 철회할 수 있다. 검증을 통과하려고 분류만 뒤집거나 필수 연결을 지우지는 않는다. 서버가 그 의미 교정을 대신하지 않는다.

새 완결 응답으로 초안을 교체하고, `length/max_tokens` 등 중단 뒤에는 이전 초안과 번호를 재사용하지 않는다. 화면용으로 절단할 수 있는 `rejected-evidence-v1` 스냅샷과 별도 경로로 구성한다. 교정에 사용한 추가 JSON은 실패 당시 암호화 이력의 `next_retry_context`에 다음 시도 번호와 함께 보존한다. 원래 단계 입력과 합치면 실제 추가 입력을 대조할 수 있다. 로그, 일반 메타데이터/통계와 공개 v3/보고서에는 설명을 넣지 않는다.

## 선택적 수집 구분자 처리

설정 경로: **파서 관리 → 이전 파서 / 비교 이력 → 새 버전 작성 → 벤더별 프로필 → 수집 필드 구분자**. 해당 벤더의 확인된 형식에서만 `/@/` 선택을 사용한다. 저장은 새 파서 후보이며 기존 후보 테스트와 승인된 Ground Truth 공식 평가 및 관리자 승격을 유지한다. 기본값은 `none`이고 기존 파서/운영 설정은 변하지 않는다.

새 엔진은 완전한 HTTP 요청 시작 줄, 구분자로 나눈 헤더와 이중 경계로 끝나는 헤더 구간을 엄격하게 확인한다. 현재 지원은 실제 줄 모드, 엄격한 공백, 선행 빈 줄 없음이며, 최대 262,144자 및 헤더 256개로 범위를 제한한다. JSON 안 HTTP 문자열, 임의 envelope나 불완전 형식을 추측해 변환하지 않는다. 알려지지 않은 벤더, 겹치는 선택, 지원하지 않거나 모호한 구조는 기존 범용 처리와 원문 분석을 유지한다.

파싱용 구조 뷰와 원문 위치 매핑을 구분한다. 모델 원문 후보에서는 확인된 구분자 위치만 제외하고 양쪽을 다른 `capture_segment`로 전달한다. 문자를 빈 문자열로 붙이거나 임의의 원문 발췌를 만들지 않는다. 원문 저장, UTF-8 바이트 수와 하이라이트 위치는 보존한다. 디코딩 원문 범위가 제외 구간을 가로지르면 해당 힌트를 보내지 않는다. 구분자 제외는 입력 예산 절단으로 세지 않으며, 실제 수신본 끝을 전달했는지는 별도로 사실대로 기록한다. 파서의 `partial`/수집 직렬화 주의점도 자동 성공으로 바꾸지 않는다.

요청 경로와 본문 등의 실제 `/@/` 값은 보존하며, 검출 가능한 모호한 헤더도 변환하지 않는다. 단, 실제 헤더 값의 `/@/X-Foo: value`처럼 경계와 완전히 같은 모양은 코드만으로 구별할 수 없다. **장비 형식이 구분자를 예약하고 실제 값의 동일 문자를 이스케이프하거나 구별한다는 사실을 확인한 경우에만** 이 프로필을 선택해야 한다. 벤더명이나 반복 등장만으로 활성화하면 안 된다. 이 한계를 설정 화면에도 명시한다.

## 검증 및 남은 범위

합성 데이터와 모의 HTTP로 구조화 교정, 예산/개인정보 경계, 실패 뒤 성공의 암호화 이력, 과거 버전 해시/라우팅과 운영 승인 보존, 파서 설정/출처/디코딩 및 프런트엔드 회귀를 검사한다. 실제 모델을 호출하거나 운영 데이터를 읽고 외부로 전송하지 않는다.

2026-11-26 실행 결과:

- Backend 관련 회귀 568개 통과: 구조화 교정/암호화 이력/기존 계약 151개, 실행 경로/파서/승격/재실행 통합 395개, 별도 파서 버전/수명주기 22개다. 반복 실행 결과를 중복 합산하지 않았다.
- Frontend 전체 893개 통과 및 Vite production build 성공.
- 배포 스크립트 단위 테스트 23개 통과. 실제 재배포는 하지 않았다.
- v2.35 고정 파일 206개와 지침 파일의 해시 일치 및 `diff --check` 확인.
- 비차단 경고: Starlette/AnyIO 사용 중단 예정 안내, 프런트엔드 테스트 렌더링의 React key 안내와 큰 번들 크기 안내가 있다.

실제 Gemma/vLLM에서 방향 해석의 개선, 분류 충돌/실패율과 전체 시간 및 입력 토큰 증가는 아직 검증하지 않았다. 예산이 남는 실패 시도에만 전체 초안 입력이 늘어나므로 회복에 도움이 될 수 있지만, 성공률이나 속도 개선을 코드 테스트만으로 보장하지 않는다. 운영 적용 전 별도 공식 평가와 관리자 검토가 필요하다. 재배포, Git 커밋/업로드와 Production/Test 설정 변경은 이번 작업에 포함하지 않는다.
