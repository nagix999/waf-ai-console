# v2.34 근거 연결과 출력 교정 후보

## 목적과 유지 범위

운영 v2.32에서 보고된 근거 연결 충돌, 확정 판정과 요청 내용 근거 불일치 및 보류와 심각도 불일치의 반복 교정을 보완합니다. `length`는 출력 중단이며 `stop`과 도메인 검증 오류는 완결 응답의 내용 정합성 실패로 구분합니다. 오류 유형이 같다는 이유로 전체 실패를 불완전 출력으로 바꾸지 않습니다.

파서, 원문 후보와 모델 입력, 공개 `waf-analysis-v3` 필드, Primary/독립 Verifier 및 최종 결합 정책을 유지합니다. 최초 포함 최대 4회, 프로필의 출력 토큰 한도와 모델 설정, 별도 출처 교정 및 조건부 판정 재검토 예산은 늘리지 않습니다. 근거 정리 v3도 기존 처리기를 그대로 사용하며 새 모델 단계는 없습니다.

v2.33 실행기는 앞선 근거 정리 전용 릴리스입니다. 혼동하지 않도록 이번 판정 후보는 `waf-system-v2.34`, `waf-judgment-v2.34`, `evidence-pipeline-v14`, `app.worker_entrypoint_v234`로 구분합니다.

## 공통 지침

기존의 두 근거 연결 문장을 교체하며 공격별 예외 규칙을 추가하지 않습니다. `related_evidence_ids`는 현재 해석을 성립시키는 데 필요한 다른 근거의 기여만 참조합니다. 같은 주제/발췌나 반대 의견이라는 이유로 연결하지 않습니다.

공통 고정 지침은 4,657자에서 4,752자로 95자 증가했습니다. 역할 지침과 사용자 정책 기본값은 그대로입니다.

직접 연결뿐 아니라 간접 연결을 따라가도 하나의 해석에 공격/정상 분류를 섞지 않습니다. 독립적인 반대 근거와 공통 `context`를 각각 참조하는 구성은 허용합니다. 필요한 상호 연결은 계속 허용하고, 통과를 위해 분류를 뒤집거나 필수 관계를 삭제하지 않습니다. 원문과 관련 근거를 코드가 임의로 제거하는 복구는 추가하지 않습니다.

## 현재 응답에 한정된 충돌 피드백

전체 출력 검증은 기존과 같은 방향성 의존 관계를 확인합니다. 충돌이 있는 완결 응답에서는 최대 2개 경로, 경로당 최대 5개 노드로 충돌 위치를 안내합니다. 각 노드는 허용된 `evidence_id`, `source_id`, `supports`만 포함하며 실제 선택된 근거와 연결, 제출된 원문 후보 번호에 맞는지 재확인합니다.

안내는 `output_validation_retry.attempts[].validation_issues[].conflict_paths`에 기록할 수 있습니다. 이는 관리자 실행 정보와 교정용 구조 자료이며 공개 분석 응답의 필드 추가가 아닙니다. 원문, 발췌, 해석문, 임의 오류 메시지와 provider 응답 본문은 추가하지 않습니다. 잘못된 구조나 알 수 없는 번호를 진단값으로 채택하지 않습니다.

경로는 직전 거절 응답의 구조를 설명할 뿐 새 응답에서 같은 번호를 편집하라는 지시가 아닙니다. 다음 생성에서 근거 번호와 내용이 달라질 수 있음을 안내하고, 모든 새 응답은 전체 출력 계약과 원문 검증을 다시 통과해야 합니다. 출처 역할 교정과 조건부 재검토의 단일 호출 경로도 유지합니다.

## 오류별 재시도

- `stop`과 검증 오류: 현재 완결 응답의 실제 오류를 교정합니다. 오류를 감추기 위한 supports 변경, 보류 전환이나 근거 생성은 요구하지 않습니다. 같은 오류가 반복되면 요청을 구별하는 단계 표기와 제한된 관계 점검 안내를 제공합니다.
- `length`/`max_tokens`: 중복 설명을 줄이고 완전한 JSON을 새로 생성합니다. 직전 완결 응답에 관계/방향/종속 필드 오류가 있었다면 해당 오류군의 짧은 일반 규칙 하나만 유지합니다. 과거 근거 번호와 경로는 재전달하지 않습니다.
- 새로운 완결 응답: 과거 응답의 오류 목록을 누적하지 않고 새 응답의 검증 결과로 교정 내용을 갱신합니다. 완결됐지만 JSON이 잘못된 경우도 오래된 경로를 물려주지 않습니다.
- 순수 관계/내용 오류: 재시도 횟수만으로 모든 설명을 한 문장으로 압축하지 않습니다. 실제 길이 중단에 대응할 때만 추가 분량 축소를 적용하며 필수 결합 의미와 반대 근거는 보존합니다.
- 응답 시간 초과: 기존 시간 초과 복구를 유지하고 추가 시도나 더 큰 한도를 부여하지 않습니다.

## 고정 버전과 운영 적용

기존 v2.32의 177개 실행 파일과 지침 원본을 보존합니다. 이전 `prompts.py`는 `legacy_prompts_v232.py`에 파일 전체를 동일하게 보관하며 SHA256은 `521e280c06b2ffbca6fd62175054858f4095bb872d76030af2bff58b7673ddaf`입니다. 이전 파이프라인 해시는 `11c5bd23b63ae871ed743295accfeb7b7f63a4aaa8c4eef9c7cec0a0b22e6c3f` 그대로입니다.

새 입력과 출처 정책은 이전 구현을 재사용하고 새 실행 조정기가 고정된 스냅샷에 맞는 worker를 선택합니다. 과거 실패의 재실행은 당시 지침과 실행기를 유지하며 최신 후보로 자동 재실행하지 않습니다. 과거 실행의 해시를 갱신하거나 기존 승인을 새 지침에 소급하지 않습니다.

새 후보의 Production 적용은 공식 Test → 승인 Ground Truth 평가 → 운영 반영 검토 → 관리자 적용 경로만 사용합니다. Compose와 재배포 도구의 기본 worker 명령은 새 실행기로 준비하지만 실제 서비스나 운영 모델/지침은 이번 코드 수정으로 변경하지 않습니다. DB migration과 새 운영 의존성은 없습니다.

## 검증과 제한

합성 응답과 모의 HTTP만 사용해 충돌과 출력 중단의 교차 복구, 근거 번호 변경, 독립 반대 근거 및 공유 context, 판정과 심각도 정합성, 기존 거부 조건, 호출 상한과 민감정보 비노출을 검증합니다. 고정 버전, 과거 재실행, 운영 승격 및 parser/egress와 동시 처리 경로도 회귀 확인합니다.

이번 확인 결과:

- 관련 백엔드 통합 회귀 470건: 첫 실행에서 469건 통과, 현재 버전을 v2.32로 단정한 기존 테스트 1건 실패. 그 기대값을 v2.34로 갱신한 뒤 해당 1건을 재실행해 통과했습니다. 런타임 검증 조건을 완화한 변경은 아닙니다.
- 처리시간 및 출력 실패 통계 회귀 70건 통과. 위 통합 회귀와 중복되지 않는 별도 테스트입니다.
- 프런트엔드 테스트 865건 통과, production build 성공. 기존의 큰 번들 경고는 남아 있습니다.
- 배포 도구 단위 테스트 23건 통과. 실제 배포나 서비스 재시작은 하지 않았습니다.
- 변경 파일의 `git diff --check` 통과. DB 스키마 변경이 없어 migration은 추가하거나 실행하지 않았습니다.

백엔드는 Python 3.12와 기존 ModuAgent 0.6.2가 있는 임시 컨테이너에서 저장소를 읽기 전용으로 연결하고 외부 네트워크 없이 검사했습니다. 실행 중인 서비스의 DB 볼륨이나 환경 파일은 연결하지 않았습니다.

실제 Gemma/vLLM 품질과 실패율, 토큰 및 처리 시간 효과는 별도 검증 대상입니다. 실패가 1% 미만으로 줄어든다고 보장하지 않으며 실행 성공률만으로 판정 품질을 평가하지 않습니다. 실제 운영 데이터나 모델 호출, Production 설정 변경과 재배포 및 Git 업로드는 수행하지 않습니다.
