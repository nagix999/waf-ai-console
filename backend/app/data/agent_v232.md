# v2.32 같은 논점의 반복 근거 보완

## 범위

같은 발췌문에 Primary와 Verifier가 각각 여러 해석을 붙여 유사한 설명이 반복되는 문제를 보완합니다. 원문 구간을 나누는 고도화는 이번 범위가 아닙니다. 시작 commit은 `1276d37`이며 기존 원문, 실행 이력과 결과를 재작성하지 않습니다.

하나의 발췌가 여러 동작이나 서로 다른 조건을 포함할 수 있으므로 같은 source ID 사용을 금지하지 않습니다. 같은 발췌와 동일한 보안 의미의 반복을 정리하되 새로운 검증 실패 조건이나 별도 LLM 단계를 추가하지 않습니다.

## 생성 지침

공통 지침은 두 줄만 교체합니다.

- 하나의 요청 동작에 대한 관측, 의도와 조건부 영향을 같은 논점의 설명으로 작성하고 표현만 바꿔 나누지 않습니다.
- 다른 동작, 성립 조건이나 필수 원문이 있는 해석과 반대 해석은 별도 번호로 보존합니다.
- 핵심 해석을 2~3개 채우라는 인상을 줄이기 위해 해당 숫자를 제거합니다. 중요한 반대 근거와 필수 원문 보존 기준은 유지합니다.

공통 지침은 4,593→4,657자입니다. 기본 관리자 지침과 역할 문구는 변경하지 않으며 같은 모델을 쓰더라도 Verifier는 Primary 출력을 받지 않습니다. 초기 생성 스키마는 제목을 제외하면 v2.31과 동일하며 의미 유사도나 문장 길이로 분류/판정을 자동 변경하지 않습니다.

## 기존 정리 단계의 새 버전

`evidence-display-editor-v2`는 기존 ID-only 출력과 정리 호출 1회, 입력 16,000바이트, 출력 최대 1,024토큰, 모델 30초/전체 대기 90초 한도를 유지합니다. 후보 전체를 한 번 검토하며 중복 후보별로 모델을 따로 호출하지 않습니다.

기존 `allowed_groups`는 같은 supports와 판단 조건 연결, 필수 관련 원문 범위를 유지합니다. 그 안에서 같은 필드/발췌/정확한 위치에 연결된 번호를 `same_source_groups`로 안내합니다. 원문은 다시 복사하지 않습니다. 위치가 없는 과거 항목을 같은 실제 위치로 추정하지 않습니다. 이 목록은 함께 비교할 후보일 뿐 자동으로 같은 의미라고 인정하는 결과가 아닙니다.

모델은 같은 동작의 반복 설명을 한 논점으로 검토하고 관측과 보안 의미의 연결이 명확한 **기존 설명**을 대표로 선택합니다. Primary 우선이나 문장 길이 우선으로 선택하지 않습니다. 대표가 중요한 의미를 포괄하지 못하면 억지로 합치지 않습니다. 새 설명문, 원문, supports, 판정이나 심각도를 생성/변경하지 않으며 모든 원본 근거 번호를 정확히 한 묶음에 포함해야 합니다.

의미 동등성은 여전히 모델 판단입니다. 구조 검증만으로 의미가 같다는 사실이나 대표 설명의 정확성을 증명하지는 않습니다. 정리 모델이 꺼져 있거나 호출이 실패하면 코드 기반의 보수적인 기존 경로를 사용하며, 표현이 다른 모든 의미 중복을 제거한다고 보장하지 않습니다.

## API와 필수 참조

API `waf-analysis-v3`와 개별 근거의 필드/내용/ID/역할 출처는 그대로입니다. 검증된 의미 묶음에 대표 하나가 있으면 기존 핵심 선택기를 사용해 하나만 반환합니다. 같은 논점을 2~3개로 채우지 않습니다. 실제 정책 판정 근거가 모델이 고른 대표와 다르면 실제 원본 근거 ID를 유지하며, Primary/Verifier 참조는 선택된 원본 ID의 교집합입니다. 다른 역할의 설명을 해당 모델이 작성한 것으로 바꾸지 않습니다.

최상위 판단 조건과 전이적으로 필요한 원문 관계는 원본 번호를 유지합니다. 그래서 조건/관계 보존에 필요한 여러 항목이 같은 발췌를 사용하면 API에 함께 남을 수 있습니다. 묶음 수를 줄이려고 이 참조를 삭제하거나 추측으로 대표 번호에 치환하지 않습니다. 중요한 반대 근거와 실제 다른 논점도 보존합니다.

코드 fallback은 의미를 추정하지 않습니다. 이번에는 필수 관련 근거의 동일성 비교에 원문/위치뿐 아니라 해석과 supports도 포함하여, 같은 원문에서 서로 다른 기여를 자동으로 동일시하지 않도록 보강합니다. 저장된 전체 결과와 관리자 감사 이력은 그대로입니다.

## 화면과 보고서

현재 core 응답의 근거 카드와 근거/원문 화면 및 보고서는 API에 선택된 근거만 사용합니다. 정확히 같은 필드와 발췌 및 위치 목록이 있는 경우 원문을 처음 한 번 표시하고, 이후 항목에는 해당 근거의 원문을 참조합니다. 다른 실제 위치, 빈/미기록/잘못된 위치, 공백이나 개행이 다른 원문은 공유하지 않습니다.

해석, 공격/정상/참고 분류, 근거 번호와 API 순서는 모두 보존합니다. 공유 원문 버튼은 키보드로 원래 발췌에 포커스를 옮기며, 기존 각 항목의 입력 보기 동작은 자신의 번호와 위치를 그대로 사용합니다. 원문과 Cookie는 텍스트로만 표시합니다. 과거 non-core 표시 계획은 변경하지 않습니다.

Markdown 보고서는 같은 공통 발췌/참조 구성을 사용하고 기존 `report-document.cjs` 빌드와 ReportLab PDF 경로가 이를 재사용합니다. Excel도 기존 API 핵심 근거 목록을 유지합니다. 전체 원문을 추가로 읽거나 모델 설명을 다시 생성하지 않습니다.

DB migration이나 새 패키지/운영 서비스 의존성은 없습니다. 원문 분할, 파서, 시그니처 context 제한, 출처 교정/조건부 재검토와 기존 시도 예산, 독립 Verifier의 실패/판정 불일치 보류, egress와 동시 처리 및 완료 응답 준비 조건은 유지합니다.
