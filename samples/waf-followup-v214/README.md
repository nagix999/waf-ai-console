# 후속 확인 정책 v2.14 검증 · 10건

실제 로그가 아닌 작성된 예제입니다. SQL·XSS·명령 삽입·경로 이동·JNDI의 정탐/차단 5건과 정탐/허용, 오탐/차단, 오탐/허용, 보류/차단, 보류/허용 각 1건입니다. 예약 IP·`.invalid` 주소만 사용하며 공격 구문을 실행하거나 링크를 조회하지 않습니다.

`expected_verdict`는 작성자의 기대 답안이지 승인된 Ground Truth가 아닙니다. 접수 시 답안·문항명은 모델 입력에서 분리합니다. 특히 권한 변경 2건은 호출자의 권한을 알 수 없어 보류를 기대하지만 실제 출력과 별도로 검토해야 합니다.

판정과 별개로, **최종 정탐 + 차단 + 튜닝 없음**일 때 최종 확인 목록이 비어 있는지 검사합니다. 오탐·보류·허용 건에서는 기록된 목적과 최종 정책의 보존 범위를 검사합니다. 실모델이 해당 확인을 생성하지 않으면 그 조합의 보존 검증은 단위 테스트 결과와 구분합니다.

운영 반영은 공식 Test → 승인 Ground Truth 평가 → Production Review → Apply 절차를 따릅니다. 이 예제 10건 통과는 자동 승격 조건이 아닙니다.
