# 파일 분석용 합성 WAF 로그 150건

실제 사내 로그·인증 정보를 사용하지 않은 합성 시나리오입니다. 작성자가 의도한 기대값이며 검증된 운영 정답이나 측정된 모델 성능이 아닙니다.

## 업로드 파일

| 파일 | 건수 | 난이도 기준 |
| --- | ---: | --- |
| [easy_50.json](easy_50.json) | 50 | 명확한 공격 구문, 무해한 키워드 일치, 명백한 캡처 누락 |
| [medium_50.json](medium_50.json) | 50 | 인코딩 해석, 본문 형식·값의 문맥, 시그니처 비교 |
| [hard_50.json](hard_50.json) | 50 | 중첩 인코딩, 파서 차이, 복합 문맥, 판정 유도 문자열, 부족한 증거 |
| [all_150.json](all_150.json) | 150 | 위 세 파일의 동일 이벤트 모음 |

난이도는 판정에 필요한 해석의 복잡도이며 심각도나 모델의 측정된 정답률이 아닙니다. 각 난이도는 참고 정탐 20건·오탐 20건·기대 보류 10건이고, WAF D/A를 각각 25건 배치했습니다. 실제 운영 분포를 재현하지 않습니다.

## 사용 방법

1. **테스트 분석 → 파일 업로드**에서 사용자가 테스트명을 입력하고 파일을 선택합니다.
2. 새 테스트를 실행합니다. 서버는 행의 `expected_verdict`를 합성 기대값 답안으로 연결하고, `difficulty`, `test_category`, `case_name`을 별도 평가 메타데이터로 저장합니다. 이 필드들은 모델 입력에 포함하지 않습니다.
3. 테스트 실행 이력에서 테스트명을 찾아 진행 상태·Confusion Matrix·평가 지표를 확인합니다. 난이도·유형으로 좁혀 볼 수 있고 개별 문항은 기존 분석 상세로 연결됩니다.
4. 각 지표의 `?`를 마우스나 키보드 포커스로 열면 정의와 높거나 낮을 때의 의미를 확인할 수 있습니다. `stub`는 실제 품질 평가에서 제외합니다.

분할 파일과 전체 파일은 같은 150개 이벤트입니다. 다만 **새 실행은 같은 파일이어도 새 분석을 생성**하고 이전 결과를 보존합니다. 같은 접수 키의 재전송은 중복 실행하지 않으며, 그 키로 파일·이름·답안을 바꾸면 충돌입니다. 파일 내부 중복은 평가 표본을 늘리지 않습니다. 재실행에는 추가 모델 호출과 비용이 발생할 수 있습니다.

신규 일반 테스트의 source는 `waf-internal-test-run-<실행 ID>`, 기존 일반 테스트는 `admin-ui`입니다. 설정의 150건 후보 검증은 별도 `waf-internal-model-test-<모델 검증 ID>`입니다. 최신 답안을 정정하려면 **분석 결과 → 참고 답안 연결**에서 정확한 source와 답안 파일을 지정해 미리보기·확정하세요. 이름으로 source를 추정하지 않습니다.

**실행별 평가는 접수 시점 답안을 고정**합니다. 일반 분석 화면은 최신 답안을 비교하므로 사후 정정 시 기준이 다를 수 있습니다. 이전 테스트 점수는 자동 변경하지 않습니다. 새 답안 기준 실행은 수정한 파일을 새 테스트로 접수하세요. 참고 답안 연결 자체는 모델을 호출하지 않습니다.

자동 파일 답안은 `source_kind=synthetic_expected`, `source_ref=test-upload:expected_verdict`, `ai_visible=null`(미확인)입니다. 독립 운영 정답이라는 보증이 아닙니다. 분석과 답안은 함께 처리하고 답안 저장에 실패한 행의 새 분석은 남기지 않습니다.

파일의 `expected_verdict`는 정확히 `true_positive`, `false_positive`, `inconclusive` 중 하나입니다. 생략·빈 문자열·JSON null은 답안 없음이며 공백만 있는 값·잘못된 철자·타입은 거부합니다. 새 직접 테스트는 이벤트와 분리된 답안 입력을 지원하지만 Production 이벤트와 기존 직접 입력 이벤트 계약에는 답안을 넣을 수 없습니다.

## 참고 답안 — 파일 업로드가 아닌 참고 답안 연결용

- [쉬움 답안](reference/easy_answers.json)
- [보통 답안](reference/medium_answers.json)
- [어려움 답안](reference/hard_answers.json)

답안은 event ID, 난이도, 시나리오 이름, 기대 판정·심각도, 근거·추가 확인 사항을 담습니다. 업로드 파일의 답안·난이도·유형·문항명은 이 파일에서 event ID로 정확히 매핑했습니다. 정답 해설·발췌 등은 업로드 이벤트에 추가하지 않았습니다. 답안 파일 자체를 분석 파일로 올리거나 LLM 입력에 덧붙이지 마세요.

이 답안 생성에는 AI가 관여했지만 평가 대상 모델의 결과를 보고 작성한 것은 아닙니다. 실제 답안 작성 과정에 맞게 AI 열람 여부를 지정하고 모르면 미확인으로 둡니다. 합성 기대값의 보류 30건은 이진 지표와 따로 평가합니다.

정탐은 공격 시도의 관찰을 뜻하며 공격 성공·서버 취약성·실제 피해를 증명하지 않습니다. 오탐도 제공된 요청 문맥 기준 기대값이며 업무 권한·서버 구현을 보증하지 않습니다. 보류는 근거가 부족한 경우입니다. 참고값과 다르다고 곧바로 모델 오류로 확정하지 말고 원문·판정 근거를 검토하세요.

## 안전과 검증 범위

- IP와 호스트는 문서용 대역·예시 도메인을 사용하고 토큰은 합성 값입니다. 공격 문자열을 실행하거나 실제 대상에 보내지 마세요.
- 일부 HTTP 원문은 의도적으로 불완전합니다. 파서의 `success`는 메시지 완전성이나 공격성 검증 결과가 아닙니다.
- 기본 32K 프로필을 위한 작은 입력이며 최대 컨텍스트·대량 트래픽 성능 검증 자료가 아닙니다.
- 실제 판정에는 검증된 모델과 moduagent 실행이 필요합니다. 일반 테스트는 Production 모델·큐를 공유하되 접수 당시 모델·프롬프트를 고정합니다.
- OpenAI에서는 Primary·Verifier·재시도별 비용이 발생할 수 있습니다. 이 파일의 수정·조회는 실제 모델 호출이나 서비스 업로드를 하지 않습니다.
- 후보 검증의 기존 `backend/app/data/waf_dummy_v1.json` 원본은 보존하고, 별도 `waf_dummy_v1_metadata.json`을 문항 분류에 사용합니다.

LDAP 필터 문법은 [RFC 4515 §3](https://www.rfc-editor.org/rfc/rfc4515.html#section-3)을 참고했습니다. 실제 애플리케이션의 값 결합 방식은 재현하지 않았습니다.

## 최초 생성 시 검증(실행 묶음 도입 전)

150개 고유 이벤트·원문, 난이도별 50건, 답안 ID 대응, D/A 균형과 참고 발췌의 원문 일치를 확인했습니다. 네트워크 없는 메모리 SQLite에서 파일 접수·암호화 원문 복원을 확인했으며 실제 LLM 정확도 검증은 하지 않았습니다.

Content-Length 예외는 고급의 `waf-syn-e1de669d8fa0`(본문 미수집), `waf-syn-6102cbe604f8`(상충하는 중복 길이) 두 건이 의도된 사례입니다.

새 실행 관리·지표 분모·배포 기준은 [테스트 실행 및 평가 정의서](../../docs/Test_Runs_and_Evaluation_v0.1.md)를 따릅니다.
