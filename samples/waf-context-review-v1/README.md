# 요청 의미 검수 자료 v1

`context_review_18.json`을 **테스트 분석 → 배치 파일 분석**에서 업로드할 수 있다. 업로드하면 모델 호출과 비용이 발생할 수 있으므로 실행 승인을 받은 뒤 사용한다.

총 18건: 공격 시도 6건, 정상 요청 6건, 권한·허용 범위를 확인해야 하는 요청 6건이다. 실제 사내 로그·계정·비밀값을 사용하지 않았다. 요청의 주소는 문서용 IP와 `.invalid` 도메인이며, 내용은 실행하지 않는 분석용 문자열이다.

## 확인할 차이

| 비교 항목 | 공격 시도 | 정상 요청 |
| --- | --- | --- |
| HTML | 검색 값에 SVG 이벤트 실행 식 | 이벤트 이름과 닮은 일반 파일명 |
| SQL | JSON 인증 값의 참 조건·주석 | 성명 안의 작은따옴표 |
| 셸 | 파일명 안의 명령 치환 | 일반 괄호 표기 |
| 경로 | 반복 상위 경로와 시스템 파일 지정 | 파일명 내부의 연속된 점 |
| 외부 조회식 | 헤더 안의 JNDI 조회식 | 기술 용어를 설명하는 문장 |
| 템플릿 | 내부 객체 접근·코드 호출 | 메일의 이름 자리표시자 |

나머지 6건은 문서 접근 권한, 서버 측 URL 조회, 사용자 SQL, 임베드 콘텐츠, 상대 경로, 관리 작업의 허용 범위를 다룬다. `reference/answers_18.json`에 참고 답안의 이유와 확인할 조건을 따로 기록했다. 요청이 허용된다고 단정하거나 모든 환경 정보 부족을 보류로 처리하지 않는지 검수한다.

## 사용 시 주의

- **AI가 작성한 개발용 검수 자료이며 독립 평가셋이나 전문가 확정 답안이 아니다.** 기존 평가에서 발견한 문제를 참고했다. 참고 답안을 사람이 검토한 뒤 품질 평가에 사용한다. 특히 보류 6건은 정상 기능·권한의 실제 기준을 정하면 답안이 달라질 수 있다.
- 이벤트에 제목·이유·난이도·분류를 넣지 않았다. `expected_verdict`만 업로드용으로 포함하며 기존 접수 경로에서 분석 입력과 분리한다. 참고 답안 파일을 이벤트로 업로드하지 않는다.
- 회사명·User-Agent 등은 모든 답안에 같은 중립값을 쓴다. 다만 문서용 주소와 서비스가 부여하는 테스트 유입 메타데이터는 남는다. 이번 자료가 모든 평가 편향을 제거한 것은 아니다.
- 예전 파싱 난이도·Hard·Medium 각 50건은 수정하지 않았다. 새 자료는 별도 집계하고 기존 150건의 점수와 합산하지 않는다.
- JSON 문법·원문 인용·답안 분리는 오프라인으로 확인한다. **이 검사가 통과해도 LLM이 참고 답안을 맞혔다는 뜻은 아니다.**

재현 확인: `python3 scripts/build_context_review_samples.py`. 네트워크·모델 호출·페이로드 실행·파일 쓰기는 하지 않는다. 정의 변경이 필요하면 새 자료 버전으로 관리한다.
